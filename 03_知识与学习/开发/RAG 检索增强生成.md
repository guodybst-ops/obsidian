# RAG 完整详解（检索增强生成）

> **RAG = Retrieval-Augmented Generation，检索增强生成**，2020年由 Meta FAIR 正式提出，是当前大模型落地最主流的技术架构。

---

## 一、核心逻辑

**先检索外部资料，再交给大模型生成答案**，解决原生大模型三大致命缺陷：

1. **知识截止**：大模型训练数据有固定时间点，无法获取最新资讯、企业内部文档；
2. **模型幻觉**：无依据编造事实、法条、数据，专业场景风险极高；
3. **私有数据隔离**：无法直接读取企业本地文件、数据库、行业资料。

---

## 二、完整工作流程

### 阶段 1：离线知识库构建（提前执行一次）

| 步骤                    | 说明                                                    |
| --------------------- | ----------------------------------------------------- |
| 1. **数据接入**           | 读取 PDF、Word、网页、数据库、工单、手册等原始文件                         |
| 2. **文本预处理**          | 清洗脏数据、分段切片（Chunk）、去除冗余                                |
| 3. **向量化（Embedding）** | 用嵌入模型把文字转为数字向量，语义相近文本向量距离更近                           |
| 4. **向量入库**           | 向量 + 原文 + 来源元数据存入**向量数据库**（Milvus、Chroma、FAISS 等）建立索引 |

### 阶段 2：在线问答推理（用户提问实时执行）

| 步骤                      | 说明                               |
| ----------------------- | -------------------------------- |
| 1. **用户 Query 向量化**     | 把用户问题转成同维度向量                     |
| 2. **语义检索召回**           | 在向量库匹配 Top-K 最相似文档片段             |
| 3. **重排序 Rerank（可选优化）** | 精细筛选，剔除无关内容                      |
| 4. **Prompt 增强**        | 把「检索到的参考资料 + 用户问题」拼接成完整提示词喂给 LLM |
| 5. **大模型生成回答**          | 强制基于检索内容作答，同时标注资料来源              |
| 6. **输出返回**             | 附带引用来源，方便校验真实性                   |

---

## 三、核心优势（对比微调 Fine-tune）

1. **低成本、快速更新知识**：只需更新文档，不用重新训练大模型；微调动辄几小时/几天，RAG 知识库分钟级更新；
2. **隐私安全**：私有数据本地向量库存储，不用上传至公有大模型；
3. **可溯源、低幻觉**：答案附带原文出处，大幅减少编造内容；
4. **灵活通用**：一套大模型可对接多套知识库（法律/医疗/企业内部），不用单独训行业模型；
5. **门槛更低**：小团队即可落地，无需大量标注训练数据。

---

## 四、RAG 技术演进版本

### 1. Naive RAG（基础版）
简单切片 + 向量检索。**缺点**：上下文冗余、检索精度差、长文档丢失关键信息。

### 2. Advanced RAG（进阶优化）
增加重排序、上下文压缩、多路混合检索（向量 + 关键词）、自适应分块。

### 3. Modular RAG（模块化 RAG）
流程解耦，检索/重排/生成模块独立可替换，适配复杂业务。

### 4. Agentic RAG（智能体 RAG，最新）
大模型自主拆解复杂问题、多轮检索、自我校验答案，不满意自动重新检索。适合多步骤复杂问答但成本更高、延迟更大。

---

## 五、主流落地应用场景

1. **企业知识库问答**：员工查制度、产品手册、项目文档、内部财报；
2. **垂直行业 AI**：法律法条检索、医疗病历/指南、金融研报、教育题库；
3. **智能客服**：基于产品说明书、工单自动回复客户问题；
4. **文档助手**：PDF/Word 长文档总结、精准问答、资料溯源；
5. **本地私有 AI**：本地部署大模型 + 向量库，数据不出内网；
6. **实时资讯助手**：对接新闻、行业快讯，获取大模型训练截止后的新信息。

## 七、RAG 局限性

1. **检索质量决定答案上限**：如果检索不到关键资料，回答依然会出错；
2. **长文本 Token 限制**：检索内容过多会超出大模型上下文窗口；
3. **复杂多逻辑推理能力弱**，需搭配 Agent 增强；
4. **向量库规模变大后**，检索速度、硬件成本上升。

---

## 八、与 [[03_知识与学习/开发/MCP]] 的关系

> RAG 解决的是"如何让大模型看到私有/最新知识"的问题；MCP 解决的是"如何让大模型连接外部工具和数据源"的问题。两者互补——RAG 提供静态知识检索，MCP 提供动态工具调用，共同构成大模型与真实世界交互的完整方案。
