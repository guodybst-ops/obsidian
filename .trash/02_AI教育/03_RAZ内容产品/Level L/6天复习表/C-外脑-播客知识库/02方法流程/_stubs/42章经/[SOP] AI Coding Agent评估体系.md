# AI Coding Agent评估体系

## 一句话

把Agent当作数字员工来评估：上岗前必须有考核方式（题库），每次迭代后必须跑完整评估（跑分），而不是只看单个demo。

## 怎么用

### Step 1：构建题库

从三个来源收集测试任务：
1. **开源仓库**：不同语言、框架的项目
2. **自有仓库**：团队自己的代码库
3. **早期客户商业仓库**：真实的业务代码

整理的题库应包含：
- 不同编程语言（Python、Java、JS、Go等）
- 不同框架
- 不同任务类型（unit test生成、bug修复、重构、文档生成等）
- 不同难度级别

目标量级：至少数百到一千道题。

### Step 2：设计评估指标

核心指标：
- **正确率/成功率**：任务完成且结果正确的比例
- **一次通过率**：不需要人介入即可正确完成的比例
- **稳定性**：同一任务多次运行时结果的一致性

辅助指标：
- 完成时间
- token消耗/成本
- 需要人工干预的次数

### Step 3：建立评估流水线

```
每次Agent迭代 →
  跑完整题库（N道题） →
  统计正确率变化 →
  对比上一版本 →
  判断是否真正变好 →
  如果变好→上线；如果不变→分析失败case
```

关键点：
- 题库不能只跑一遍——每次迭代都要重新跑全量
- 不能只看几个demo，要看统计显著性
- 这类数据以前不存在，需要自己构建（含合成数据）

### Step 4：持续维护题库

- 随着Agent能力提升，增加更难的任务
- 随着新客户接入，纳入新的业务场景任务
- 定期检查题库是否已被"刷过"（Agent过拟合）

## 完整示例

以unit test Agent的评估体系构建：

```
题库构成（1000道题）：
├── Python: 300题
│   ├── 简单函数测试: 150题
│   ├── 类测试: 100题
│   └── 复杂场景: 50题
├── Java: 250题
├── TypeScript: 200题
├── Go: 150题
└── 其他语言: 100题

评估流程：
1. Agent接收到1000个代码文件，为每个生成unit test
2. 自动运行生成的测试代码
3. 统计：多少测试通过了（pass rate）
4. 检查覆盖率：生成的测试覆盖了多少原始代码行
5. 人工抽检：随机抽50个结果检查测试质量

版本迭代对比：
v1.0: pass rate 62%, coverage 45%
v1.1: pass rate 71%, coverage 52% → 提升，上线
v1.2: pass rate 68%, coverage 55% → pass rate下降但coverage上升，需要分析
```

## 适用场景与边界

**适用场景**：
- AI Coding Agent公司的产品质量控制
- 投资人评估Agent公司时验证产品是否真正可工作
- 任何做数字员工类产品的公司

**局限性**：
- 题库构建用时长、成本高，不适合早期探索阶段 [AI推理]
- 某些任务类型（如creative coding、架构设计）难以用自动化评估
- 仅1个来源，未来需要更多元的数据支撑
