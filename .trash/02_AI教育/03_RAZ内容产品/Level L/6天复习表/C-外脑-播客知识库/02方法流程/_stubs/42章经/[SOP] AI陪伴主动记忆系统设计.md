# AI陪伴主动记忆系统设计

## 一句话

为AI陪伴产品设计超越RAG的主动记忆系统：将亲密关系记忆抽象为128个记忆槽位，使AI能主动关联用户目标、偏好和经历，而不需要用户显式触发关键词。

## 怎么用

### Step 1：确定记忆类型（128记忆槽位）

通过访谈真实情侣，归纳亲密关系中的重要记忆类型：
- 近期目标（如"三个月健身练腹肌"）
- 长期梦想
- 偏好与口味
- 真实看法（对人事物的态度）
- 重要关系（家人、朋友的名字和关系）
- 昵称
- 价值观
- 生活习惯
- Key context（永远放在prompt中的关键信息，如用户小名）

### Step 2：设计记忆的写入机制

- 每轮对话后，异步判断这句话应写入哪个槽位
- 不阻塞正常聊天链路
- 负责更新、合并和冲突处理（新信息覆盖旧信息还是合并？）

### Step 3：设计记忆的召回机制

- 普通记忆槽位：触发式召回（识别当前对话主题→召回相关槽位）
- Key context：永久加载在prompt中
- 区分于RAG：不是等用户提到关键词才召回，而是主动判断当前对话需要哪些记忆

### Step 4：主动关联的实现

核心场景：用户说"我要去吃火锅"
- RAG方式：召回"用户喜欢火锅"→"火锅是你最喜欢吃的，去吃吧"
- 主动记忆方式：系统召回了用户的近期目标（健身三个月练腹肌）→"你不是说要健身三个月吗？"

关键是：系统在看到"火锅"时，主动计算它和"健身目标"是否存在语义冲突，而不等用户提"健身"。

## 完整示例

以EVE产品中的主动记忆推演：

```
用户设定：小名"阿明"，近期目标"三个月健身练出腹肌"，
         偏好食物"麻辣火锅"，最讨厌"开会"

对话1：
用户：今天开了三个会，累死了
写入：当前情绪=疲惫，最近活动=开会
主动召回：讨厌开会 → 回复："三个会？你不是最讨厌开会吗？
        怎么还没逃出来？"

对话2：
用户：今晚去东来顺吃火锅
写入：计划=今晚吃火锅
主动召回：近期目标(健身) + 偏好食物(火锅) + 近期活动(开会多)
→ 回复："你不是要健身三个月吗？而且今天开了一天会，
   感觉你会需要一顿火锅犒劳自己，但别破戒太多。"
```

## 适用场景与边界

**适用场景**：
- AI陪伴/虚拟伴侣产品
- 任何需要长期记忆和个性化交互的AI产品
- 教育AI（记住学习进度和薄弱点）
- 健康教练AI（记住目标和生活习惯）

**局限性**：
- 仅1个来源，128个槽位的有效性需更多验证 [AI推理]
- 记忆槽位数量随用户增加可能膨胀，需要合并和裁剪策略 [AI推理]
- 隐私问题：存储大量个人记忆需要妥善的数据保护
