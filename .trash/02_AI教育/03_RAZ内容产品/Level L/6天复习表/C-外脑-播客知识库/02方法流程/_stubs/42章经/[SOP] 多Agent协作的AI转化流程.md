# 多 Agent 协作的 AI 转化流程

## 一句话

在私域/高客单价转化场景中，不直接让 AI 替代销售，而是让多个 AI Agent 协作完成从意图识别到前置沟通再到数据报告的全流程，最后由金牌销售完成关键成交——这比「AI 直接替代销售」更实际也更有效。

## 怎么用

### Step 1：设计 Agent 分工

按转化链路拆成多个 Agent，每个 Agent 只做一件事：

| Agent | 职责 | 判断标准 |
|---|---|---|
| Agent 1：意图识别 | 判断用户此刻是否有购买意向 | 高意向→走成交 SOP；低意向→回答问题、保温 |
| Agent 2：推课/推产品 | 根据意图推荐合适的试听课/低价产品，收集联系方式 | 根据用户特征匹配产品 |
| Agent 3：提醒+催课 | 提醒上课、催课、答疑、收集反馈 | 保持用户不会流失 |
| 系统：报告生成 | 汇总用户从进来到最后听完课的全程数据 | 形成结构化报告供销售参考 |
| 人（金牌销售） | 基于报告进行最终电话成交 | 高客单价场景中人的转化率更高 |

### Step 2：构建基础能力

每个 Agent 需要的基础能力：

1. **意图识别**：从历史对话数据中学习——好的销售聊几句话就知道这人是「今天要买」还是「只是看看」→ AI 也需要训练这个判断
2. **SOP（标准话术剧本）**：转化是有封闭目标的过程——优秀销售脑子里的套路需要转化为 AI 可执行的流程
3. **知识库**：回答专业问题。AI 把专业问题回答到位，销售只需负责签约
4. **语气/情感微调**：根据业务场景和品牌调性调整语气
5. **封闭场景的剧本能力**：用户聊到意料之外的话题时，AI 可以通过剧本把用户自然拉回目标流程

### Step 3：建立反馈飞轮

- 设置指标（转化率、成交率、单效）
- 做对照组实验——AB test 新的 SOP 和话术
- 抽案例观察对话过程
- 每一两个月就能看到明显改进
- 持续优化 SOP

### Step 4：从人盯到放手

- 类似自动驾驶的监管模式
- 早期：人看着 AI 跑，确认没问题
- 中期：部分场景放手
- 后期：全自动运行（但最关键的成交环节仍保留人）

## 完整示例

以教育行业私域转化推演：

| 阶段 | Agent 操作 | 用户状态 |
|---|---|---|
| 1 | Agent 1 判断：「这个人问了价格，语气急切」→ 高意向 | 有意向但需要更多信息 |
| 2 | Agent 2 推送：「三天后有老师上一节免费试听课，原价 X，我给你留个位置？」→ 收集手机号 | 留下手机号，约课 |
| 3 | Agent 3 提醒：「明天晚上8点记得来听课哦」→ 催课 → 课后问反馈 | 听课，产生好感 |
| 4 | 系统生成报告：「该用户星期三来，之前听过三次试听课，这次有明显报课意向，关注语文和数学，孩子五年级……」 | — |
| 5 | 金牌销售拿到报告，打电话：「刘妈妈，我看你家孩子最近看了很多语文课，这次试听感觉怎么样？我们有个适合五年级的语文班……」 | 成交 |

**效果**：小范围测试中单效可达三四倍。

## 适用场景与边界

### 什么时候用
- 高客单价/高决策成本产品（教育、保险、金融、SaaS）
- 私域转化场景（线索已经在手里）
- 有大量无人响应/响应不及时/响应质量低的线索需要盘活
- 拥有金牌销售团队但无法覆盖所有线索

### 什么时候不用
- 低客单价/冲动消费产品（不需要复杂转化）
- 无「人完成成交」环节的纯自助场景
- 没有足够历史销售数据来训练意图识别和 SOP
- 初创期还没有验证过转化模式的业务

### 已知局限
- 需要中等以上线索量才能 RO I为正（如果线索本身就很少，人直接聊更高效）
- 每个行业/公司的 SOP 不同，需要单独定制——第三方 SaaS 做不深
- 用户可能识别出是 AI 在聊——但在封闭场景中用户对此的容忍度较高（因为原来的人工服务往往更差）
