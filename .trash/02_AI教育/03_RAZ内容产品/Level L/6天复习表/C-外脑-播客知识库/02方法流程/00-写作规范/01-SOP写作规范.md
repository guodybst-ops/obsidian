# 02 方法流程 · SOP 写作规范（`[SOP]` 前缀专用）

> **适用范围**：本规范专管 `02方法流程/` 下前缀为 `[SOP]` 的笔记。**不管** `[框架]` 和 `[心法]`——它们各有专属规范。
> 顶层入口见 [[00-总规范]]。
> 立规缘起：2026-07-13。用户明确指出"02 应当是我可以直接使用的方法流程 SOP，不是思路介绍"。同日发现 02 层混着 SOP / 框架 / 心法 三种物种，本规范只固化 SOP 一类。

---

## 一、02 层的本质定义

**02 是"操作手册"，不是"读后感"，也不是"方法论综述"。**

判断某个文件是否属于 02，用一个终极问题：

> **一个不了解陈唐 / 张津剑 / 润宇 / 敏哥的人，能不能只看这个文件、跳过所有背景，30 秒内知道"我第一步要做什么"？**

- ✅ 能 → 是合格 02
- ❌ 不能（需要先读背景/理论/来源引用才能理解要做什么）→ 是不合格 02，本质是**"披着方法皮的概念笔记"**，应挪到 03 或降级重写

---

## 二、SOP 与"方法论介绍"的辨别清单

| 特征 | 合格 SOP（02） | 不合格（伪装成 SOP 的方法论） |
|---|---|---|
| 开头 3 行 | 直接说做什么 / 何时用 / 得到什么 | 讲这个方法来自哪里、为什么值得学 |
| 主体 | 编号步骤，动词开头，可打勾 | 一段段散文式解释 |
| 例子 | 单独放"附录：实例"，与步骤分开 | 例子穿插在每一步中，占用大量篇幅 |
| 判断分支 | 有决策树 / if-then 表格 / 判断点清单 | 只有"具体情况具体分析"式含糊 |
| 可复用产物 | 有模板 / 清单 / 表格 / 打分卡可复制粘贴 | 没有任何可复用的输出物 |
| 来源引用 | 只在文件底部 `## 来源` 一节 | 正文里反复出现"陈唐说 / 张津剑讲"打断操作节奏 |
| 篇幅分布 | 主流程 > 60%，其余分节都 < 20% | 背景 / 意义 / 案例 各占大头 |

**红线判据**：如果文件里"该方法的意义 / 为什么这么做 / 谁提出 / 案例讲解"合计占篇幅 > 30%，直接判定不合格。

## 三、标准骨架（模板）

新建或返工 02 stub 必须使用以下骨架。**每节都是必填**（无内容也要保留标题写 "N/A" 并说明原因）：

```markdown
---
tags: [方法, ...]
created: YYYY-MM-DD
layer: extract
status: stub / growing / stable
provenance: external / mixed
viewpoint_owner: external_author / mixed
method_type: 查表法 / 决策框架 / 组织流程 / 沟通话术 / 定价模型 / ...
aliases: [...]
source_count: 1
sources:
  - show: "..."
    episode: "..."
    speaker: "..."
---

# <方法名>

## 一句话（≤ 40 字）
做什么 + 得到什么。不写来自谁、不写为什么伟大。

## 什么时候用（触发条件，3-5 条 bullet）
- 场景 A（用户处于这个具体状态时）
- 场景 B
- **红线**：不适用于 X 场景

## 输入（做之前要准备的东西）
- 材料 / 数据 / 参与者 / 时间预算
- 前置条件（如："需要已经跑过一次面谈"）

## 输出（做完得到什么）
- 一份 XX 表 / 一次 XX 沟通 / 一个 XX 决定
- 可衡量的完成信号（"你知道自己做完了"的判据）

## 主流程（核心，占篇幅 ≥ 60%）

### Step 1: <动词开头的步骤名>
- 具体动作（1-3 行，动词开头）
- 遇到 X 就 Y（if-then）
- 判断这一步做完的信号

### Step 2: ...

（步骤数量控制在 3-7 步；过长拆子方法）

## 判断点 / 决策树（如有分支）

用表格或伪代码明示：
```
如果 A → 走路径 1
如果 B → 走路径 2
两者都不成立 → 退回 Step X
```

## 模板 / 清单 / 打分卡（可复制粘贴）

给出可以直接抠走的表格 / 打分维度 / 话术模板 / 清单：

| 列 A | 列 B |
|---|---|
| ... | ... |

## 常见坑（3-5 条硬红线）
- ❌ 不要 X（原因 1 行以内）
- ❌ 不要 Y

## 附录：实例（1 个跑通的例子，与主流程分开）
一次完整跑通，可以带角色和数字。**放在附录，不塞进步骤**。

## 来源
- [[89单集笔记/... | XXX]] — 一句话说明这次引用取的是什么 [原话 / 归纳]

---

> stub：X 个来源。跨节目再次出现时升级到父目录。
```

## 四、写作红线（禁止清单）

1. ❌ **禁止在正文步骤中夹叙夹议** — 步骤章节只能出现动作和判断，人物/来源引用一律搬到底部
2. ❌ **禁止用"为什么这么做"作为开篇章节** — 想解释背景，放到最后一节 `附录：为什么值得用`
3. ❌ **禁止步骤和示例混写** — Step 3 里写"举个例子：..." 是不允许的，示例统一去附录
4. ❌ **禁止把"边界 / 不适用场景"写成理论论证** — 只列 3-5 条 bullet，每条一行
5. ❌ **禁止在 stub 中放"关联" "相关"链接超过 5 条** — 只放最直接相关的，其余用后向链接自然形成
6. ❌ **禁止 `## 附录` 章节超过主流程篇幅** — 附录喧宾夺主 = 结构错乱

## 五、自检清单（提交前必过 6 关）

写完一个 02 stub，用以下 6 个问题自检；任一"否"就返工：

- [ ] **30 秒判据**：陌生人只看前 3 节能知道 Step 1 做什么？
- [ ] **动词判据**：主流程每步都以动词开头？
- [ ] **可打勾判据**：主流程可以做成 checklist？
- [ ] **可复用产物判据**：有至少 1 个可抠走的模板/表格/清单？
- [ ] **背景占比判据**：背景/来源/案例合计篇幅 < 30%？
- [ ] **一句话判据**：`## 一句话` 章节 ≤ 40 字，且不含"某某说 / 某某提出"字样？

---

## 六、返工原则（针对已存量 stub）

- **返工前必读原文**（强红线）：动手前必须先完整读一遍原 stub，识别其中的原话、案例、类比、推演示例、来源、关联链接，逐项决定"新骨架里哪一节能装 / 装不下就挪到附录"。**禁止不读原文就按新骨架重写**——会丢失已提炼素材。
- 已存在的 02 stub 若不符合规范，**不删除**，**改写骨架**：把原文里的方法论描述保留（放到附录），主体按新骨架重写。原文中的推演示例、案例、类比无处安放时，追加 `## 附录：原文素材` 兜底。
- 单次批量返工上限：**10 个 stub / 批次**，超过要分批。
- 返工时 frontmatter 追加 `revised_at: YYYY-MM-DD` 和 `revised_reason: "对齐 SOP 规范 v1"`。

- ❌ 没有一个可以打印下来照用的清单或表格

`46个商业问题查表法.md`（v1，2026-07-13 返工版）：

- ✅ 主流程 6 步，每步动词开头，可打勾
- ✅ 有"本周动作卡"模板可以直接抄走

- ✅ 两个实例（第 7 题 + 第 1 题）放在附录 A/B，与主流程分开
- ✅ 背景/意义压缩到附录 C 30 行以内

## 八、与其他层的边界

- **03 概念链接**：如果内容是"如何理解 X"、"X 是什么"、"X 与 Y 有什么区别" → 属于 03，不属于 02
- **01 人物原萃**：如果内容是"某人的心智模型 / 某人的方法框架" → 属于 01 的方法收录节，不属于 02（除非用户能直接照做）
- **89 单集笔记**：如果内容是"这一集讲了什么" → 属于 89

**判据关键词**：
- "我要怎么做" → 02
- "这是什么 / 为什么会这样" → 03
- "谁说的 / 谁怎么想" → 01
- "这一集主要内容" → 89
