# 张海龙

## 画像

- **身份**：Gru.ai 创始人，AI Coding Agent 创业者
- **背景**：从初中开始写代码（20多年），创办过开源中国、Coding.net（合并到腾讯）。2023 年判断 AI 可能第一次直接生产劳动力（而不只是工具），切入 Agent 赛道
- **标签**：AI Coding / Agent / Copilot vs Agent / 异步劳动力 / 长期服务程序员群体

## 擅长 & 不擅长

- **擅长**：分析 AI Coding 的产品形态和市场逻辑——尤其是 Copilot 与 Agent 的本质区别、码平民化为何不可行；从开发者视角判断工具价值
- **不擅长**：消费级 AI 产品、非技术人群的 AI 需求（他说「普通人不想写代码，普通人想喝咖啡、拍照、兜风」——他对非程序员群体缺乏同理洞察）；Agent 商业模式尚未验证，他的产品判断属于早期探索

## 核心心智模型

### 模型1：Copilot vs Agent 二分框架

- **一句话**：Copilot 是同步工具（像电钻，你操作它辅助你），Agent 是异步劳动力（像帮你拧螺丝的小弟，可以独立接任务）。两者本质不同：Copilot 依赖用户实时操作，Agent 依赖可靠性而非聪明
- **来源**：[[42章经]] 030 [原话/归纳]
- **怎么用**：
  1. 判断一个 AI Coding 产品：它是让你在 IDE 里写得更快的工具（Copilot 型），还是你能关掉电脑让它自己跑的工人（Agent 型）
  2. Copilot 型判断标准：是否找到了 PMF？交互是否流畅？延迟是否够低？
  3. Agent 型判断标准：可靠性 > 聪明度。问「它搞砸一件事的代价是什么？」而不是「它能做什么？」
  4. 关键洞察：Copilot 已跑通 PMF，会长期存在；Agent 还没跑通 PMF
- **局限性**：这是基于 2024 年状态的判断。如果模型能力出现跃迁——比如模型自己在没有任何人类监督下能可靠完成复杂工程任务——Copilot 和 Agent 的边界可能模糊甚至消失。他本人也承认模型进化会利好 Agent

### 模型2：AI 从工具到劳动力

- **一句话**：过去为程序员做工具，这一波 AI 可能第一次直接生产劳动力。Copilot 是更快的电钻，Agent 是数字员工——生产力提升不在一个量级
- **来源**：[[42章经]] 030 [原话/归纳]
- **怎么用**：
  1. 分析一个 AI 产品时先问：它在做一个「更好的工具」还是「一个新的劳动力」？
  2. 如果答案是工具：竞争壁垒在体验和生态
  3. 如果答案是劳动力：竞争壁垒在可靠性、任务边界定义和反馈回路设计
  4. Agent 产品必须从窄任务切入（如 Gru.ai 选 unit test）——「什么都能干 = 什么也不能干」
- **局限性**：这是一个方向判断而非已被验证的结论。Agent 是否真能成为可靠的「劳动力」仍是一个开放问题

### 模型3：代码平民化不可行论

- **一句话**：软件工程历史上低代码/无代码从未大规模成功；普通人没有写代码的需求；复杂需求用自然语言讲不清楚
- **来源**：[[42章经]] 030 [原话/归纳]
- **怎么用**：
  1. 评估一个「让普通人写代码」的 AI 产品时，用两条标准：这个需求如果够 common，会不会已经变成专业软件？如果够简单，会不会被 ChatGPT 覆盖？
  2. 警惕「一句需求生成整个系统」的叙事——复杂需求无法用自然语言精确描述
- **局限性**：他的判断基于传统软件工程历史。但如果 LLM 的推理和交互能力发生质变——比如能通过长时间对话逐步澄清需求——「自然语言讲不清」的前提可能不再成立。他对 Agent 能力的悲观和对「代码平民化」的悲观之间存在张力：如果 Agent 真能成为可靠劳动力，为什么这个劳动力不能帮非技术人完成技术任务？

## 决策启发式

1. **Agent 最重要品质不是聪明，是可靠**：一个什么都敢说但不可靠的 Agent 比什么都不会的更糟糕 — [[42章经]] 030
2. **窄任务切入，不要什么都行**：Agent 说自己什么都能干，基本意味着什么也不能干。选一个具体任务先做透 — [[42章经]] 030
3. **对底层理解不能偷懒**：能自己看论文就自己看，能自己手写就手写——AI Agent 是全新领域，不能一上来就完全依赖现成工具 — [[42章经]] 030
4. **判断 AI 产品先问：是工具还是劳动力？** — [[42章经]] 030

---

## 内在张力 / 盲区

1. **Agent 能力 vs 码平民化的矛盾**：他认为 Agent 将成为劳动力，但又坚信「代码平民化不可行」。如果 Agent 真能可靠工作，为什么非程序员不能通过 Agent 完成任务？这个矛盾他没有正面处理
2. **开发者视角的偏见**：20 多年程序员出身，长期服务开发者群体，他的所有核心判断都站在程序员角度。他对「普通人不想写代码」的断言虽然简洁有力，但没有和非技术用户做过深度研究
3. **Agent 还未跑通 PMF**：他对 Agent 的所有判断——包括「可靠性 > 聪明度」「窄任务切入」——都是信念而非经验。Gru.ai 本身还在 PMF 探索中
