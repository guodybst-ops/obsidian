# 朱哲清Bill

## 画像

- **身份**：Pokee AI 创始人
- **背景**：在 Meta 七年多负责将强化学习框架落地到广告推荐和基础设施系统，担任应用 RL 团队负责人；同时在 Stanford 攻读 RL 博士
- **标签**：强化学习 / LLM / Agent / RL+LLM 组合 / 电商 AI / 工具使用

## 擅长 & 不擅长

- **擅长**：强化学习在工业场景的落地——不是纯学术 RL，是广告推荐这种「action 很多、需要探索、多步决策」的真实系统；判断 RL 与 LLM 的结合点和分工
- **不擅长**：纯预训练/基础模型能力（他明确说「我们不是大模型公司」）；C 端消费级产品设计

## 核心心智模型

### 模型1：RL ≠ LLM 的平行竞争，RL 是一种学习方式

- **一句话**：RL 和 LLM 不是平行竞争的技术路线——RL 是一种学习方式，可以和 LLM 结合。LLM 提供世界的语言理解和抽象能力，RL 在此基础上做决策和探索
- **来源**：[[42章经]] 035 [原话/归纳]
- **怎么用**：
  1. 当考虑 RL 时不要把它理解为「另一个模型」——理解为一种让模型学会做决策的训练方式
  2. LLM 的角色：知识库 + 输入输出接口——它听懂世界
  3. RL 的角色：决策核心——它选择行动、探索不确定区域
  4. 判断场景是否适合 RL：action 多不多？需不需要探索？是不是多步决策？前一步是否影响后一步？目标是不是整体收益？
- **局限性**：RL+LLM 的组合架构增加了系统复杂度——你需要在两个系统之间设计接口和反馈回路，这对工程要求极高。他的分析基于学术和 Meta 广告推荐的工业经验，但创业公司有限的算力和数据是否支撑这种双系统架构？他在 Pokee 验证了成本可控（月训费不到一万刀），但效果尚未经市场大规模检验

### 模型2：LLM 沿高概率走，RL 探索不确定性

- **一句话**：语言模型容易沿高概率路径走（像被训练过的最常见回答），RL 更关注不确定性在哪里——以更高效率探索未知
- **来源**：[[42章经]] 035 [归纳]
- **怎么用**：
  1. 判断问题类型：如果最优解在常见路径上 → 用 LLM 就够了
  2. 如果最优解需要「不常见」的策略/组合 → 需要 RL 探索
  3. 在 Agent 设计中：LLM 负责"这个问题的标准答案是什么"，RL 负责「还有其他可能吗？那个可能的结果是什么？」
- **局限性**：这是一个概念层面的区分，实际工程中 LLM 也能通过 temperature 调高和多次采样实现一定程度的探索——区分度不如他说的那么绝对。RL 的探索效率优势在无限环境中成立，但在有约束的产品环境中（如电商推荐），LLM + 规则也能覆盖大部分不确定性

### 模型3：Agent 的本质是 RL 驱动的决策

- **一句话**：Agent 真正困难的是复杂多层规划——每增加一步，复杂度指数级上升。需要的不是穷举而是搜索和对未来状态的预估。多数业务不需要从零写代码，而是组合已有 API 完成多步执行
- **来源**：[[42章经]] 035 [归纳]
- **怎么用**：
  1. 设计 Agent 时不要只靠 prompt 串联——对多步决策引入 RL 驱动的搜索和规划
  2. 先分析你的业务：是需要从零创作的（少数），还是组合已有工具的（多数）？
  3. 如果答案是后者——用 LLM 做理解 + API 调用 + RL 做决策，不用从头造轮子
- **局限性**：他的体系高度偏向 RL 驱动的 Agent——这既是他的学术专长也是他的公司定位。Prompt-based Agent（如 LangChain style）在很多场景已经够用。RL 驱动只是在「最困难的多步决策」中才有绝对优势

## 决策启发式

1. **RL 是一种学习方式，不是 LLM 的竞争对手**：LLM 给世界理解，RL 给决策和探索能力 — [[42章经]] 035
2. **Agent 的关键不是 prompt 串联，是搜索和对未来状态的预估** — [[42章经]] 035
3. **我们不是大模型公司，我们是强推理和规划型工具使用 Agent 公司**：创业公司不需要做自己的基础模型 — [[42章经]] 035
4. **很多工程问题本质上就是在组合各种 API**：不需要从零开始 — [[42章经]] 035

---

## 内在张力 / 盲区

1. **RL 中心主义**：他的一切判断——从「为什么 LLM 不够」到「Agent 该怎么做」——都导向 RL 这个解决方案。这既是他的学术专长也是他的产品方向。对于「RL 是否真的比 prompt-based Agent 更优」，需要有第三方独立评估
2. **Meta 经验的可迁移性**：他在 Meta 做的是广告推荐 RL——有海量数据、完整基础设施、清晰 reward 信号的场景。创业公司缺少这些前提条件——他的「低成本方案」（月训费不到一万刀）是否在大规模下保持同等质量未经检验
3. **对 prompt-based Agent 的潜在低估**：他的框架天然倾向于把「强化学习驱动的搜索」作为更好的解决方案，但 2024-2025 年大量有效的 Agent 产品实际上就是 prompt 串联 + 工具调用
