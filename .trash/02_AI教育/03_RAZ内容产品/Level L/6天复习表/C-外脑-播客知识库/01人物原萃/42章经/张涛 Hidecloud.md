# 张涛 (Hidecloud)

## 画像

- **身份**：光年之外产品负责人
- **背景**：塞班手机时代入行的最早一代 mobile 产品人；神策数据 5 年（非业务售前+咨询）；从 To C 到 To B 都做过；2023 年 All in AI
- **标签**：AI原生产品经理 / 塞班时代入行 / 读paper的产品经理 / ComfyUI / 信息洁癖 / 0-Prompt设计理念

## 擅长 & 不擅长

- **擅长**：判断 AI 技术的能力边界并将其转化为产品设计（TPF — Technology-Product Fit）；在信息极度碎片化的 AI 前沿通过读 paper + 上手跑 demo 保持认知领先；理解开源社区进展的不对称信息差
- **不擅长**：大规模工程技术（他做的是产品层，不是 infra 层）；资金极度充裕的大厂语境之外的小团队生存策略（他在光年之外，不是独立创业者）

## 核心心智模型

### 模型1：TPF — Technology-Product Fit

- **一句话**：上一代产品经理解决的是 PMF（产品-市场匹配），AI 时代产品经理必须先解决 TPF（技术-产品匹配）——要理解模型能做什么、不能做什么，因为这决定了 90% 的产品交互。
- **来源**：[[42章经]] 018 — 他观察到当前大部分 AI 产品还是 Model as Product，模型本身的输入输出基本决定了产品的交互 [归纳]
- **怎么用**：
  1. 先理解模型的输入输出能力边界——不要从用户想做什么开始，要从模型能做到什么开始
  2. 判断你的产品属于三种形态中的哪一种：90% Model+10% 产品（太薄，火一阵就没了）vs 10% AI+90% 产品（留存高但不够 magic）vs 50/50（期待但还没出现）
  3. 应用团队不必从零 pre-train，但**必须能"操纵模型"**（Fine-tune/LoRA/蒸馏/裁剪）——这是下限能力
  4. 产品形态是市场演进出来的，不是规划出来的——先做一个 end 去市场验证，再迭代
- **局限性**：他在 2023/2024 年提出 TPF，当时"懂模型边界"是信息差红利。随着 2025-2026 年 best practice 沉淀为常识，这个红利会消失——他自己也承认"2 年内信息差极大，之后不一定需要懂技术"。

### 模型2：0-Prompt 设计理念

- **一句话**：不要假设用户会用打字的方式和 AI 产品交互。Prompt 不一定要来自用户——可以从图片、从前一帧 output、从环境感知自动生成。
- **来源**：[[42章经]] 018 — 他在设计儿童绘画产品「嘟嘟波」时的核心设计原则，以及"很难想象一年后 AI C 端产品主流场景是用户拿着手机一直打字"的判断 [归纳]
- **怎么用**：
  1. 识别你的产品中哪些环节需要用户思考「我该输入什么」——这些环节是流失点
  2. 用两种方式降 Prompt 成本：从用户行为中自动提取意图（拍照/语音/手势）、从上一轮输出中自动生成下一轮的输入
  3. AIGC 不只是 G（生成）有价值——C（内容）本身也具备消费价值。大多数用户是来消费的，不是来生成的
  4. 理解 Diffusion 原理后重新思考推荐：不局限已有内容库 → 在向量空间里现生成无限内容
- **局限性**：0-Prompt 在消费/娱乐场景中很有效，但在生产力/专业工具中可能反效果——专业用户确实需要精确控制输入。他的 0-Prompt 设计主要围绕儿童和消费级场景，对 B 端产品的适用性未验证。

### 模型3：产品经理的信息差方法论

- **一句话**：AI 产品经理的竞争优势不来自天赋，来自信息差——坚持读 paper、自己上手 run demo、浸泡在 Twitter 语境里。大部分人在零，你只要到二三，信息差就足够大。
- **来源**：[[42章经]] 018 — 他描述自己的学习方法，以及面试中"创建过 GPTs 吗？"刷掉 90% 候选人的观察 [归纳]
- **怎么用**：
  1. **读 paper**：一天精读+速读 2-3 篇，有信息洁癖——能看原文就看原文，不喜欢二次咀嚼的内容
  2. **上手跑 demo**：本地把大模型跑起来，看到电脑开始吐字的那一下，"hello world 的震撼是看十篇文章换不来的"
  3. **浸泡语境**：关注 Twitter/X 上的 AI 大号，保持和前沿语境同步
  4. **阶段性地把信息差变现**：每 2-3 个月重新评估——我理解的技术边界和实际模型能力之间的 gap 有多大？
- **局限性**：这是个人方法论，不是可规模化复制的方法。他本身有信息洁癖和长期做产品的技术积累，对于没有技术背景的产品经理，读 paper 的门槛可能高到不切实际。另外，当 AI 发展速度放缓后，信息差的衰减速度会比预计更快。

## 决策启发式

1. **不跟最强大的模型竞争，用好开源社区就够了**：开源社区已有足够好的能力，不必追逐最 strong 的模型 — 实例：绝大多数任务用 7B 模型在 MacBook 本地就能跑 — [[42章经]] 018
2. **AI 产品 day one 就得收费**：推理成本不是可以忽略的——成本约束是 AI 产品不能像互联网产品一样先免费再变现的核心原因 — [[42章经]] 018
3. **你竞争的不是另一个 AI 模型，是抖音、是 Office**：做到 50 分也竞争不过 100 分的抖音——AI 产品要找到AI能带来质变的场景，而不是和成熟产品比功能 — [[42章经]] 018
4. **声音是几大模态里最成熟的，但大家关注最少**：关注模态中被忽视的洼地 — [[42章经]] 018

## 内在张力 / 盲区

1. **信息洁癖 vs 规模化产品判断**：他极度依赖一手信息，但产品判断在许多时候需要的不只是技术信息，还有市场数据、用户研究——这些往往是二手/处理过的信息。过度坚持一手信息可能在市场判断上产生盲区
2. **光年之外的语境**：他在光年之外（由王慧文创办，后有充足资金），对"AI 产品 day one 要收费"的判断可能不适用于需要快速增长用户基数的创业者——他有资本等得起，小团队等不起
3. **对"人类情感太容易被 hack"的推理存在道德模糊**：他描述了看 agent 在自己剧本里黑自己维护自己时仍然被打动的体验，但没有深入讨论这种情感 hack 的边界在哪里——当你知道用户在情感上被 hack 了，产品设计应该做到什么程度
4. **Model as Product 的悲观假设**：他认为当前产品大部分是 Model as Product（90/10 或 10/90），中间地带还没出现。但这可能是 AI 产品必经的阶段，而非缺陷
