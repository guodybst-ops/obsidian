# Lucy的雷霆英语王国小程序项目技术文档

## 1. 项目技术架构

本项目是一个原生微信小程序工程，当前没有使用 Vue、React、Taro、uni-app 等跨端框架，也没有接入 npm 包、云开发或后端服务。

### 技术栈

| 模块 | 当前方案 |
|---|---|
| 小程序类型 | 原生微信小程序 |
| 页面结构 | WXML |
| 页面样式 | WXSS |
| 页面逻辑 | JavaScript |
| 页面配置 | JSON |
| 本地存储 | `wx.getStorageSync` / `wx.setStorageSync` |
| 路由切换 | 自定义底部导航 + `wx.redirectTo` |
| UI组件库 | 无，全部为自定义 WXSS 样式 |
| 后端服务 | 暂无 |
| AI生成 | 暂无真实接口，当前为本地演示逻辑 |
| 发音播放 | 有道词典在线发音地址，正式上线前需配置合法域名 |

### 全局入口

- `app.json`：声明页面路径、窗口样式、懒加载配置。
- `app.js`：维护全局学习状态、积分状态和本地存储方法。
- `app.wxss`：定义全局页面背景、顶部栏、按钮重置、页面容器等基础样式。

### 当前架构特点

1. **轻量原型架构**：所有数据先放在本地 JS 文件和本地缓存中，便于快速预览和修改。
2. **无后端依赖**：导入微信开发者工具后即可预览，不需要服务器。
3. **自定义导航**：没有使用微信小程序原生 `tabBar`，而是实现了 `components/bottom-nav` 自定义底部导航。
4. **全局状态集中在 `app.js`**：学习时长、知识点、积分、任务完成状态都通过 `getApp()` 访问。
5. **适合继续演进为正式 MVP**：后续可把本地数据替换为云数据库、云函数和 AI 接口。

## 2. 页面结构

当前小程序共有 3 个页面，页面顺序在 `app.json` 中声明：

```json
{
  "pages": [
    "pages/knowledge/knowledge",
    "pages/calendar/calendar",
    "pages/rewards/rewards"
  ]
}
```

### 页面一：知识点页

路径：`pages/knowledge/knowledge`

用途：课文筛选、搜索、照片墙、课文知识点学习、老师录入知识点。

### 页面二：学习日历页

路径：`pages/calendar/calendar`

用途：展示当天学习数据、月度热力图、累计学习数据和今日学习知识点。

### 页面三：积分库页

路径：`pages/rewards/rewards`

用途：头像替换、每日任务、积分累计、奖品兑换。

## 5. 每个页面实现功能

### 5.1 知识点页

核心文件：`pages/knowledge/knowledge.js`

#### 静态数据

页面内置 `lessons` 数组，当前包含示例课文：

- `Big Machines`
- `Big Ben and Westminster Palace`
- `Chichen Itza`
- `Cinderello`

每篇课文结构包括：

```js
{
  id: 'big-machines',
  level: 'Level L',
  title: 'Big Machines',
  cover: '/assets/references/参考图-知识点首页.png',
  tags: ['机器', '工程', '被动语态'],
  points: []
}
```

每个知识点结构包括：

```js
{
  id: 'machine',
  type: '单词',
  text: 'machine',
  phonetic: '/məˈʃiːn/',
  chinese: '机器；机械',
  phraseAudio: 'machine',
  sentence: 'Big machines are used to move heavy things.',
  example: 'A machine can help people do hard work.'
}
```

#### 已实现功能

| 功能 | 方法 | 说明 |
|---|---|---|
| 初始化筛选 | `onLoad` / `applyFilter` | 默认筛选 Level L 数据 |
| Level 切换 | `handleLevelChange` | 切换后重新筛选课文 |
| 搜索 | `handleSearch` | 按标题、标签、知识点等文本过滤 |
| 清空搜索 | `clearSearch` | 清空关键词并恢复筛选结果 |
| 选择课文 | `selectLesson` | 切换当前选中的课文卡片 |
| 展开照片墙 | `toggleGallery` | 控制照片墙半展开/全展开 |
| 选择照片 | `choosePhoto` | 调用 `wx.chooseMedia` |
| 展开知识点 | `togglePoint` | 展开详情，并调用 `app.recordKnowledgeInteraction({ id, text })` 记录有效交互 |
| 发音播放 | `playPoint` / `speak` | 播放发音，并记录一次有效交互 |
| 打开老师面板 | `openTeacherPanel` | 显示录入弹窗 |
| 关闭老师面板 | `closeTeacherPanel` | 关闭录入弹窗 |
| 更新标题 | `updateFormTitle` | 更新录入表单标题 |
| 更新原始输入 | `updateFormRaw` | 更新录入单词/词组文本 |
| 生成知识点 | `generateKnowledge` | 本地拆分输入，生成预览数据 |
| 加入首页 | `useGenerated` | 把生成数据插入 `lessons` 数组顶部 |

#### 当前限制

- 录入生成的数据只存在当前页面运行内存中，刷新小程序后不会持久保存。
- 发音播放已接入在线发音地址，正式上线前需配置合法域名或替换为自有 TTS。
- 课文数据写死在 JS 文件中，尚未接数据库。

### 5.2 学习日历页

核心文件：`pages/calendar/calendar.js`

#### 已实现功能

| 功能 | 方法 | 说明 |
|---|---|---|
| 实时读取学习数据 | `onShow` / `loadStudyData` | 每秒读取一次全局学习状态 |
| 生成热力图颜色 | `heatLevel` | 根据去重知识点数返回 `level-0` 到 `level-4` |
| 切换月份 | `previousMonth` / `nextMonth` | 左右切换查看不同月份 |

#### 展示数据

- 今日学习时长：`todayDurationValue` + `todayDurationUnit`
- 今日知识点数量：`todayKnowledgeCount`
- 今日知识点列表：`todayKnowledge`
- 累计学习时长：`monthlyDurationValue` + `monthlyDurationUnit`
- 累计学习天数：`studyDays`
- 累计知识点：`monthlyKnowledgeCount`
- 月度热力图：`heatmap`

#### 当前限制

- 当前仍使用本地缓存，换设备或清缓存后学习记录会丢失。

核心文件：`pages/rewards/rewards.js`

#### 静态数据

任务数据：

```js
const tasks = [
  { id: 'login', title: '每日登录', points: 1 },

  { id: 'read-word', title: '阅读单词', points: 2 },
  { id: 'read-phrase', title: '阅读词组', points: 2 },
```

奖品数据：

```js
const prizes = [
  { id: 'duck-chair', name: '奶娃扇子', points: 5, image: '/assets/prizes/image01.jpg' }
]
```

#### 已实现功能

| 功能 | 方法 | 说明 |
|---|---|---|
| 页面显示时加载状态 | `onShow` / `loadState` | 读取积分、任务完成状态、头像 |
| 切换任务/兑换卡 | `switchMode` | 设置 `mode` 为 `tasks` 或 `prizes` |

- 奖品数据写死在页面 JS 中。

## 6. 数据流向

### 6.1 全局学习状态

全局状态定义在 `app.js` 中，核心结构如下：

```js
{
  version: 2,
  points: 8,
  completedTasks: {},
  dailyRecords: {
    '2026-07-08': {
      totalSeconds: 42,
      knowledgeMap: {
        machine: 'machine'
      },
      interactions: 3
    }
  },
  timer: {
    total_time: 42,
    count_time: 3,
    pause_if: false
  }
}
```

### 6.2 初始化数据流

```text
小程序启动
  ↓
app.js onLaunch()
  ↓
读取 wx.getStorageSync('lucyStudyState')
  ↓
如果有缓存：标准化为 version 2 数据结构
如果无缓存：创建空学习记录
  ↓
写入 app.globalData.study
```

### 6.3 学习记录数据流

```text
用户在知识点页点击知识点
  ↓
pages/knowledge/knowledge.js togglePoint()
  ↓
app.recordKnowledgeInteraction({ id, text })
  ↓
记录去重知识点，count_time 归 0，pause_if = false
  ↓
每秒累加 total_time，10 秒无交互后 pause_if = true 并暂停计时
  ↓
app.saveStudyState()
  ↓
wx.setStorageSync('lucyStudyState')
  ↓
学习日历页 onShow() 读取并展示新数据
```

### 6.4 积分数据流

```text
用户在积分页点击任务
  ↓
pages/rewards/rewards.js completeTask()
  ↓
写入 completedTasks[id] = true
  ↓
app.addPoints(points)
  ↓
更新 study.points
  ↓
wx.setStorageSync('lucyStudyState')
  ↓
积分页 loadState() 刷新展示
```

### 6.5 兑换数据流

```text
用户点击奖品卡片
  ↓
pages/rewards/rewards.js redeemPrize()
  ↓
app.spendPoints(points)
  ↓
如果积分不足：提示积分还不够
如果积分足够：扣减 points 并保存本地缓存
  ↓
弹窗提示兑换成功
  ↓
积分页 loadState() 刷新展示
```

### 6.6 头像数据流

```text
用户点击头像
  ↓
wx.chooseMedia()
  ↓
选择图片得到 tempFilePath
  ↓
wx.setStorageSync('lucyAvatar', tempFilePath)
  ↓
rewards 页面 setData({ avatar: path })
```

## 8. 后续正式化改造建议

### 第一阶段：整理代码结构

建议新增：

```text
data/
  lessons.js
  tasks.js
  prizes.js

services/
  studyService.js
  pointService.js
  aiService.js
  audioService.js

components/
  lesson-card/
  knowledge-point-card/
  study-heatmap/
  prize-card/
```

目标：把页面从“数据 + 逻辑 + UI 混合”改成“页面负责展示，服务负责数据”。

### 第二阶段：接入真实数据

1. 使用云数据库保存课文、知识点、学习记录、积分、奖品。
2. 使用云存储保存课文图片、照片墙图片、奖品图片、音频文件。
3. 使用云函数接入 AI 接口，生成释义、音标、例句和复习任务。
4. 增加老师端和学生端身份区分。

### 第三阶段：完善学习闭环

1. 播放音频后记录“已听”。
2. 学生跟读后上传录音。
3. AI 批改发音，给出分数和错音提示。
4. 自动生成错题/错词复习队列。
5. 每周生成学习报告。

## 9. 当前项目适合交给开发者的说明

如果交给开发者继续做，可以这样描述当前状态：

> 这是一个原生微信小程序原型，已经完成三页 UI 和本地交互。当前数据为 JS 静态数据 + 微信本地缓存，暂未接云开发、数据库、AI 和真实 TTS。请在保持现有页面风格的基础上，优先把课文/知识点/学习记录/积分/奖品抽象成数据服务，再接入云数据库和 AI 生成能力。

## 10. 当前风险点

| 风险 | 影响 | 建议 |
|---|---|---|
| 数据写死在页面 JS | 后续维护成本高 | 抽离到 `data/` 或云数据库 |
| 录入生成不持久化 | 老师录入内容刷新后丢失 | 接本地缓存或云数据库 |
| 任务不按日期重置 | 每日任务逻辑不真实 | completedTasks 增加日期维度 |
| 发音只是占位 | 学习体验不完整 | 接 TTS 插件或云函数音频生成 |
| 页面组件未拆分 | 后续页面变复杂后难维护 | 优先拆知识点卡、热力图、奖品卡 |
| 无用户身份 | 只能服务单个 Lucy | 正式版需接微信登录和学生档案 |
