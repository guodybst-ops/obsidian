# 状态初始化与知识图谱关系设计

> 日期：2026-07-06
> 状态：架构决策稿 V0.1
> 关联文件：[[11 Learning State Engine 完整架构蓝图]]

---

## 1. 本轮决策

### 1.1 学生状态初始化

正式采用混合初始化方案：

```text
新学生进入
-> 所有相关知识点给中性初值
-> 做一组短前测
-> 根据前测校准第一版 student_state
-> 前两次练习只输出“初步判断”
-> 证据超过阈值后再输出稳定红黄绿报告
```

这个方案的意义：

- 不会一开始假装系统很懂学生。
- 不会因为没有历史数据而无法启动。
- 可以让家长和老师理解“前几次是校准期”。
- 可以避免第一次作答波动直接造成错误标签。

### 1.2 知识图谱关系

系统要预留类似 Obsidian 的知识图谱能力：

> 相关知识点之间有连线，连线能表示关系类型和关系紧密程度。

当前只进入架构层，不进入界面设计和实现。

## 2. 混合初始化方案

### 2.1 初始默认值

当学生没有历史数据时，每个目标知识点先给中性初值：

```json
{
  "mastery": 0.60,
  "confidence": 0.20,
  "evidence_count": 0,
  "status_color": "yellow",
  "state_phase": "uncalibrated"
}
```

解释：

- `mastery=0.60` 不是说学生已经掌握，而是避免系统一开始把学生判成红色。
- `confidence=0.20` 表示系统证据不足。
- `state_phase=uncalibrated` 表示还不能给稳定结论。

### 2.2 短前测

前测不是考试，而是状态校准。

前测原则：

- 题量少：5-10 题。
- 覆盖核心知识点。
- 优先基础题和少量变式题。
- 不输出强评价，只更新初始状态。

前测输出：

```json
{
  "pretest_result": {
    "covered_knowledge_points": [],
    "state_events": [],
    "initial_state_adjustments": [],
    "calibration_note": "初步校准，不代表稳定掌握。"
  }
}
```

### 2.3 校准期

前两次练习都属于校准期。

校准期报告规则：

- 可以显示红黄绿，但必须标注“初步判断”。
- 不输出“已经掌握”“基础薄弱”等确定性措辞。
- 给老师/家长的结论要附带证据数量。
- 不用一次结果决定长期学习路径。

### 2.4 稳定期

当某个知识点满足以下条件，才进入稳定判断：

```text
evidence_count >= 3
confidence >= 0.45
至少经历 2 种题型，或同一题型出现跨时间证据
```

稳定期报告才可以说：

- 基本掌握。
- 部分掌握。
- 需要专项补救。

### 2.5 初始化状态阶段

建议给 `student_state` 增加 `state_phase` 字段：

| state_phase | 含义 | 报告措辞 |
| --- | --- | --- |
| `uncalibrated` | 尚未校准 | 暂无足够证据 |
| `calibrating` | 校准期 | 初步判断 |
| `evidence_building` | 证据积累期 | 倾向判断 |
| `stable` | 稳定判断期 | 可以输出明确建议 |

## 3. 知识图谱关系模型

### 3.1 KnowledgeRelation

知识点之间的连线不是装饰，而是系统决策依据。

建议关系结构：

```json
{
  "relation_id": "rel_pep6_u1_usually_often",
  "source_knowledge_point_id": "kp_pep6_u1_usually",
  "target_knowledge_point_id": "kp_pep6_u1_often",
  "relation_type": "confusable_with",
  "direction": "bidirectional",
  "strength": 0.85,
  "evidence_source": ["curriculum", "student_errors"],
  "note": "两个频率副词容易混淆，适合成对训练。"
}
```

### 3.2 关系类型

| relation_type | 含义 | 用途 |
| --- | --- | --- |
| `belongs_to` | 属于某单元/主题 | 组织知识结构 |
| `prerequisite_of` | A 是 B 的前置知识 | 决定学习顺序 |
| `confusable_with` | 容易混淆 | 生成对比题 |
| `co_practiced_with` | 适合一起练 | 组成练习组 |
| `remediates` | A 可补救 B 的错误 | 错题再练 |
| `applies_to` | 知识点应用到能力场景 | 做迁移题 |
| `same_pattern_as` | 同一结构或题型 | 做变式训练 |

### 3.3 关系强度

`strength` 用 0 到 1 表示关系紧密程度。

| strength | 含义 | 系统动作 |
| --- | --- | --- |
| 0.00-0.29 | 弱关联 | 只在图谱中弱显示，不主动联动 |
| 0.30-0.59 | 中关联 | 可用于推荐复习或补充练习 |
| 0.60-0.84 | 强关联 | 可用于组题和错题再练 |
| 0.85-1.00 | 极强关联 | 错一个时优先检查另一个 |

关系强度来源：

- 教材结构。
- 老师标注。
- 学生错题共现。
- 前置知识关系。
- 同一题型或同一语法结构。

### 3.4 图谱如何影响学习策略

知识图谱不是只给用户看，它要影响系统决策。

例子：

- `usually` 错了，且和 `often` 是强 `confusable_with`，下一轮优先生成对比题。
- `I go to school by bus.` 错了，系统检查 `by bus` 和 `go to school` 是否也不稳。
- 阅读定位错了，系统检查 `bus stop` 是否只是词义不懂，还是阅读技能不稳。

## 4. 未来可视化预留

未来可以做类似 Obsidian 的知识图谱视图，但现在不作为重点。

预留设计：

- 节点：知识点。
- 节点颜色：该学生在该知识点上的红黄绿状态。
- 连线：知识点关系。
- 连线粗细或深浅：关系强度。
- 连线类型：前置、混淆、共练、补救、应用。

当前不讨论：

- UI 长什么样。
- 用什么图谱库。
- 是否动画。
- 是否做交互拖拽。

当前只确认：

> 架构中必须有 `KnowledgeRelation` 和 `strength`，以便未来可以自然发展成知识图谱视图。

---

## 5. 对现有文件的影响

后续需要更新的数据结构：

- `student_state` 增加 `state_phase`。
- `knowledge_points` 保持不变。
- 新增 `knowledge_relations` 表。
- 学习报告中增加“证据阶段”表达。

当前不急着改 Dify 或产品实现。

---

## 6. 当前结论

- 状态初始化正式采用混合方案。
- 前两次练习属于校准期，只能输出初步判断。
- 稳定红黄绿必须依赖足够证据。
- 知识图谱必须支持知识点连线。
- 连线必须支持关系类型和关系强度。
- 图谱可视化以后再说，现在只做架构预留。
