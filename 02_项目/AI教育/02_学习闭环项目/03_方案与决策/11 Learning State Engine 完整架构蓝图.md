## 1. 第一性原理总定义

学习的本质不是“看过内容”，也不是“做过题”，而是：

> 学习者面对某类任务时，可稳定调用的知识和能力状态发生了改变。

所以系统的本质不是出题器，而是：

> 学习状态更新引擎。

最小闭环：

```text
Knowledge State
-> Stimulus
-> Student Action
-> Feedback Signal
-> State Update
-> Learning Policy
-> Next Stimulus
```

这意味着：

- 题目只是刺激，不是系统资产的全部。
- 答案只是反馈的一部分，不是学习本身。
- 错题不是终点，而是状态更新证据。
- 报告不是总结文案，而是状态可视化。
- AI 不是老师本人，而是状态判断、策略推荐和内容生成的函数集合。

## 2. 七层架构

### L1 Knowledge Layer：知识层

定义系统要教什么。

核心对象：

- `KnowledgePoint`：最小知识点。
- `KnowledgeRelation`：知识点之间的关系。
- `KnowledgeScope`：教材、考试、课程、能力域边界。
- `KnowledgeInput`：用户输入的知识材料，输入类型不设限制，由 AI 自动识别；交互形态优先采用类似 ChatGPT 的对话窗口和拖拽上传。
- `KnowledgeTransformation`：把知识点转化为题目、练习和教案的过程。

关键问题：

- 知识点切多细？
- 哪些知识点是先修？
- 哪些知识点容易混淆？
- 哪些知识点需要反复复习？
- 输入的任意材料如何抽取知识点？
- 一个知识点如何转成题目或教案？

2026-07-06 追加决策：系统需要预留类似 Obsidian 的知识图谱能力。相关知识点之间应有连线，连线包含 `relation_type` 和 `strength`，用于表达关联类型和关联紧密程度。具体设计见 [[12 状态初始化与知识图谱关系设计]]。

2026-07-07 追加决策：L1 不只是静态知识库，还必须包含“AI 对话式知识输入与转化”能力。输入类型不设限制，用户可以把材料拖入聊天框，AI 自动识别材料类型和知识结构，并把知识点转为题目、练习和教案。交互网页板块见 [[13 交互式网页板块说明]]。

### L2 Learner State Layer：学生状态层

定义学生当前处于什么状态。

核心对象：

- `Mastery`：掌握度。
- `Confidence`：系统对判断的置信度。
- `Evidence`：判断依据。
- `ErrorProfile`：高频错因画像。
- `LearningHistory`：练习和复习轨迹。
- `PassStreak`：连续通过次数。
- `FailStreak`：连续不通过次数。
- `DailyLearningMetrics`：每日学习量、做题量、转绿/转红知识点等趋势数据。

关键问题：

- 学生状态如何初始化？
- 一次答题能提供多强证据？
- 什么情况下从红变黄、从黄变绿？
- 多久没练会遗忘？

当前红黄绿简化规则：学过某个知识点后转为黄色；连续 3 次该知识点题目考核均通过，转为绿色；连续 3 次不通过，转为红色。底层仍保留 `mastery`、`confidence` 和 `state_phase`。

2026-07-07 追加决策：L2 需要包含数据看板，至少支持每日学习量折线图，用来展示每日做题数量、学习知识点数量、通过知识点数量、转绿/转红知识点数量和学习时长等趋势。

### L3 Stimulus Layer：学习刺激层

定义系统给学生什么任务。

题目只是刺激的一类。

刺激类型：

- 识别：选择、判断、配对。
- 回忆：填空、默写、短答。
- 生成：翻译、造句、写作。
- 迁移：阅读理解、应用题、真实场景表达。
- 纠错：找错、改错、解释错因。

关键问题：

- 一个知识点适合什么刺激？
- 什么刺激能证明“真的会了”？
- 如何避免学生只记住原题？

### L4 Feedback Layer：反馈层

定义系统如何理解学生输出。

反馈不是只判对错，而是提取状态证据。

反馈结构：

- `is_correct`
- `error_tags`
- `evidence_strength`
- `explanation_for_student`
- `diagnosis_for_teacher`
- `needs_human_review`
- `wrong_knowledge_points`
- `error_dashboard_metrics`

关键问题：

- 答案部分正确怎么处理？
- 翻译题多种表达如何处理？
- AI 不确定时怎么降级？
- 学生输入包含无关内容或提示词攻击怎么处理？
- 如何把错因和错误知识点沉淀成数据看板？

2026-07-06 追加决策：L4 必须把学生输出转化为错因数据和错误知识点数据，并能形成数据看板，包括常见错因、常错知识点、错因 x 知识点矩阵。

### L5 State Update Layer：状态更新层

定义反馈如何改变学生状态。

状态更新不是简单加减分，而是根据证据强度、题型、难度、连续表现更新。

更新来源：

- 当前题是否正确。
- 当前题难度。
- 当前题检测的知识点。
- 错因标签。
- 是否连续答对或连续同错因答错。
- 距离上次练习时间。

关键问题：

- 基础题错了是否比难题错了更严重？
- 连续答对几次才能认为掌握？
- 单次正确是否足够变绿？
- 旧知识多久要回炉复习？

### L6 Learning Policy Layer：学习策略层

定义下一步学什么、练什么、怎么练。

这是系统的核心决策层。

策略输入：

- 知识图谱。
- 学生状态。
- 错因画像。
- 学习目标。
- 时间限制。
- 教师/家长期望。

策略输出：

- 下一组知识点。
- 下一组刺激类型。
- 难度。
- 是否复习。
- 是否人工介入。
- 是否停止练习。

### L7 Reporting / Intervention Layer：报告与干预层

定义如何把状态转化为行动。

报告不是为了好看，而是为了触发正确行动。

报告对象：

- 学生：知道下一步怎么练。
- 家长：知道孩子哪里稳、哪里不稳、是否需要焦虑。
- 老师：知道讲什么、补什么、怎么分层。
- 机构：知道班级错点、续费证据、老师工作量节省点。

## 4. 教育学原则映射

| 原则 | 系统含义 | 架构落点 |
| --- | --- | --- |
| 检索练习 | 学生要主动输出，而不是只看讲解 | Stimulus Layer |
| 间隔重复 | 掌握度会随时间衰减，需要复习 | State Update Layer |
| 掌握学习 | 每个知识点要达到阈值再进入下一步 | Learner State Layer |
| 最近发展区 | 题目难度应略高于当前水平 | Learning Policy Layer |
| 反馈及时性 | 错误后要尽快给反馈和再练 | Feedback Layer |
| 认知负荷 | 一次练习不应塞太多知识点 | Policy / Stimulus Layer |
| 迁移训练 | 会做原题不等于掌握 | Stimulus Layer |

## 5. 心理学原则映射

### 5.1 不制造习得性无助

连续答错时，系统不应继续加难，而应降级、拆小、给可完成任务。

架构规则：

- 连错 3 题触发 `lower_difficulty`。
- 同一错因反复出现，进入专项补救，不继续推进新知识。

### 5.2 不给虚假掌握感

一次答对不等于掌握。

架构规则：

- `mastery` 和 `confidence` 分离。
- 低 `confidence` 时报告只能说“初步表现”。
- 绿灯需要多次证据，最好跨题型验证。

### 5.3 保护学习动机

报告不能只说错，应该给学生明确可执行的下一步。

架构规则：

- 学生报告不使用“基础差”等标签。
- 学生报告只给 1-2 个当前最重要动作。
- 家长报告避免夸大焦虑。

## 6. 架构边界

### 6.1 当前不是产品

本文件不定义页面、按钮、Dify 节点、数据库选型或商业报价。

这些以后都可以变，但底层架构不能轻易变。

### 6.2 当前不是纯算法

这个系统不是只靠一个掌握度公式。教育系统必须允许：

- 老师复核。
- 家长解释。
- 学生体验。
- 内容边界。
- 安全审查。

### 6.3 当前不是通用 AI 老师

系统不追求什么都能讲。

它优先做：

> 在一个清晰知识范围内，稳定追踪学生状态，并决定下一步训练。

- [ ] 迁移到其他学科时，哪些层复用，哪些层重做。

## 8. 当前最重要的 5 个架构问题

### Q1：状态初始化

学生第一次进来时，状态从哪里来？

候选方案：

1. 所有知识点统一 `mastery=0.60, confidence=0.20`。
2. 先做 5-10 道前测题初始化。
3. 由老师/家长给初始水平。
4. 混合：先统一初值，再用前两次练习快速校准。

当前决策：采用方案 4，即混合初始化。先给中性初值，再用短前测和前两次练习快速校准。校准期只输出“初步判断”，证据足够后再输出稳定红黄绿报告。具体设计见 [[12 状态初始化与知识图谱关系设计]]。

### Q2：知识点粒度

知识点太粗，报告无用；太细，维护爆炸。

当前倾向：

> 中粒度知识点 + 细粒度错因标签。

### Q3：掌握度更新

早期不要上复杂算法，先用可解释规则。

当前倾向：

> 规则模型 V0.1，后续再引入更复杂的知识追踪模型。

### Q4：Learning Policy

系统到底优先补弱，还是推进新知识？

当前倾向：

> 先补最影响当前单元闭环的薄弱点，再做迁移验证，不急着扩新知识。

### Q5：报告真实性

如何避免报告看起来很聪明但没有证据？

当前倾向：

> 报告必须显示证据强度。证据不足时，只能说“初步判断”。

## 9. 下一轮共创建议

下一轮不要继续谈产品，也不要谈 Dify。

建议只讨论一个架构问题：

> 学生状态如何初始化？

因为初始化会影响后面所有事情：

- 第一次练什么。
- 报告是否可信。
- 红黄绿是否合理。
- 老师/家长是否接受。
- 系统是否能逐步变聪明。

当前已采纳的初始化方案：

```text
新学生进入 -> 所有知识点给中性初值
-> 做一组短前测
-> 根据前测生成第一版 state
-> 前 2 次练习只说“初步判断”
-> 证据超过阈值后才输出稳定红黄绿报告
```

这个方案最稳，既不会一开始假装很懂学生，也不会因为没有数据而无法启动。

同时，系统架构已预留知识图谱关系模型：知识点之间可以像 Obsidian 一样有连线，并用关系强度表达紧密程度。该能力暂时只作为架构预留，不进入产品和界面讨论。
