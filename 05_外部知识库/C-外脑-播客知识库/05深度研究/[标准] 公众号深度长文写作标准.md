# 公众号深度长文写作标准

这个标准用于 `05深度研究/` 下的 `[长文]` 文件。它解决的不是“文章有没有写长”，而是文章是否像一篇可以公开发布的公众号深度长文：有问题意识，有叙事推进，有材料背书，也有清楚的观点归属。

## 一、文章形态

长文不是内部研究报告，也不是知识库条目扩写。

它应该先让读者进入一个具体处境，再把处境背后的结构慢慢拆开。开头要有场景、冲突或反常识判断；中段要有叙事推进和论证转折；结尾要把文章收束到一个有余味的判断。

避免把正文写成：

```text
概念 1 -> 概念 2 -> 概念 3 -> 检查表
```

更适合写成：

```text
一个具体困境 -> 为什么旧解释不够 -> 谁在播客里提供了关键视角 -> 多个视角合在一起说明什么趋势 -> 普通人怎么重新理解自己的行动
```

## 二、背书引用硬规则

每篇长文的核心判断必须有来源归属，不能只写“我理解”“我们会发现”。

正文里至少出现三类背书：

1. **人物背书**：谁提出或强调了这个观点。
2. **节目背书**：出自哪档播客、哪一期或哪组连续讨论。
3. **语境背书**：当时是在讲什么案例、问题、行业或具体场景。

推荐写法：

```text
杨涛在《平民创业手册》016 里谈 MVP 付费验证时，重点不是让人把产品做小，而是让普通人先拿到真实付费反馈。
```

```text
斯斯在《富女孩宝典》004 和 012 里反复使用“获客、交付、复购、推荐”的完成度模型，这让首单从“成功”变成了一个更早期的测试点。
```

```text
这是本文的 AI 综合判断：把杨涛的现金流优先级、粥左罗的低成本高上限机会、斯斯的 12-6 月法则放在一起看，普通人的转型更像分阶段下注，而不是一次性 All in。
```

禁止写法：

```text
真正重要的不是成交，而是客户资产。
```

如果要写这句话，必须补成：

```text
这个判断来自几组材料的交叉：斯斯在《富女孩宝典》里讲复购和推荐，杨涛在《平民创业手册》050 里把好客户定义为高客单、高利润、高信任、高粘性、复购和转介绍；《我是销冠》的信任公式和客户识别方法，则把这件事落到了销售动作上。
```

## 三、观点来源表

每篇长文末尾固定添加：

```markdown
## 观点来源表

| 文中观点 | 主要提出者/来源 | 原始语境 |
|---|---|---|
|  |  |  |
```

表格不追求堆满资料，而是要覆盖文章的关键支柱观点。一般一篇长文至少 5 条，最好覆盖：

- 开头提出的核心问题；
- 中段最重要的转折判断；
- 关键模型或方法；
- 案例依据；
- 文章最后的综合判断。

如果某个判断是 AI 综合，不属于任何单一播客作者，必须写清楚：

```text
AI 综合：基于 A、B、C 三组节点归纳
```

## 四、内部来源

每篇长文末尾固定添加：

```markdown
## 内部来源

本文基于播客知识库中的内部研究底稿或概念节点改写，不代表用户本人观点。主要参考节点包括：

- <已有笔记路径或标题>
```

内部来源只链接已经存在的笔记。不要为了让文章看起来丰富而创建死链。

## 五、六项自检

发布前逐条检查：

1. 读者看完前三段，是否知道这篇文章在解决什么现实困境？
2. 文中每个核心判断，是否能看出是谁提出、从哪里来、原始语境是什么？
3. 是否区分了外部作者观点和 AI 综合判断？
4. 是否有具体案例或节目语境支撑，而不是只有抽象概念？
5. 是否像公众号长文一样自然推进，而不是内部研究报告？
6. Wiki Link 是否只链接已存在目标，没有死链？
