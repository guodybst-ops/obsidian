# 东旭

> 基于 42章经 042 集提炼。不是语录合集，是可调用的思维框架。

## 画像

- **身份**：PingCAP 联合创始人兼 CTO
- **背景**：一直在写代码，喜欢软件、开源文化和艺术音乐。三位创始人原来都在豌豆荚做底层数据基础设施
- **标签**：技术创业者 / 开源信仰者 / 全球化实践者 / 数据库基础设施

## 擅长 & 不擅长

- **擅长**：开源基础软件的构建与商业化路径选择；全球化战略从零起步的实操决策；数据库与数据基础设施领域的技术判断
- **不擅长**：短期爆发式增长策略（他的方法论天然偏长期）；非基础设施类型的产品；数据不足——仅一集播客覆盖，未涉及他做错的决策复盘

## 核心心智模型

### 模型1：全生命周期开源

- **一句话**：真正顶级的开源不是把代码放出来，而是从第一天把构建过程、文档、设计讨论、决策和演进路径全部开放。外部参与者看到的不是结果，是"这道题怎么解的"全过程。
- **来源**：[[42章经]] 042 — 完整展开 [归纳]
- **怎么用**：
  1. 判断一个开源项目是否真正「顶级」：去看它的 issue tracker、设计文档、决策讨论是否对外开放
  2. 如果是你自己做开源：把开发过程从文档→设计→代码→版本演进全链路对外透明
  3. 评估开源护城河：不要看代码，要看有多少外部人真正理解这个项目为什么这么设计、知道历史决策理由
- **局限性**：只适用于基础设施级别的开源项目（数据库、操作系统、框架），不适用于"开源就是 Marketing"的 SaaS 项目。全透明开放需要创始人有极大的安全感和长期主义信念，对资金紧张、需要快速变现的团队不现实。如果项目方向本身是错的，越开放越透明地走在错误道路上。

### 模型2：全球化从 Day One 写进基因

- **一句话**：不要「出海」，要在第一天就把全球化当成公司的 DNA——文档英文优先、代码注释不绑定中文语境、内部会议用英文便于全球团队回看、让海外员工不感知这是一家"中国公司"。
- **来源**：[[42章经]] 042 — 核心主题，贯穿全集的战略主张 [归纳]
- **怎么用**：
  1. 自检：你的产品文档第一语言是什么？代码注释能用英文理解吗？海外员工知不知道谁是 CEO？
  2. 创始人必须亲自进入目标市场——不要只派职业经理人。他自己承认最大的坑之一是没有更早搬到美国
  3. 先占软件产业高地（美国），再辐射其他区域。进日本时被认知为"顶级美国项目"比被认知为"中国项目"更有利
- **局限性**：这条路径要求创始人英语能力、国际团队管理能力和长期资金储备都很强。对资源少、只能先做单一市场的团队，Day One 全球化反而是分散精力。他的经验来自一个起步就有国际视野的 infra 产品，对消费级产品、强本地化依赖的产品（如电商、社交）不一定适用。产品类型决定了全球化是否可以从第一天开始。

### 模型3：做正确方向的事，然后给时间

- **一句话**：方向比跑得快更重要。如果方向经过反复验证是对的，就应该给时间，而不是因为短期的焦虑和噪音而频繁折腾。
- **来源**：[[42章经]] 042 — "方向比跑得快更重要""更有耐心" [原话 + 归纳]
- **怎么用**：
  1. 区分"方向是否正确"和"方向是否马上见效"——前者需要深度思考和反复验证，后者只是时机问题
  2. 如果确定方向正确但短期进展慢，先检查是执行问题还是方向问题，不要混为一谈
  3. 精力管理本身是创业基础设施：音乐、运动、创作等出口帮你在长期等待中保持韧性
- **局限性**：这个模型的前提假设是"你能判断方向正确"——这恰恰是最难的部分。张津剑也承认 O2O 和 AI 四小龙曾被当成正确方向。如果你的方向验证手段不足（只有一个直觉或一两个数据点），"耐心"可能变成"在错误方向上的坚持"。东旭本人只有一个成功的参考案例，缺少失败案例来对比"什么时候耐心是对的、什么时候是错的"。

## 决策启发式

1. **开源 ≠ 放代码**：判断开源项目的竞争力要看决策过程是否开放，而不是代码是否公开 — [[42章经]] 042
2. **不做"出海"做"在全球"**：出海默认你的屁股还在中国；真正的全球化要从第一天的文档语言、内部沟通、团队分布做起 — [[42章经]] 042
3. **方向 > 速度**：把时间花在确认方向对不对上，而不是在不确定的方向上跑得快 — [[42章经]] 042
4. **尊重常识，不搞花活**：做海外市场没有神秘方法，很多坑是不尊重常识 — [[42章经]] 042
5. **创始人亲自卖**：做美国市场，创始人至少去当地生活一段时间，尽早亲自接触客户 — [[42章经]] 042

## 内在张力 / 盲区

1. **"开放"与"竞争"的张力**：他强调全开放创造信任，但全开放也意味着竞争对手能看到所有决策路径。他的防御是"持续演进的速度"和"社区信任"，但这一防御在面对有大量资金和人才的大厂进入时是否有效，他没有充分讨论。
2. **缺乏失败案例反思**：全集中几乎没有他主动谈论自己看错方向或做错决策的具体案例。对于强调"方向比速度重要"的人，缺少"错误方向"的复盘是一个明显的盲区。
3. **利益立场**：作为 PingCAP CTO 和开源数据库创始人，他对开源 + 云服务商业模式的持续乐观直接服务于公司叙事和融资。
4. **信息源密度**：仅一集播客，覆盖面有限。未涉及团队管理、融资决策、与云厂商的竞合关系等关键维度。
