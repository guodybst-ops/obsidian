# 吴翼

## 画像

- **身份**：清华大学交叉信息院（叉院）助理教授，曾任 OpenAI 研究员
- **背景**：长期研究强化学习的泛化性和多智能体 RL。博士论文题目《Building Generalizable Learning Agents》（包含 RL、泛化、agent 三个关键词）。在伯克利读博期间师从 Pieter Abbeel、Sergey Levine。2020 年从 OpenAI 回国任教
- **标签**：强化学习 / RLHF / O1 推理 / Agent / 预训练×RL = 智能 / 多样性探索 / 人生也是 RL

## 擅长 & 不擅长

- **擅长**：强化学习的全栈理解——从学术理论（泛化性、多智能体）到工业落地（OpenAI、蚂蚁 AReaL 框架）；用 RL 框架理解和解析 AI 产业趋势（如 O1 的本质）
- **不擅长**：创业实务——他是教授而非创业者；具体的 AI 应用产品设计。数据不足——仅一集，非技术维度的能力无法判断

## 核心心智模型

### 模型1：预训练 × 强化学习 = 完整智能体

- **一句话**：预训练和强化学习是乘法关系——预训练给「理解世界的知识」，强化学习给「做决策的能力」。两者乘起来才有完整智能。RLHF 让模型「好用」，O1/R1 式推理 RL 开始让模型「更聪明」
- **来源**：[[42章经]] 039 [原话/归纳]
- **怎么用**：
  1. 分析一个 AI 产品时先看：它用的是预训练能力（理解知识、生成内容）还是 RL 能力（决策、规划、多步执行）？
  2. RLHF 类型：让模型遵从指令、对齐人类偏好 → 价值在「好用」
  3. O1 类型：让模型在思考过程中自我纠正、探索不同路径 → 价值在「聪明」
  4. 如果模型只有理解能力没有决策能力 → 它是库。如果只有决策能力没有理解能力 → 它是搜索
- **局限性**：乘法关系是一个概念洞察但缺少对应的工程框架——如何在具体产品中「乘以」RL？他的分析停留在「是什么」层面，「怎么做」依赖学术界和 OpenAI 的工程能力。对大多数 AI 创业公司来说，「预训练已经是商品化的了，我们只要加 RL」其实是一句太天真的话——因为在别人模型之上做 RL 本身就是一种受限于 API 和推理成本的工程挑战

### 模型2：O1 范式的本质——从「一次给答案」到「在思考中探索」

- **一句话**：RLHF 让模型更好用，但 O1 式强化学习开始让模型更聪明——从单次回答变成在回答过程中进行多步思考、自我纠正和策略探索，形成新的 scaling law
- **来源**：[[42章经]] 039 [原话/归纳]
- **怎么用**：
  1. 判断一个任务是否适合 O1 范式的 RL：问题是「一次能答对」还是「需要多步推理 + 自我调整」？
  2. O1 范式的基础是 RL——模型在回答过程中通过试错学会更好的推理路径
  3. 关注新 scaling law：O1 的 scaling 不是增加数据/参数 → 是增加推理步数和搜索宽度
- **局限性**：O1 范式目前主要在数学、代码等有客观 ground truth 的领域有效。在创作、情感交流、商业判断等主观场景——"什么是更聪明的推理"本身就很难定义 reward。他的分析基于 OpenAI 的成果，但 OpenAI 如何做到的不完全公开——他的解读有推测成分

### 模型3：Diversity-Driven RL——人生不能只走最优化策略

- **一句话**：传统 RL 容易找到最高效的策略就反复使用，但人生需要 diversity——需要「diversity-driven reinforcement learning」，在可承受范围内追求高熵生活
- **来源**：[[42章经]] 039 [归纳]
- **怎么用**：
  1. 自我审视：你现在走的是「最大化某种已知 reward」的策略吗？
  2. 如果是——你失去了探索更高 reward 路径的可能（local optima trap）
  3. 跳出方法：在可承受范围内做探索——大不了再跳回来。人生怎么也能选三四次
  4. 实证基础：他的研究兴趣从纯 RL→泛化性→多智能体→今天就开源的 AReaL 框架——他自己的职业路径就在践行 diversity-driven
- **局限性**：diversity-driven RL 在今天还是一个学术概念，不是一套成熟方法。在生活中「追求多样性」的前提是你能承受探索的财务和时间成本——对学生 or 有家庭负担的人，这个框架可能过于 Idealistic。他的学生身份 vs 教授身份本身就在不同的人生阶段有不同的风险耐受力

## 决策启发式

1. **预训练 × RL = 智能**：不能只评价预训练能力或只评价决策能力——两者乘积决定天花板 — [[42章经]] 039
2. **RLHF 让模型好用，O1 让模型聪明**：两者不一样，对应不同的 AI 价值 — [[42章经]] 039
3. **强化学习里基建远大于所有**：没有屠龙刀（快速迭代的 RL 基建），算法想法很难真正 scale — [[42章经]] 039
4. **跳出 local optimal，大不了再跳回来**：人生怎么也能选三四次 — [[42章经]] 039
5. **创业公司不能只想终局——如果终局已经到来，就没有你的机会** — [[42章经]] 039

## 内在张力 / 盲区

1. **OpenAI inside 视角的盲区**：他在 OpenAI 工作过，对这个组织有 insider 视角但也可能存在 insider 的情感附着。他对 O1 范式的分析来自对前同事工作的理解，但可能美化了 OpenAI 的技术路线
2. **学者视角 vs 创业者视角**：他是教授而不是创业者——他对「预训练 × RL」的框架是学术级的简洁优美，但工程化落地和商业化的难度被简化了
3. **Diversity-Driven 的矛盾**：他倡导人生追求多样性——但他自己的路径（伯克利 PhD → OpenAI → 清华教授）是典型学术精英的安全路径。他走的不算高熵
