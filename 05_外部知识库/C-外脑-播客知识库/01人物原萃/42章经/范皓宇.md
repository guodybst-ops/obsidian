# 范皓宇

> 基于 42章经 051 集提炼。不是语录合集，是可调用的思维框架。

## 画像

- **身份**：理想汽车 SVP，自称"原教旨主义产品经理"
- **背景**：大学学工业设计，跨界做过功能机、游戏、自媒体、操作系统、用户体验设计，最终进入汽车领域。认为一切产品的底层逻辑都指向同一件事：观察世界、组织资源、创造体验
- **标签**：原教旨主义产品经理 / 跨界产品人 / 观察-压缩设计法 / 实用主义理想主义者

## 擅长 & 不擅长

- **擅长**：从跨领域的底层共通性理解产品设计本质；平衡功能、情感和成本的多约束决策；将复杂内容压缩为可被用户理解和使用的最优解
- **不擅长**：纯技术驱动的产品判断（他是设计背景，不是技术背景）；数据驱动的增长和运营（他认为数据是拐杖）；数据不足——仅一集播客，未涉及失败产品复盘和团队管理

## 核心心智模型

### 模型1：观察-压缩设计法

- **一句话**：无论做什么产品，底层都是三件事：观察真实的素材（用户、生活、环境）、理解元素之间的关系、把复杂内容压缩为可被用户理解和使用的"最优解"。产品人的第一步永远不是列需求，而是打开眼睛观察真实世界。
- **来源**：[[42章经]] 051 — 用大学指纹识别仪设计案例展开 [归纳]
- **怎么用**：
  1. 接到产品需求时，先不写 PRD，先去观察用户的实际生活场景和痛点
  2. 问：除了完成功能，有没有什么东西可以被"压缩"进去，让产品更有趣、更贴近用户生活？
  3. 用他的指纹识别仪案例自检：你设计的产品除了完成功能，有没有什么东西让用户愿意"把玩"？
  4. 不是用户调研驱动，是假设驱动——先有创作者假设，再用观察验证和调优
- **局限性**："观察真实世界"依赖产品经理的感性能力和审美判断，不是一个可标准化、可传授的方法论。不同的人观察同一个场景可能得出完全不同的洞察。这个方法对有设计背景的人天然友好，对工程或数据背景的产品经理可能难以执行。此外，在数据密集的产品（如推荐系统、搜索引擎）中，"观察"不如"实验"有效。

### 模型2：有用 × 有趣 二维张力

- **一句话**：有用是敲门砖——没有用就没有被选择的入口。有趣是时间轴——只有有用没有趣，会被更便宜的替代品卷走。产品的长期价值在于有用且有趣，让用户产生连接和信任。
- **来源**：[[42章经]] 051 — 核心主张，用打火机、扇子、电脑贴纸等日常物件展开 [归纳]
- **怎么用**：
  1. 评估一个产品：它在有用维度得分多少（解决实际问题的效率）？在有趣维度得分多少（让人想靠近、把玩、自定义）？
  2. 有用不足：先补功能，否则产品进不了用户的选择集
  3. 有趣不足：寻找能让用户自发"靠近"产品的东西——不是加一个独立的"情绪价值模块"，而是让产品本身变得让人想互动的
  4. 红线：有趣不是外部硬塞的，是人和物靠近之后自然生成的。如果你的"有趣"是策划出来的，用户能感觉到
- **局限性**：不是所有产品都需要"有趣"——工业设备、医疗器材、基础设施软件的"有趣"不一定是竞争优势。这个框架偏向消费品和用户体验驱动的产品，对 B2B 基础设施和纯功能型产品的适用性有限。在价格敏感的竞争环境中，"有用且有趣"可能被"更便宜的有用"淘汰——成本约束是他的框架中较少讨论的部分。

### 模型3：实用主义理想主义的统一

- **一句话**：如果你不是一个实用主义者，就不配做理想主义者。商业产品必须考虑成本、销量、收益，但同时也要考虑它是否有意义、是否能长期与用户共鸣。产品设计的本质就是"既要又要也要"——既要成本低、又要体验好；既要技术发挥到最大、又要让用户觉得简单。
- **来源**：[[42章经]] 051 — 核心信念，"既要又要也要" [归纳]
- **怎么用**：
  1. 做产品决策时，列出所有约束（成本、技术可行性、用户体验、品牌定位、时间）
  2. 不要在任何一个维度上自我设限——先问"如果要同时满足这些矛盾的要求，方案长什么样"
  3. 意志力 = 现实与想象中美好世界之间的张力。用意志力把 imagined world 拉到现实中
  4. 判断序列：每一次选择后都有反馈，连续判断拉成序列。这个序列决定了你是谁，也决定了产品最终变成什么样
- **局限性**："既要又要也要"在理论上是多约束优化问题——可以求解。但在现实中，资源、时间和人力的有限性意味着必须做取舍。他没有给出"哪些约束可以松弛、哪些绝对不能碰"的具体框架。理想汽车作为一个高客单价产品（汽车）天然有更多的成本空间去同时满足多种约束——但在低毛利行业中（如消费品、电商），约束空间要小得多。这个框架可能过度受汽车行业的利润结构和多约束天然可解的影响。

## 决策启发式

1. **先观察再定义**：产品第一步不是写需求，是观察用户在真实场景中的行为 — [[42章经]] 051
2. **有用是敲门砖，有趣是护城河**：功能可以被复制，但人和物之间的"把玩"关系很难被复制 — [[42章经]] 051
3. **数据是拐杖，走路靠自己**：数据是事后验证工具，不是事前判断工具。真正有经验的产品人能像厨师一样凭感觉判断"不对" — [[42章经]] 051
4. **既要又要也要**：产品设计的价值就在于同时满足多组矛盾的约束。不要因为难就提前放弃某一边 — [[42章经]] 051
5. **判断序列决定产品**：不是某一个关键决策定义了产品，是一连串小判断的累积方向 — [[42章经]] 051
6. **想象力的匮乏是真正的匮乏**：解决用户没说出口的需求，需要的不只是数据，是想象力 — [[42章经]] 051

## 内在张力 / 盲区

1. **数据与直觉的矛盾未解**：他说"数据是拐杖"，但也承认"数据和指标也在用"。两者的真正关系他没有系统解决——什么时候相信直觉、什么时候依赖数据？他只说"好的产品人凭感觉发现问题再用数据验证"，但"什么时候感觉是对的、什么时候感觉是偏见"没有判断方法。
2. **汽车行业的特殊性**：他的所有产品理念都受到汽车行业的强影响——汽车是高客单价、长决策周期、强体验驱动的产品。他的框架在面对快消、SaaS、社交媒体等不同产品类型时，可能需要大幅调整。他本人承认"一线城市很多需求已过度满足"，但对自己作为服务高客单价市场的产品经理的偏见没有讨论。
3. **信息源密度**：仅一集播客。讨论全部集中在产品设计哲学层面。作为一个带领大型产品团队的 SVP，没有涉及团队管理、组织冲突、失败项目复盘。对于一个强调"既要又要也要"的产品人，他如何在组织内实际推动这种多约束决策，没有具体展开。
4. **利益立场**：作为理想汽车 SVP，他对"产品力"的叙事直接服务于公司品牌和竞争定位。
