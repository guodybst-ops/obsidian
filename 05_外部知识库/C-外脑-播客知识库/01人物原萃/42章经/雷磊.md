## 核心心智模型

### 模型1：反馈信号驱动设计

- **一句话**：为 Agent 设计系统时，最重要的不是规定每一步怎么做，而是设计最后的结果反馈信号。让 Agent 自己从真实世界的结果中学习，而不是被人类对中间行为的主观评价所限制。
- **来源**：[[42章经]] 044 — 用 AlphaProof 和川菜菜谱两组类比展开 [归纳]
- **怎么用**：
  1. 定义你要 Agent 完成的目标（最终结果而非中间过程）
  2. 设计反馈信号：Agent 的某个行为是否让目标更近了？反馈必须来自真实结果（菜好不好吃），而非人类评价（大厨说好不好吃）
  3. 让 Agent 在反馈循环中自己探索最优路径，不要人为规定每一步
  4. 自检：你在设计的系统是在约束 Agent 的行为，还是在给 Agent 清晰的结果反馈？
- **局限性**：真实结果的反馈信号在很多场景下并不清晰或无法自动获取。做菜容易（好吃/难吃是客观的），但产品策略、投资决策、人际沟通的"结果"可能需要数年才能显现，甚至永远没有确定答案。在反馈延迟长的场景中，仅靠结果反馈可能导致 Agent 学错规律。此外，完全依赖结果反馈可能让 Agent 在过程中做出不可接受的行为。

### 模型2：Agent 与 SaaS 的本质二分

- **一句话**：Agent 交付的是结果，SaaS 是给人用的工具。给人设计软件和给 Agent 设计软件应从完全不同的出发点开始。
- **来源**：[[42章经]] 044 — 贯穿全集的核心区分 [归纳]
- **怎么用**：
  1. 区分你在建的到底是给人用的工具还是给 Agent 用的环境——问：最终用户是点击按钮的人，还是一个自动完成任务的 Agent？
  2. 如果是 Agent 环境：云端化 + 安全隔离 + 并行执行能力 + 结果反馈信号
  3. 如果是 SaaS：易用性 + 操作流程 + 权限管理 + 人类学习成本
  4. 人类执行像贪婪算法（串行优化），Agent 可以并行探索全局最优——不要用人的执行逻辑去设计 Agent 的执行路径
- **局限性**：二分法在极端清晰时才成立，但现实中很多产品是过渡形态——既有 Agent 交付结果的部分，又有人工介入和微调的入口。二分法在早期阶段可能过度简化了产品设计。此外，这个区分的前提是 Agent 能力足够强到可以自主交付结果，但当前大部分 Agent 的实际可靠性还达不到这个标准。

### 模型3：AI 创新四阶段

- **一句话**：AI 发展从聊天→推理→Agent→创新，到了创新阶段 AI 可能从真实世界反馈中产生人类未想到的结果，而不只是逼近人类专家的偏见。
- **来源**：[[42章经]] 044 — 用川菜菜谱的类比展开 [归纳]
- **怎么用**：
  1. 判断你关注的产品/公司处于四阶段中的哪一阶段
  2. 如果还在"推理"或"Agent"阶段，核心矛盾是可靠性和工程化
  3. 如果目标是"创新"，必须建立 AI 从真实世界直接获取反馈的机制（不是从人类标注数据中学习）
  4. 关注自身行业中有哪些环节可以跳过"逼近专家"直接进入"真实世界反馈"
- **局限性**：这是方向性推演而非已验证路径。当前 AI 尚未稳定到达 Agent 阶段，创新阶段更是假设。在非技术领域（如法律、医疗），真实世界反馈代价极高，不可逆转的错误可能先于创新发生。这个四阶段模型可能低估了每个阶段之间的鸿沟宽度。

## 决策启发式

1. **先问是人用还是 Agent 用**：出发点错了全盘错。SaaS 设计从人开始，Agent Infra 设计从 Agent 开始 — [[42章经]] 044
2. **设计反馈信号而非流程**：不要规定 Agent 每一步做什么，要定义"什么叫做好"，让 Agent 自己找到路径 — [[42章经]] 044
3. **安全不是标签，是边界**：Agent 的安全重点在于把影响控制在可接受范围内（沙盒、权限、隔离），而不是一个抽象的"安全"声明 — [[42章经]] 044
4. **AI 从真实世界学，不从人类偏见学**：如果只让 AI 逼近专家判断，结果不会超越专家。真正突破来自让 AI 直接面对结果反馈 — [[42章经]] 044

## 内在张力 / 盲区

1. **创业者身份与推演性思考的张力**：他的框架偏远期推演和概念区分，但创业需要马上落地的产品。从"设计反馈信号"的理论到具体产品中如何实现这个反馈信号，中间有一段空白。
2. **Agent Infra 的定位竞争**：他承认 AI 环境是 AWS 级机会，但也承认云厂商可能吃掉大部分。他选择的路径（合并 runtime + agentic 层）是否能抵御云厂商的降维打击，没有展开讨论。
3. **信息源密度**：仅一集播客，且他的公司 Grasp 处于早期阶段。所有框架都来自"他相信"而非"他验证过"。没有失败案例分析。
4. **利益立场**：作为 Agent Infra 创业者，他对 Agent 时代必然到来的叙事有直接的商业利益。
