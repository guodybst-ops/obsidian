# 虞快

> 基于 42章经 049 集提炼。不是语录合集，是可调用的思维框架。

## 画像

- **身份**：Mercor 首位中国员工，工程管理
- **背景**：学计算机和数学，毕业后在 Google 做软件工程师，之后去 Two Sigma 和 Citadel 做 trading 工程，后来回到湾区加入 Mercor
- **标签**：硅谷工程师 / 高速增长见证者 / Agency 信仰者 / 人才观察家

## 擅长 & 不擅长

- **擅长**：判断高速增长公司的组织特质；硅谷式工程招聘和人才评估标准；AI Lab 对专家数据服务的需求分析
- **不擅长**：从零到一的创业方法论（他是在公司已有产品和增长后加入的）；中国市场的人才和市场判断；数据不足——仅一集播客，未涉及管理失败案例和团队冲突

## 核心心智模型

### 模型1：Agency 驱动的人才筛选

- **一句话**：招聘时最看重的是 Agency——主动发现问题、独立探索方案、克服阻力把结果拿出来的能力。给了方向后，需要告诉你每一步做什么还是能自己走很远，是区分高价值工程师和普通工程师的核心信号。
- **来源**：[[42章经]] 049 — 用 parking function 面试题和多个实例展开 [归纳]
- **怎么用**：
  1. 面试时观察自主性：给候选人一个任务，看需要描述到什么程度，能独立运行多久
  2. 用 parking function 这样的题：观察候选人是陷入模拟还是跳出来思考本质规律
  3. 给简单题看沟通行为：忘了知识点不可怕——不沟通、不求助、自己硬磕才可怕
  4. 评估已有团队：每个人是"等待指示"型还是"主动推动"型？前者需要更多管理投入，后者释放管理精力
- **局限性**：Agency 高度依赖于工作环境——优秀的自驱者在糟糕的环境中可能表现为消极。不沟通也可能是"环境让不沟通比沟通更安全"。他的面试案例（parking function、简单题）来自硅谷高密度技术公司的招聘场景——对非技术岗位或不同文化背景的公司，这些题目可能无法有效测量 Agency。用一两个面试题判断 Agency 本身有误判风险。

### 模型2：数据标注到 evaluation provider 的跃迁

- **一句话**：随着模型能力提升，传统"数据标注"已经不够。模型已经会做普通人会做的事，新的瓶颈是"模型做不到的、需要专家才能判断的事"。因此一流 AI 数据公司的定位不是标注公司，而是 evaluation provider——帮 AI Lab 定义模型应该完成什么任务。
- **来源**：[[42章经]] 049 — 核心业务定位论述，"evaluation 是模型的 PRD" [归纳]
- **怎么用**：
  1. 判断一家 AI 数据公司的真正价值：它在做基础标注还是在做专家评估？前者可自动化，后者随模型能力提升而需求上升
  2. 如果自己做模型：评估环节需要引入真正的领域专家来定义"什么是好"。普通标注者的判断已经没有信息增量
  3. 跟踪信号：当某类标注任务被基础模型自身完成时，这个方向的数据标注价值归零
- **局限性**：专家数据的供给有天然上限——能做专家评估的人本身就是稀缺的。随着模型能力提升，能作为"专家"的门槛越来越高，最终可能出现"没有足够多的人能评估模型"的悖论。他的框架依赖"专家永远比模型强"，但这个假设可能在垂直领域不成立。另外，他描述的 Mercor 路径依赖极高的人才密度和高速增长——这个模式是否可以被其他公司复制，他没有讨论。

### 模型3：快速增长的组织飞轮

- **一句话**：快速增长靠三个相互咬合的因素：决策快（不依赖漫长数据分析，依赖高质量直觉）、执行快（说到做到）、反馈快（做什么都很快看到结果）。速度本身会让人上瘾——因为反馈周期短，团队有持续的正向激励，能自发维持高强度。
- **来源**：[[42章经]] 049 — 从 Mercor 11 个月从 100 万到 1 亿 run rate 的观察 [归纳]
- **怎么用**：
  1. 自检决策速度：团队做一个重要决定的平均周期是多长？依赖多少层数据验证？
  2. 自检执行速度：团队"说到做到"的比例是多少？做不到时是否快速调整？
  3. 设计短反馈循环：一周内能做成什么、能看到什么结果？把长周期任务拆成多个短周期里程碑
  4. 招聘时明确告知高强度期望，确保加入者不是被动接受而是主动选择
- **局限性**：高速度决策的代价是更高频率的错误。"不要大错特错，快速发现改掉"的前提是错误可逆——但有些错误（如招聘了错误的关键人才、签了错误的大客户合同）是不可逆的。速度飞轮对正在扩张的产品市场匹配（PMF）阶段的公司有效，但对需要战略调整或收缩的公司可能是火上浇油。此外，22 岁平均年龄的高强度文化是否可持续——生理年龄和家庭结构变化后，这套逻辑还能走多远——他没有讨论。

## 决策启发式

1. **招 Agency 而不是招技能**：技能可以通过 AI 补，但没有自主推动力的工程师在 AI 时代是最先被淘汰的 — [[42章经]] 049
2. **评估先于训练**：模型能力越强，评估模型的专家门槛越高。未来的 AI 数据公司不是标注公司，是 evaluation 公司 — [[42章经]] 049
3. **说到做对比决策正确更重要**：高增长环境下，执行力最难被复制。决策可以改，执行失信会破坏团队信任 — [[42章经]] 049
4. **工程师时间重新分配**：生成代码的时间减少，判断方向、理解客户、提出方案的时间应该增加 — [[42章经]] 049
5. **崩溃比沉默好**：面试中候选人忘了知识点但主动沟通，比默默卡住强一百倍 — [[42章经]] 049

## 内在张力 / 盲区

1. **高强度的可持续性**：他描述的文化是年轻、单身、没家庭负担的人可以承受的。但 Mercor 的创始团队和员工平均年龄 22 岁——没有人知道五年后这套文化是否还能运转。
2. **速度至上的反噬风险**：他坦承"决策快不代表每个决策都对"，但这个框架中"发现错误-改掉"的修正成本没有被量化。在 mercor 的招聘和评估业务中，一个错误决策的修正成本可能相对低（可以换人/换模型），但如果把这个方法迁移到硬件、生物医药等领域，速度优先可能致命。
3. **信息源密度**：仅一集播客，且他加入 Mercor 只有几个月时间。所有观察都基于极短的窗口期，缺少对一个组织经历完整周期（低谷、裁员、竞争失败）的反思。
4. **利益立场**：作为 Mercor 员工，他对公司业务定位和增长叙事有组织身份认同，可能倾向于描述更积极的画面。
