# [SOP] 055-播客社群线下活动策划复盘流程

## 一句话（≤ 40 字）
把播客听众聚会做成可复用线下 IP。

## 什么时候用（触发条件，3-5 条 bullet）
- 播客、社群或个人 IP 准备办线下听友会、周年活动、策展或市集。
- 需要把内容影响力转化成真实连接和现场体验。
- 活动预算、人手、时间有限，必须取舍范围。
- 活动结束后要沉淀为下一次可复用的流程。
- **红线**：不要同时硬塞分享会、策展、市集、招商、直播和大量摊主，超出团队承载就必须砍。

## 输入（做之前要准备的东西）
- 活动目的：庆典、复盘、社群连接、招商样板、内容共创或商业转化。
- 已有资产：节目数据、听众故事、嘉宾资源、品牌方、场地方、设计师、摄影摄像。
- 约束：日期、城市、预算、人手、场地面积、室内外条件、赞助资源。
- 现场模块备选：论坛、策展、书单、心愿墙、通讯录、摊主、市集、拍照点。
- 复盘素材：照片、视频、票务、签到、人员分工、预算、事故记录、用户反馈。

## 输出（做完得到什么）
- 一份活动策划案和执行清单。
- 一张团队分工表和现场动线表。
- 一份活动复盘报告：做成了什么、没做到什么、下次怎么改。
- 一个可延续的活动 IP 节点。

## 主流程（核心，占篇幅 ≥ 60%）

### Step 1: 定义活动目的和固定节点
- 写清这场活动是为了庆祝、连接、变现、品牌样板，还是年度复盘。
- 选择一个可重复的日期或主题，让活动有长期记忆点。
- 做完信号：能用一句话说清“为什么非办不可”。

### Step 2: 选择可托底的城市和场地
- 优先选团队资源、人脉、供应链和应急能力最强的城市。
- 场地要匹配主题、天气、动线、视觉和预算。
- 做完信号：即使出问题，也有人能立刻补位。

### Step 3: 砍掉超载模块
- 把所有想法列成清单，按“必要、加分、明年再做”分级。
- 时间不足时，优先保证主体验和可留痕模块。
- 做完信号：团队知道这次不做什么。

### Step 4: 设计现场内容结构
- 至少设置一个内容主轴：论坛、展览、故事墙、书单、心愿或社群匹配。
- 每个模块都要对应一个用户动作：听、看、写、拍、聊、买、报名。
- 做完信号：用户不是只来旁观，而是能参与。

### Step 5: 明确团队角色和外部合作
- 拆出策展、文案、设计、摄影、后勤、检票、嘉宾、直播、志愿者、商务。
- 外部合作方写清资源交换、露出权益、交付物和截止时间。
- 做完信号：每个现场问题都知道找谁。

### Step 6: 预埋传播和视觉留痕
- 提前设计拍照点、展板、主视觉、视频素材和用户可发朋友圈的瞬间。
- 安排摄影摄像覆盖入场、主舞台、互动区、合影和撤展。
- 做完信号：活动结束后有足够素材证明现场发生过什么。

### Step 7: 活动后复盘和续约下一次
- 复盘数据、预算、用户反馈、团队消耗、没完成项和可商业化项。
- 当场记录下一届可提前招募的品牌方、摊主、内容团队和志愿者。
- 做完信号：不是“办完就散”，而是进入下一次筹备。

## 判断点 / 决策树（如有分支）

```text
如果预算有限 → 优先内容体验和视觉留痕，招商放下一届
如果团队少于 5 人 → 不同时做大型论坛和复杂市集
如果场地很大 → 用展板、书单、故事墙和互动区填充，不靠临时摆设
如果时间少于 1 个月 → 只做最小可完成版本
如果活动想长期化 → 先固定日期、命名和复盘机制
如果用户要摆摊或共创 → 必须提前招募专人负责摊主沟通
```

## 常见坑（3-5 条硬红线）
- 不要为了“显得丰富”把团队能力外的模块全塞进去。
- 不要只重现场，不留照片、视频和可传播素材。
- 不要把志愿者和核心负责人混用，关键岗位必须有人兜底。
- 不要临时招摊主，摊主沟通、用电、物料、动线都会放大复杂度。
- 不要只复盘成功，也要记录砍掉的模块和没做到的原因。

## 附录：实例（1 个跑通的例子，与主流程分开）

一个播客周年活动原本想做大型市集、分享会、策展和多城市联动。临近落地时，团队发现时间不足、预算有限、人手有限，于是把城市固定在资源最强的大本营，场地选择室内大型文化空间；本届先保留论坛、策展、书单、心愿、通讯录和视觉留痕，砍掉对接大量 To C 摊主的模块。活动后复盘出下一届可提前招募品牌方、摊主和合作团队，并把固定日期沉淀成年度 IP。
