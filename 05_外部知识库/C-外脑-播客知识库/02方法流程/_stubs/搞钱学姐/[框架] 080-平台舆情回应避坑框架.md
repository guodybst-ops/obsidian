# [框架] 080-平台舆情回应避坑框架

## 一句话（≤ 40 字）
用六维检查平台回应会不会越描越黑。

## 什么时候用（触发条件，3-5 条 bullet）
- 平台、品牌、社区或内容产品出现用户集体不满。
- 运营公告、审核、删改、收费、开票、封禁等动作引发舆情。
- 团队准备发道歉、说明、律师函或二次公告。
- 需要判断“该说什么、先做什么、哪些话不能说”。
- **红线**：不适用于事实未查清就急着甩锅、威胁用户或制造对立。

## 评估对象（这个框架用来打分的是什么）
- 评估对象：一次平台舆情回应方案。
- 颗粒度：一份公告、一条高管回应、一套补救动作或一份律师函。
- 目标：判断回应是“可发、先改、先做事、不应发”。

## 维度定义（框架的骨）

### 维度 1：用户情绪——是否承认用户真实痛点

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 先识别用户为什么痛 | 把用户行动说成无理取闹 |
| 知道核心用户是谁 | 吃核心用户红利，却轻视其感受 |
| 避免嘲讽、阴阳怪气、标签化 | 用玩笑、黑话或轻慢态度回应 |

→ **怎么问出来 / 怎么观察出来**：问“这份回应有没有让用户感觉自己被看见？”

### 维度 2：事实责任——是否说清发生了什么和谁负责

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 时间线、操作原因、责任边界清楚 | 偷偷改公告、反复改口 |
| 承认平台应承担的责任 | 把责任全推给用户、系统或基层 |
| 解释简短且可验证 | 长篇解释像找借口 |

→ **怎么问出来 / 怎么观察出来**：问“用户能不能看懂到底错在哪里？”

### 维度 3：回应姿态——是为解决问题，还是为回应而回应

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 该道歉时直接道歉 | 为道歉而道歉，后面全是辩解 |
| 语气克制、具体、承担责任 | 高管个人情绪上头 |
| 不和用户争输赢 | 把回应写成辩论稿 |

→ **怎么问出来 / 怎么观察出来**：问“这份回应是在安抚用户，还是在证明自己没错？”

### 维度 4：行为补救——有没有先做能改变局面的动作

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 立即修复流程、开放入口、加速处理 | 只说抱歉，没有行动 |
| 给出时间表和负责人 | 用“后续优化”糊过去 |
| 补偿或替代方案与用户损失相关 | 补救动作和痛点无关 |

→ **怎么问出来 / 怎么观察出来**：问“用户明天会看到什么变化？”

### 维度 5：法律动作——是否避免把舆情再次升温

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 只有必要时才使用法律手段 | 一上来发律师函吓用户 |
| 法律动作和事实证据匹配 | 用法律话术掩盖态度问题 |
| 先判断舆情效果 | 维权姿态导致二次传播 |

→ **怎么问出来 / 怎么观察出来**：问“这一步会降温，还是让更多人围观？”

### 维度 6：组织价值观——管理层是否理解核心用户

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 决策层理解核心用户和消费场景 | 用户结构和管理层认知错位 |
| 内部先统一价值观再发声 | 认知跟不上，越道歉越暴露问题 |
| 长期产品机制匹配用户尊重 | 只在舆情时临时补话术 |

→ **怎么问出来 / 怎么观察出来**：问“这次问题是单点失误，还是价值观长期错位？”

## 打分卡 / 分级表（可复制粘贴）

| 维度 | 0 分：高危 | 1 分：薄弱 | 2 分：可改 | 3 分：可发 | 当前分 | 证据 |
|---|---|---|---|---|---:|---|
| 用户情绪 | 嘲讽/轻视 | 未识别痛点 | 基本承认 | 充分看见 |  |  |
| 事实责任 | 偷改/甩锅 | 模糊 | 基本清楚 | 清晰承担 |  |  |
| 回应姿态 | 争辩 | 道歉夹解释 | 克制 | 真诚直接 |  |  |
| 行为补救 | 无动作 | 动作空 | 有时间表 | 立刻改变 |  |  |
| 法律动作 | 升温 | 过重 | 谨慎 | 必要且克制 |  |  |
| 组织价值观 | 严重错位 | 认知不足 | 可修正 | 与用户一致 |  |  |

分级：
- **A 级（15-18 分）**：可发，配套同步执行补救动作。
- **B 级（10-14 分）**：先改稿，补齐事实、动作和语气。
- **C 级（0-9 分）**：不要发，先停下错误动作、查事实、做补救。

## 打完分怎么用（决策后果）

- 用户情绪低分：先做用户访谈或舆情复盘，不要急发公告。
- 事实责任低分：先查时间线和责任边界。
- 回应姿态低分：删掉辩解、嘲讽、甩锅和高高在上的表达。
- 行为补救低分：先做事，再说话。
- 法律动作低分：暂缓律师函，重新评估是否会二次升温。
- 组织价值观低分：不要让认知错位的人单独发声。

## 常见坑（3-5 条）
- ❌ 不要偷偷改公告，用户会比对。
- ❌ 不要把用户维权说成攻击或闹事。
- ❌ 不要在道歉后面接一长串“但是”。
- ❌ 不要用律师函替代事实说明和行为补救。
- ❌ 不要让不了解核心用户的人代表平台发情绪化回应。

## 附录：实例（1 个跑通的例子）

一个女性用户占多数的平台因审核和公告引发集体投诉，用户开始用合规方式集中要求平台履行义务。初版回应把用户行为轻描淡写为“麻烦”，还反复修改公告，打分只有 6 分。按框架修正后，平台先停止争辩，公开时间线，承认流程设计不友好，立即开放入口并给出处理排期；高管不再个人化发声，法律动作只保留给明确造谣和攻击。修正后重点从“证明平台没错”变成“让用户看到改变”。
