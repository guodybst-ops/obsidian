# [框架] 077-OpenClaw养虾适配评估框架

## 一句话（≤ 40 字）
评估你是否适合把 OpenClaw 养成助理。

## 什么时候用（触发条件，3-5 条 bullet）
- 看到 OpenClaw、Agent、本地部署工具爆火，想判断要不要跟。
- 想把 AI 变成长期助理，而不只是聊天工具。
- 有多个账号、客户、资料、代码、运营或自动化任务。
- 想借热点做部署、维修、资料包、Skills 或 B 端服务。
- **红线**：不适用于完全不愿碰技术、没有明确任务、只想追热点的人。

## 评估对象（这个框架用来打分的是什么）
- 评估对象：一个人、团队或项目是否适合投入 OpenClaw 类 Agent 工具。
- 颗粒度：以具体任务组合为单位，不评估抽象的“我要不要学 AI”。
- 目标：判断是立刻养、轻量试、外包安装，还是暂时不跟。

## 维度定义（框架的骨）

### 维度 1：任务相关性——它是否影响你的赚钱或效率

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 有持续重复任务可交给 Agent | 只是想知道新工具是什么 |
| 任务影响赚钱、客户交付或时间效率 | 不影响生活，也不影响赚钱 |
| 能说清“用它干什么” | 只问“该安装什么 Skill” |

→ **怎么问出来 / 怎么观察出来**：问“如果不懂这个工具，我的收入、交付或效率会受影响吗？”

### 维度 2：技术承受度——能否处理安装、调试和报错

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 愿意安装、部署、调试、查问题 | 看到代码、权限、远程控制就恐惧 |
| 能接受前期踩坑 | 一次报错就放弃 |
| 会做基础备份和权限检查 | 让陌生人随意远程电脑 |

→ **怎么问出来 / 怎么观察出来**：问“我能否独立完成一次安装或找到可靠协助？”

### 维度 3：成本替代——是否能替代人力或外包

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 能替代部分实习生、助理或运营任务 | 工具成本高于可替代成本 |
| Token、设备、服务器成本可控 | 为了尝鲜买设备，任务却很少 |
| 多账号、多客户、多区域能形成规模效应 | 只有一次性小任务 |

→ **怎么问出来 / 怎么观察出来**：问“它每月能省下多少人力时间或外包费用？”

### 维度 4：使用场景清晰度——能否定义 Agent 角色

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 每只 Agent 有明确岗位和任务边界 | 一个 Agent 什么都想做 |
| 知道需要哪些 Skills、记忆和工具 | 只装热门插件 |
| 能用通讯工具稳定下指令 | 指令含糊，反复返工 |

→ **怎么问出来 / 怎么观察出来**：问“这个 Agent 的岗位说明书是什么？”

### 维度 5：变现路径——能否把热点转成收入

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 能做一键部署、资料包、维修、Skills、B 端定制 | 只会消费教程，不会服务别人 |
| 目标客户明确：不会装、不会用、想省人力的人 | 不知道卖给谁 |
| 能把新工具换壳迁移到下一波热点 | 只押一个工具名 |

→ **怎么问出来 / 怎么观察出来**：问“别人在哪个环节不会，我能不能替他解决？”

### 维度 6：安全风险——是否能控制权限和信息泄露

**观测信号**：

| ✅ 好信号（这方面强） | ❌ 坏信号（这方面弱） |
|---|---|
| 敏感账号、客户资料、密钥有隔离 | 把所有权限交给一个工具 |
| 部署前做备份、权限、日志检查 | 不知道数据流向哪里 |
| 出事后能复盘并修补漏洞 | 被黑、泄露后继续裸奔 |

→ **怎么问出来 / 怎么观察出来**：问“它能接触哪些敏感资料，泄露后损失多大？”

## 打分卡 / 分级表（可复制粘贴）

| 维度 | 0 分：不适合 | 1 分：薄弱 | 2 分：可试 | 3 分：适合 | 当前分 | 证据 |
|---|---|---|---|---|---:|---|
| 任务相关性 | 无真实任务 | 任务弱 | 有部分任务 | 影响赚钱/效率 |  |  |
| 技术承受度 | 完全恐惧 | 依赖别人 | 可跟教程 | 能独立排错 |  |  |
| 成本替代 | 不省成本 | 成本不清 | 可省部分 | 明显替代人力 |  |  |
| 使用场景清晰 | 不知干嘛 | 场景泛 | 有岗位雏形 | 岗位清晰 |  |  |
| 变现路径 | 不知道卖谁 | 只消费 | 有服务雏形 | 可收费 |  |  |
| 安全风险 | 裸奔 | 风险高 | 有基础隔离 | 权限清楚 |  |  |

分级：
- **A 级（15-18 分）**：适合投入，先做 1 只核心 Agent，再扩多 Agent。
- **B 级（10-14 分）**：适合轻量试，用低权限、低成本方式跑一个任务。
- **C 级（0-9 分）**：暂时不跟，先补任务定义、技术基础或安全边界。

## 打完分怎么用（决策后果）

- 任务相关性低：不必追热点，先找真实业务问题。
- 技术承受度低：选择一键部署或找可信服务商，但不要交出敏感权限。
- 成本替代低：先不买设备，用轻量工具试流程。
- 变现路径高但技术低：可以做资料整理、需求撮合或低风险服务。
- 安全风险低于 2 分：暂停部署，先做权限隔离和备份。

## 常见坑（3-5 条）
- ❌ 不要因为爆火就养，先问它影响不影响你的赚钱。
- ❌ 不要把“装上了”当成“能用了”，关键是任务和角色。
- ❌ 不要把敏感账号、客户资料、密钥无边界交给工具。
- ❌ 不要每个热点都重头学，重点是迁移底层商业思路。
- ❌ 不要用 Agent 做比自己 30 分钟能完成还差的任务。

## 附录：实例（1 个跑通的例子）

一个海外内容运营者有多个账号、客户资料和重复发布任务。打分：任务相关性 3，技术承受度 2，成本替代 3，使用场景 2，变现路径 2，安全风险 1，总分 13。结论：可以轻量试，但先不让 Agent 接触客户核心账号；先把“资料整理”和“内容初稿”作为低权限任务，补好备份和密钥隔离后，再扩到多账号运营。
