# 大模型应用开发三层法

## 一句话

大模型应用开发从易到难分三层：Prompt 工程（最轻量）→ Embedding（私有知识嵌入）→ Fine-tuning（改变模型风格）。大多数应用不应一上来就微调，而应先判断前两层是否够用。

## 怎么用

### Step 1：先做 Prompt 工程
- 给模型指令、样例（one-shot/few-shot）、上下文控制输出
- Few-shot 能净提高回答符合预期的概率 20%-30%
- 需要持续迭代——跟模型"找感觉"，自嘲"Prompt 艺术家"
- 观测信号：模型输出是否符合预期风格和准确度？

→ 如果 Prompt 够用，停在这里。不够用，进入 Step 2。

### Step 2：加 Embedding（私有知识嵌入）
- 把私有知识以"外脑"方式嵌入 promp
- 本质是在调用大模型前做 prompt 组装——将用户问题与私有知识库中相关内容拼成完整 prompt
- 涉及工程细节：8K context 怎么分配（用户提问占多少、命中信息占多少、回答预留占多少）
- 用向量数据库做相似度匹配来找相关信息
- 观测信号：模型能否回答超出训练截止时间和公共知识范围的问题？

→ 如果 Embedding 够用，停在这里。如果必须改变模型默认风格/行为，进入 Step 3。

### Step 3：Fine-tuning（微调）
- 需要大量高质量 QA 样本（一个问题换花样问 20 遍，换花样回答 20 遍）
- 非常吃资源——本地部署需要运行推理模型 2-3 倍的机器配置
- 商业模型提供微调 API 可以降低门槛
- 适用场景：想要模型默认回答风格发生改变（比如写诗风格接近你想要的）
- **判定标准**：只有必须改变模型性格时才用微调，能省就省

## 完整示例

以教育场景为例推演：

一个 AI Tutor 应用：
1. Prompt 层：给模型设定"你是一个高中物理老师，用 Socratic 方法引导学生，不要直接给答案"，加上 few-shot 示例（一个好回答、一个坏回答）
2. Embedding 层：该学生的错题本、知识薄弱点、历史对话作为私有知识嵌入——每次对话前自动组装进 prompt
3. Fine-tuning 层：如果模型始终无法用合适的"高中老师语气"讲话，才考虑微调

大部分教育类 AI Tutor 产品只需要前两层。

## 适用场景与边界

**适用场景**：所有基于大模型 API 做应用开发的团队
**不适用场景**：只是把 AI 当单点功能嵌入的（比如加个"AI 润色"按钮）
**已知局限**：
- Prompt 工程需要大量人工迭代和测试，不是"一次写好就行"
- Embedding 的搜索精度决定效果上限——如果私有知识匹配不准，整个链路崩溃
- Fine-tuning 成本极高，对大部分应用开发者不划算
- 三层之间不是严格线性——有时需要两层配合
