# 分发容器选择法

## 一句话

为产品选择单列还是双列分发，不是一个 UI 问题，而是一个生态选择。单列（上滑全屏）追求消费效率和快速泛化，双列（封面平铺）追求社区公平和中长尾生态。

## 怎么用

### Step 1：回答三个问题

| 问题 | 偏单列的特征 | 偏双列的特征 |
|---|---|---|
| 你的内容消费目标？ | 追求单次消费时长/广告变现 | 追求用户互动/社区粘性 |
| 你的内容供给特征？ | 头部内容质量高，需要高效分发 | 中长尾内容重要，需要给新人机会 |
| 你的用户使用场景？ | 碎片时间、无脑消费、连续刷 | 有目的浏览、选择观看、互动导向 |

### Step 2：单列 vs 双列的生态影响对比

| 维度 | 单列（全屏上滑） | 双列（封面选择） |
|---|---|---|
| 消费效率 | 极高，无需选择 | 中等，需要用户选择 |
| 公平性 | 更容易推头部内容 | 中长尾创作者获得更多曝光 |
| 商业化 | 广告可自然插入 | 广告打断感更强 |
| 泛化能力 | 更容易泛化到新内容类型 | 泛化更依赖社区引导 |
| 适合内容 | 短视频、音乐、娱乐 | 图文、攻略、深度视频、社区讨论 |
| 代表产品 | 抖音、TikTok | 快手（早期）、小红书、B 站 |

### Step 3：关键警告——不要用 AB test 做这个决策

单列和双列影响的不是短期转化率，而是长期创作者生态和用户心智。短期 AB test 只能测消费行为变化，测不出：
- 新创作者是否愿意来你的平台
- 用户在 6 个月后是否还把平台当成社区
- 中长尾创作者是否有动力持续创作

### Step 4：平台成熟后的"泛化"策略

当你已经有一个成熟的分发容器后，平台可以做更多内容类型。有些题材在某个容器里表现更好：
- 深度 30 分钟视频 → B 站更适合（用户心智是"花时间看"）
- 图文攻略/笔记 → 小红书更适合（双列+图文）
- 迅速娱乐 → 抖音最适合（单列+短平快）

## 完整示例

以抖音 vs 快手的竞争为例：
1. **抖音选单列**：用户不需要选择，连续上滑即可，消费效率极高。用户无聊时打开抖音像点烟一样简单，最终把"无脑消费"做到数亿 DAU
2. **快手早期选双列**：用户先看封面再做选择，中长尾创作者更容易获得反馈。快手更像社区，但泛化效率和商业化效率始终低于抖音
3. **结果**：抖音用单列高效泛化打败了快手的双列社区，但小红书在图文领域用双列建立了新的护城河

## 适用场景与边界

- **适用**：内容平台、社交产品、短视频/直播产品的初期架构设计
- **不适用**：工具型产品、B2B 产品、电商产品（电商更关注商品流而非内容流）
- **已知局限**：框架来自内容消费领域经验，对交易类、工具类产品的适用性有限
