# RL+LLM组合Agent架构

## 一句话

Agent的决策架构：RL作为决策核心（评估路径、探索不确定性、选择最优action），LLM作为外部接口和抽象层（理解自然语言、表示API语义、输出人类可读结果）。两者不是平行竞争关系，而是互补的乘法关系。

## 怎么用

### Step 1：判断任务是否需要RL决策层

适合RL决策的场景特征：
- 可采取action数量很大
- 很多action的结果尚未充分观察
- 需要探索不确定性
- 当前action会影响后续action
- 优化目标不是单点结果，而是整体长期收益

不适合RL决策的场景：
- 单步预测问题（如分类、简单翻译）
- 结果已知且不需要探索
- action空间极小且全部已被定义

### Step 2：设计action空间

区分两类环境：
- **action被完整定义的环境**（如供应链调货、电商API操作）：RL直接调用预设action
- **action未完整定义的环境**（如解数学题、复杂推理）：LLM辅助生成中间步骤，RL用value评估路径质量

### Step 3：建立RL决策层

RL模型负责：
- 评估不同action和路径的成功概率
- 探索不确定性更高的路径（而非只走高概率路径）
- 当路径失败时判断应该回退到哪个节点
- 优化整体长期收益，而非单步结果

关键：RL模型可以很小（如1500万参数），关键是对action空间的决策效率。

### Step 4：LLM作为接口层

LLM负责：
- 理解自然语言需求→转化为state和action表示
- 将API文档和业务语义embedding化
- 辅助生成训练数据和评价结果质量
- 将RL的决策结果整理成人类可读的输出

### Step 5：联合训练与迭代

- LLM提供预训练理解能力（世界知识、语言、视觉表征）
- RL在此基础上学习如何与世界交互
- 小RL模型+小LLM配合可大幅降低推理成本（比单一超大模型低两个数量级）

## 完整示例

以Pokee AI的电商Agent推演：

```
用户需求："圣诞节要做促销"

Step 1 - LLM理解：
将自然语言转化为结构化目标：
- 目标actions：打折、改运费、调首页、发邮件、上线promo code
- 约束：圣诞主题、指定产品类别

Step 2 - RL决策：
评估多种执行路径：
- 路径A：先打折→调首页→发邮件→改运费（预期成功率85%）
- 路径B：先发邮件→改运费→打折→调首页（预期成功率72%）
- 路径C：并行执行所有action（预期成功率67%，但速度最快）

RL选择路径A，因为它在历史数据中成功率最高。

Step 3 - 执行与反馈：
Agent按路径A依次执行，通过API调用完成每个action。
如果某个action失败（如promo code冲突），RL自动回退重新规划。

Step 4 - LLM输出：
任务完成后，LLM将执行结果整理为：
"已完成圣诞促销设置：23款产品折扣已生效，运费模板已更新，
首页推荐已切换到圣诞主题，已向1200位老客户发送促销邮件。"
```

## 适用场景与边界

**适用场景**：
- API丰富的业务领域（电商、广告、金融、旅行等）
- 多步决策任务（供应链优化、行程规划、客服工单处理）
- 需要探索最优路径的场景（推荐系统、定价策略）

**局限性**：
- 需要action空间可定义——零散的、没有API的纯人工流程不适用
- RL的训练需要环境和反馈，不适合"一次性任务"场景
- 仅1个来源，来自Pokee AI的实践经验 [AI推理]
- 对工程基础设施要求高——需要训练框架、并行环境、奖励设计
