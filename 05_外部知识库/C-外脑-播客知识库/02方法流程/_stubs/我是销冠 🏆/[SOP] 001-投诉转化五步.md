# [SOP] 投诉转化五步

## 一句话（≤ 40 字）
把有效投诉转成关系修复和复购机会。

## 什么时候用（触发条件，3-5 条 bullet）

- 客户已经付费，并主动表达不满。
- 客户愿意花时间解释问题。
- 你希望从流失风险中找忠诚客户机会。
- 高客单客户因服务、产品或沟通落差产生抱怨。
- **红线**：不适用于恶意勒索、辱骂攻击或违法要求。

## 输入（做之前要准备的东西）

- 投诉内容原文。
- 订单/服务记录。
- 可提供的修复权限：解释、补偿、替换、升级、转交。
- 客户历史价值与未来潜力判断。

## 输出（做完得到什么）

- 一次投诉处理记录。
- 一个修复动作和一个后续跟进时间。
- 完成信号：客户知道问题被认真接住，并愿意继续沟通。

## 主流程（核心，占篇幅 ≥ 60%）

### Step 1: 接住情绪

- 先确认客户感受，不急着解释原因。
- 用一句话复述客户最在意的问题。
- 做完信号：客户从发泄转为愿意具体描述。

### Step 2: 分离事实与情绪

- 把投诉拆成事实、损失、期待三栏。
- 遇到模糊表达时追问具体时间、产品、人员、动作。
- 做完信号：你能说清到底是哪一环出错。

### Step 3: 判断客户类型

- 判断客户是有效投诉、误解投诉、过度要求还是恶意投诉。
- 有效投诉优先修复，误解投诉优先解释，恶意投诉启动边界。
- 做完信号：你知道该补偿、解释、升级还是止损。

### Step 4: 给出修复动作

- 在权限内给出明确动作：更换、补偿、专人跟进、流程纠正或资源升级。
- 不承诺做不到的事。
- 做完信号：客户知道下一步谁在什么时候做什么。

### Step 5: 做二次触达

- 问题解决后主动回访，确认客户是否满意。
- 把客户反馈写入团队流程，避免同类问题重复。
- 做完信号：投诉从一次事故变成服务改进记录。

## 判断点 / 决策树（如有分支）

```text
客户付费且愿意解释 -> 高优先级修复
客户只情绪发泄 -> 先接情绪，再取事实
客户要求越界 -> 给边界，不无限补偿
问题来自流程 -> 回填团队复盘
```

## 常见坑（3-5 条硬红线）

- 不要第一反应防御和反驳。
- 不要把所有投诉都当麻烦。
- 不要用超出权限的补偿换暂时平静。
- 不要修完单个客户后忘记改流程。

## 附录：实例（1 个跑通的例子，与主流程分开）

高净值客户对服务体验不满，如果团队只解释“我们流程就是这样”，客户会沉默流失。更好的做法是先承接情绪，再查明具体环节，给出修复动作，并在解决后回访。客户被漂亮解决后，反而可能因为“被重视”而成为更忠诚的客户。
