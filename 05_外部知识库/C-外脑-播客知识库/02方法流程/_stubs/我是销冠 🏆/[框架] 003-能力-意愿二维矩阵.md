# [框架] 能力-意愿二维矩阵

## 一句话（≤ 40 字）
用能力和意愿判断客户推进策略。

## 什么时候用（触发条件，3-5 条 bullet）

- B 端项目推进慢，不知道卡在人还是事。
- 对接人逻辑很强但总是挑战方案。
- 客户说要做，但迟迟不动。
- 你需要判断该培训、激励、绕开还是放弃。
- **红线**：不要凭一次对话给人永久贴标签。

## 评估对象（这个框架用来打分的是什么）

- B 端客户对接人、内部推动者、合作方负责人。
- 颗粒度：一个人对某个具体项目的状态，而不是这个人的整体能力。

## 维度定义（框架的骨）

### 维度 1：能力——他能不能把这件事做成

**观测信号**：

| 好信号（能力强） | 坏信号（能力弱） |
|---|---|
| 能清楚说出目标、流程和约束 | 只会复述上级口径 |
| 能调动资源或找到关键人 | 不知道谁能拍板 |
| 能识别方案风险 | 连基本问题都问不清 |

→ **怎么问出来 / 怎么观察出来**：问他“这件事在你们内部要经过哪些人、哪些节点、哪些风险”。

### 维度 2：意愿——他想不想把这件事做成

**观测信号**：

| 好信号（意愿强） | 坏信号（意愿弱） |
|---|---|
| 主动推进会议和资料 | 总让你等通知 |
| 会告诉你内部真实阻力 | 只做表面配合 |
| 能看见自己从项目中得到什么 | 觉得这是领导派下来的麻烦 |

→ **怎么问出来 / 怎么观察出来**：问他“如果这件事做成，对你个人和团队最重要的结果是什么”。

## 打分卡 / 分级表（可复制粘贴）

| 对接人 | 能力 | 意愿 | 象限 | 策略 |
|---|---|---|---|---|
|  | 强/弱 | 强/弱 | A/B/C/D |  |

- **A：能力强 + 意愿强** → 给资源，减少干扰。
- **B：能力强 + 意愿弱** → 找个人成就窗口，激活动机。
- **C：能力弱 + 意愿强** → 培训和工具支持。
- **D：能力弱 + 意愿弱** → 能换人就换人，不能换就降低预期。

## 打完分怎么用（决策后果）

- B 象限 → 不要继续讲方案，先找“他做成这件事有什么好处”。
- C 象限 → 提供模板、材料、会议支持，降低执行难度。
- D 象限 → 尽快找更高层或其他内线，不把项目押在他身上。

## 常见坑（3-5 条）

- 不要把“挑战你”一律理解成反对你。
- 不要只补能力，不补意愿。
- 不要把对接人的个人目标和组织目标混为一谈。
- 不要在 D 象限客户上无限消耗。

## 附录：实例（1 个跑通的例子）

某大公司对接人能力强，但一直质疑方案。继续堆逻辑不会改变局面。更好的做法是判断他可能缺少个人推进动机，补一份能帮他向领导汇报的材料，让他从“挑战方”变成“共同推动方”。
