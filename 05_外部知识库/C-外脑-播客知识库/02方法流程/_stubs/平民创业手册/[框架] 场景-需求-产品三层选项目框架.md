# [框架] 场景-需求-产品三层选项目框架

## 一句话

用场景、需求、产品三层筛掉不该做的项目。

## 什么时候用

- 面前有多个赚钱项目，不知道先做哪一个。
- 想判断一个副业、加盟、选品或内容变现方向是否值得投入。
- 容易一上来沉迷产品细节、供应链或品牌故事，需要先判断大方向。
- 想区分自己应该做流量驱动项目，还是客户价值驱动项目。

## 评估对象

一个候选项目。颗粒度要能用一句话说清楚：

> 我准备为哪类人，在什么场景下，解决什么需求，用什么产品或服务承接。

## 三层定义

### 第一层：场景

场景是“解决了什么问题、提供了什么价值的载体”。先看这件事是否真的发生，以及发生的土壤够不够大。

| 判断项 | 好信号 | 风险信号 |
|---|---|---|
| 基本面 | 覆盖人群足够大，能容纳很多细分需求 | 只有很小圈层自嗨 |
| 系统稳定 | 20 年前有，今天有，未来大概率仍然有 | 完全依赖短期政策、平台漏洞或单次热点 |
| 上升趋势 | 正在变大、变快、变普及 | 已明显衰退或被替代 |
| 合规成本 | 政策、平台、行业规则能承受 | 黑天鹅和封禁风险过高 |

### 第二层：需求

需求要看是否刚、痛、爽、痒、高频，以及一个需求能不能带出一个货盘。

| 判断项 | 好信号 | 风险信号 |
|---|---|---|
| 刚/痛/爽/痒 | 用户有强烈动机解决 | 用户只是觉得“不错” |
| 高频或终身 | 会反复发生，或周期很长 | 一次性、低频、难复购 |
| 货盘延展 | 一个需求能带出一组产品 | 只能卖单一小品 |
| 用户愿付成本 | 愿意付钱、时间、信任或注意力 | 只点赞不行动 |

原文用“遮丑”举例：鲨鱼裤、提臀裤、瘦腿袜、美背、束腰、天鹅臂等产品，都来自“变美、变瘦、看起来更体面”的需求。

### 第三层：产品

产品层不是先追求完美，而是判断这个产品能不能承接需求，并且是否值得长期做。

| 判断项 | 好信号 | 风险信号 |
|---|---|---|
| 五高 | 高客单、高利润、高粘性、高复购、高转介绍中多项成立 | 只靠一次性低毛利成交 |
| 客户价值 | 后续能延展更多服务或产品 | 只有单次流量套现 |
| 早期承接 | 能做到标准水准、主流审美、刚刚好能用 | 起步就追求 95 分以上 |
| 流量匹配 | 普通人能通过内容、分发、成交跑起来 | 必须先有强品牌、强供应链或强资本 |

## 打分卡

| 层级 | 问题 | 结果 | 备注 |
|---|---|---|---|
| 场景 | 基本面够大、系统稳定、趋势向上吗？ |  |  |
| 需求 | 是否刚、痛、爽、痒、高频，且能带出货盘？ |  |  |
| 产品 | 是否至少具备若干“五高”信号？ |  |  |
| 客户价值 | 客户是否能被持续服务，而不只是一次成交？ |  |  |
| 流量能力 | 早期是否能靠内容、分发或成交拿到量？ |  |  |

## 打完分怎么用

- 三层都强，且五高中至少有多项明显信号：进入最小验证。
- 场景大但需求弱：继续访谈或放弃，不要靠“教育市场”自我说服。
- 需求强但产品五高弱：可以当短期流量项目，不宜误判为长期事业。
- 产品很想高端，但客户价值不足：回到流量驱动，先验证获客和成交。
- 没有量却执着找源头厂家：先做销量和流量，数量上来后供应链和渠道会自然涌现。

## 原文例子

### 痛风、糖尿病相关产品

这类需求痛感强、周期长、同类人群容易互相推荐，因此更可能带来复购和转介绍。

### 日化食品 vs 减肥祛斑白牌

同样直播卖出 3000 单，日化食品客户可能只是冲品牌而来；减肥、祛斑祛痘白牌客户如果基于对人的信任购买，后续还能延展到瑜伽、器械、代餐、医美、美妆、女装、母婴、大健康、身心灵、副业、情感、成长、读书会等需求。

### 早期供应链

每天 5 单时，绕过中间商省下的钱很有限；每天 1 万单时，价格、快递、账期、机构分成和渠道资源都会变化。早期重点是先把量跑起来。

## 常见坑

| 坑 | 表现 | 修正 |
|---|---|---|
| 先选产品再找场景 | 被产品细节吸引，忽略用户是否真的需要 | 先看场景和需求 |
| 把趋势当需求 | 只看赛道热，不看用户痛感 | 问用户是否已主动解决 |
| 过早追求供应链源头 | 单量很小却花大量时间谈最低价 | 先拿量，量决定价格 |
| 产品洁癖 | 早期从 90 分优化到 95 分 | 先做到标准水准，把精力放到流量 |
| 模式幻想 | 想做平台级、模式级创新 | 普通人先接受流量驱动现实 |

## 适用边界

- 适合普通人选项目、副业、选品、内容变现方向。
- 不替代具体财务测算、法律合规、用户访谈和小规模实测。
- 对复杂 to B 项目，需要增加采购链路、预算归属、决策人和交付风险评估。
