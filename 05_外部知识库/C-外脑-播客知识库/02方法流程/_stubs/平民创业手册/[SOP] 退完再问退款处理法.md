# 退完再问退款处理法

## 一句话

先降低对抗完成退款，再复盘用户为什么不满意。

## 什么时候用

- 知识付费、社群、课程、服务型产品出现退款请求。
- 用户已经明确表达不满意或不适合继续。
- 想保留复盘信息，而不是陷入争吵。
- **红线**：合同、合规或恶意退款场景要按既定规则处理。

## 输入与输出

| 类型 | 内容 |
|---|---|
| 输入 | 用户退款请求、订单信息、退款规则 |
| 输出 | 完成退款、一次原因复盘、产品/筛选改进项 |
| 完成标准 | 用户对抗感降低，团队知道下一次如何预防 |

## 主流程

### Step 1：先确认规则

- 查订单和承诺。
- 确认是否符合退款条件。
- 合规场景按合同和平台规则处理。

### Step 2：符合条件就先退

- 不先争辩。
- 不用长篇解释证明自己没错。
- 告知退款进度。

### Step 3：退款后再问原因

模板：

```text
已经先帮你处理退款了。方便的话想请你说一句，主要是哪一点没有满足预期？我想用来改进后续服务。
```

### Step 4：归因到三类问题

| 类型 | 表现 | 后续动作 |
|---|---|---|
| 筛选问题 | 用户本来不适合 | 优化售前筛选 |
| 交付问题 | 内容或陪跑不到位 | 修交付流程 |
| 行动问题 | 用户不执行，只抱怨 | 明确行动门槛 |

### Step 5：更新产品红线

- 哪类用户以后不收？
- 售前要提前说清什么？
- 哪个交付环节要补？

## 常见坑

- 不要先吵再退，容易把售后变成舆情。
- 不要把所有退款都归因为用户问题。
- 不要没有记录，退款是产品筛选和交付的信号。
- 不要为了留人继续消耗团队情绪。
