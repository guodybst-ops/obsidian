# 前端流量后端交付分层运营法

## 一句话

**做生意的两条独立引擎不能混在一个"我"身上——前端负责流量 / 品牌 / 声量，后端负责交付 / 供应链 / 复购，两端由不同"负责人"背 KPI 才能稳定长大。**

## 什么时候用

- ✅ **1 人打全场做副业**：前端后端全靠你，忙到崩且始终不稳定
- ✅ **有员工 / 合伙人**：不同岗位职责边界模糊
- ✅ **想把生意从"我"这个人身上剥离**：想放假 / 想请假 / 想 exit
- **红线**：不适用于**日 GMV < 1 千**的极小体量（分层反而增加成本）；不适用于纯艺术创作性质（作品不适合分层）

## 输入

- **过去 30 天你的时间分配表**：前端事 % + 后端事 % + 混合 %
- **你目前的核心 KPI 是什么**（营收 / 复购 / 声量）
- **可分配到分层的至少 1 位合作方 / 员工 / 助理**

## 输出

- 一张**前后端职责边界卡**（模板 A）
- **完成信号**：3 个月后你个人 40%+ 时间从前端或后端**成功剥离**，同时 KPI 不下滑

## 主流程

### Step 1：定义两条引擎的具体 KPI

- **前端引擎 KPI**（3 选 1 或 2）：
  - 新增粉丝 / 新客户线索数
  - 内容曝光量 / 品牌搜索指数
  - 私信 / 加微信数
- **后端引擎 KPI**（3 选 1 或 2）：
  - 复购率 / NPS
  - 交付准时率 / 客诉率
  - 客单价 / LTV
- **判断信号**：两组 KPI 有明确数字目标，且**互不重叠**

### Step 2：把过去 30 天所有工作条目**归类**

- 每一条打钩：属于前端 / 后端 / 混合
- 混合的条目要拆——**80% 的混合都能拆成两件独立事**
- 拆完你会发现自己在前端做了 60% 后端 40%，或反过来——**你在过度偏科**
- 思思金句："**你以为你是 CEO，其实是既没能好好卖也没能好好交付的中间人**——分层第一天才是真开始。"
- **判断信号**：拆完 ≥ 95% 条目能归为纯前端或纯后端

### Step 3：找"另一半"——把弱的那一端交出去

- 你天然强的那一端（例：前端）留下，你自己做
- 弱的那一端交给：
  - **合伙人 / 老下属 / 学员** → 分成合作
  - **服务商 / 供应链** → 外包
  - **助理 + SOP** → 内部化
- 思思金句："**别人 5000 块能做好的事，你不要花 5 万时间去补短板**——补短板是打工人思维，长板 × 长板才是老板思维。"
- **判断信号**：弱端至少有 1 个明确负责人（不含"我兼")

### Step 4：立"边界" —— 前端 / 后端不能越界指挥

- 前端不能直接下单让后端"这个客户你必须接"
- 后端不能直接不接前端来的客户
- 通过**订单表 / 定价表 / SLA 表**建立交接界面
- 思思金句："**边界模糊 = 谁都能甩锅**——每一次前后端吵架都是边界没定清楚。"
- **判断信号**：一份可打印的"前后端交接 SOP"上线并被双方签字

### Step 5：每周复盘 30 分钟——KPI 独立打分

- 前端 KPI 单独打分，不受后端好坏影响
- 后端 KPI 单独打分，不受前端好坏影响
- 出现"某端拖累另一端"→ **重新谈边界或换人**
- **判断信号**：连续 4 周两端 KPI 各自达到 ≥ 80% 目标

## 判断点：分层 vs 不分层

```
月流水 < 1 万 ──────────→ 不分层（成本大于收益）
月流水 1-5 万 ──────────→ 半分层（前端你做 + 后端 1 位服务商）
月流水 5-30 万 ─────────→ 全分层（前端 + 后端各 1 位主责）
月流水 30 万+ ──────────→ 前端后端各带小团队 + 中台协调
```

## 常见坑

- ❌ **一个人做全场并觉得能扛** → 6 个月内必崩
- ❌ **让强的那端补弱的那端** → 前端做后端 3 个月，前端 KPI 掉光
- ❌ **前后端共用 KPI（营收）** → 出问题时互相甩锅
- ❌ **不建交接 SOP** → 每次订单来都要临时讨论
- ❌ **弱端找不到"另一半"就先自己扛** → 除非月流水 < 1 万；否则先花钱找兼职**顶一格**
- ❌ **前后端合伙人分成 50-50** → 通常前端应拿 60-70%（他决定订单量）

## 附录：实例（013 集"MBTI 咨询"分层案例）

**背景**：一位听众自己做 MBTI 深度咨询，从写内容到交付 1 对 1 全包，忙到崩且客诉多。

- Step 1 KPI：前端 = 私信数；后端 = 客户 NPS
- Step 2 归类：前端占她 70% 时间，交付质量下滑
- Step 3 找另一半：招了 1 位受过训练的助理咨询师 + 建了标准化交付模板
- Step 4 边界：她做前端所有内容 + 高单价客户；助理做中低价客户 + 售后
- Step 5 复盘：3 个月后她时间从每天 12h → 6h，营收翻倍，NPS 从 65 → 85

**思思点评**："**前端后端分层不是招人问题，是你敢不敢让别人也当'主角'**——不敢分层的老板永远长不大。"
