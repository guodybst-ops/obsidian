# 091 - 和吴翼技术解读OpenAI Operator：推理从抽象世界走向物理世界的开端

> 结构化说明：本笔记基于机器转写与清洗稿整理，属于 L4 萃取成品；原始音频、原始转写、清洗稿应继续作为原料保留。

## 一句话核心

OpenAI Operator 标志着 AI 从纯文本推理走向多模态、闭环交互的智能体，是逻辑推理从抽象世界伸向物理世界的开端信号。

## 摘要

2025年1月24日，OpenAI 发布首个智能体产品 Operator，打响全球智能体竞赛第一枪。前 OpenAI 研究员、清华叉院助理教授吴翼从技术视角解读：Operator 本质上是多模态、闭环的 o1（Agent o1 版本），其成功依赖好的基座模型、高质量数据集和高效大规模支持 Agent 的强化学习系统。吴翼回顾 OpenAI 2016 年首次尝试 Web Agent 失败的历史，指出当时缺少基座模型。他认为 2025 年是 Agent 之年，但商业化还需一年；Operator 目前仍是中间态产品，未来会向物理世界延伸。他还讨论了智能体与人的协作模式变化、创业公司机会以及学术界应探索非共识方向。

## 发言人

- **张小珺**：主持人，商业访谈录主理人。
- **吴翼**：前 OpenAI 研究员，清华大学交叉信息研究院助理教授，研究方向为强化学习。

## 金句收藏

1. “如果你去看 OpenAI 的历史，你会发现 OpenAI 成立之后干的第一个项目就是 Web Agent，但失败了——他们只有强化学习，没有基座模型。”
2. “Operator 更像是多模态、闭环的 o1，一个 Agent o1 的版本。”
3. “Agent 的商业价值在于人参与的少，意味着扩展了人的时间。”
4. “智能提升是核心，产品是智能提升后的自然涌现。”
5. “用户提供的不是数据，用户提供的是钱。”
6. “AI 时代的数据飞轮不是自动的，它需要聪明的研究员不停介入清洗数据。”
7. “Operator 是一个信号：逻辑推理从抽象世界走向视觉物理世界的开端。”
8. “如果现在读 AI 的 PhD，你不应该做大语言模型——去探索那些大公司还没做的非共识方向。”
9. “共识之下是巨头的主战场，非共识上面容易出现突然成长起来的新东西。”
10. “你开摩托车可以走乡间小道，人家开坦克不一定往那开。”

## 故事与场景

- **OpenAI 2016 年 Web Agent 失败**：OpenAI 成立后第一个大项目就是让通用视觉智能体在网页上点击，当时只有强化学习，没有基座模型，甚至没有人类标注数据，用 LSTM 去点网页，最终失败并裁掉二三十人。
- **Operator 的拟人行为**：吴翼提到一个 demo 中，AI 会关掉弹出的广告；另一个例子中，AI 计算退款时先在浏览器尝试几次失败，然后去计算器里按一下，行为很像人类。
- **吴翼导师 Stuart Russell 的 AI 安全故事**：吴翼开玩笑说，如果导师一直健在，说明没有邪恶 AI 穿越回来杀他，因为导师一直在做 AI 安全呼吁。

## 核心概念

- **CUA（Computer-Using Agent）**：一种专门为交互和 Agent 使用而定制化训练的模型，具备闭环控制系统——模型输出 token 后主动调用外部环境，期待下一个反馈，而非传统开环模型的一次性输出。例子：Operator 使用的底层模型。
- **闭环控制系统 vs 开环系统**：开环系统（如传统大模型）给指令直接输出，中间无反馈；闭环系统（如 Operator）输出动作后观察环境反馈，再继续思考与行动。例子：Operator 点网页时，点错会后退重试。
- **强化学习（RL）在 Agent 中的应用**：通过好的基座模型 + 高质量人类演示数据 + 大规模强化学习训练，让模型涌现出自我探索、自我修正的行为。例子：Operator 的长期规划能力来自 RL 激发。
- **OpenAI 五级分类**：L1 聊天机器人 → L2 推理者 → L3 智能主体（Agent） → L4 创新者 → L5 组织。L3 是当前 Operator 所在级别，人参与越来越少，自动化越来越高。例子：L3 需要推理规划 + 环境交互，L4 需要超越人类指令的创新。
- **多模态推理**：结合语言、视觉、动作等多种模态的推理能力。Operator 使用原生多模态基座模型（类似 GPT-4o）理解语言和视觉，动作通过结构化文本（thinking + action）实现。
- **数据飞轮 vs 半自动闭环**：推荐系统的数据飞轮是自动的，用户行为越多系统越好；AI 的数据飞轮需要研究员介入清洗数据，用户反馈不能直接提升智能，但能指示能力缺口。例子：Operator 的用户指令（复杂任务）比 Chatbot 闲聊更有价值，但仍需人工处理。
- **Agent 的起源**：最早来自博弈论（两个 player 玩零和游戏），后在强化学习中指与环境交互的智能体，大模型时代指大语言模型调用外部世界。Operator 将两者合并。

## 我的批注

> [!NOTE] 智能提升与产品的关系
> 吴翼强调“智能提升是核心，产品是智能提升后的自然涌现”，这与许多公司“产品驱动数据飞轮”的叙事不同。OpenAI 内部研究、post-training、产品团队相对独立，研究团队负责突破智能上限，产品团队负责交付。这解释了为什么 OpenAI 能持续发布令人惊讶的模型，而产品形态往往滞后。

> [!NOTE] 学术界应避开大公司主赛道
> 吴翼引用李飞飞的话“如果你现在读 AI 的 PhD，你不应该做大语言模型”，并建议学术界探索非共识方向，如多 Agent 交互模式、个性化 AI 等。这为研究者提供了战略定位：不要与巨头的坦克正面竞争，而是走乡间小道。

> [!QUESTION] Operator 的“泛化性”是否真的来自多模态？
> 吴翼说 Operator 的泛化性比 o1 好，因为有了眼睛（多模态输入）。但网页本身是文本图像化，并非真实物理世界。这种泛化性是否只是对更多网页布局的适应，还是真正跨模态的推理能力？未来 Operator 进入物理世界时，泛化性会面临更大挑战。

## 对话稿

**张小珺**：对于 Operator 你的整体感受怎么样？

**吴翼**：首先是意料之中，第二是真正看到的时候还是挺震撼的。它真的会用一种好像人也会这么去做的方式，通过强化学习把它规模化、通用化。

**张小珺**：Operator 在通往 AGI 路线图上标志着什么？

**吴翼**：它是一种通用型的变化。o1/o3 在聚焦问题上思考更深，但没有环境交互和多模态。Operator 有了多模态和闭环控制系统——想一会儿，点一下，看反馈，连续做很多轮交互。

**张小珺**：Operator 包含哪些核心技术要点？

**吴翼**：三件事：好的基座模型（原生多模态）、高质量数据集和任务、高效率大规模支持 Agent 的强化学习系统。其中强化学习系统需要交互环境，比纯文本推理复杂得多。

**张小珺**：为什么 Operator 是单独入口？

**吴翼**：两方面。一是它用了和 o3 不一样的基座模型；二是产品上，大家习惯了 GPT 的使用方式，这种完全不同的用法更适合单独放出来。

**张小珺**：Operator 怎么整合语言、视觉和动作？

**吴翼**：理解部分靠原生多模态基座模型（类似 GPT-4o）；动作部分通过结构化文本——先 thinking，然后 action（点或打字），格式规定后强化学习训练。

**张小珺**：Agent 这个词是怎么来的？

**吴翼**：最早在博弈论里，两个 player 叫两个 agent；后在强化学习里指与环境交互的智能体；大模型时代指大语言模型调用外部世界。Operator 把两边合并了。

**张小珺**：如果 Agent 成为主流，人机协作方式会怎么变？

**吴翼**：两个变化。一是 AI 能否个性化、适应人，而不是人适应 AI；二是当所有人都用 AI，软件界面会不会为 AI 留两扇门。

**张小珺**：2025 年技术演进方向？

**吴翼**：主赛道太共识了（多模态、推理、Agent），巨头开坦克往前冲。非共识方向更容易出现新东西，比如多 Agent 交互模式、个性化 AI。学术界应该提前想 2026 年的事。
