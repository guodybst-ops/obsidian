# [SOP] 单集笔记生产 SOP

## 一句话

把一篇原文清洗稿转成一份结构化单集笔记，30–60 分钟一篇，标杆参照给女孩 101 / 102。

## 什么时候用

- 决定要把某一集播客原文变成可检索、可复用、可回链的结构化笔记
- 一档播客已经确定"逐集精读"策略（如给女孩 001–108 / 富女孩宝典 001–015）
- **红线**：不用于原文只有几段话的碎片集；不用于纯广告集；不用于原文缺失或严重错乱的集

## 输入

- **原文清洗稿**：`99原始资料/<节目名>/NNN - 标题.md`
- **节目索引**：`89单集笔记/<节目名>/00-<节目名>｜播客索引.md`（缺失就先建）
- **人物档案清单**：`01人物原萃/*.md`

## 输出

一份 `89单集笔记/<节目名>/NNN - <标题>.md`，包含：

- 完整 frontmatter（14 字段）
- 摘要（3–5 段，≥ 250 字）
- 金句收藏（6–12 条）
- 核心要点（8–16 个编号小节，每节 100–300 字）
- 关键问答（长集必备，4–8 组）
- 关联（人物 / 概念 / 方法 Wiki Link）
- 原文回链

**完成信号**：陌生人只读这篇笔记就能大致复述这集在讲什么；至少挂上 2 个人物、3 个概念/方法 stub 候选；若出现明确取舍链，挂上 04 判断哲学候选；节目索引对应集状态改为 ✅。

## 主流程

### Step 1: 读原文 · 分层标注

- 完整读一遍 `99原始资料/<节目>/NNN - <标题>.md`
- 分三种颜色标注：
  - 🟥 **金句候选**：主播/嘉宾说得凝练、可摘录的原话
  - 🟨 **要点候选**：可编号的观点、模型、故事、判断
  - 🟩 **关联候选**：出现的具名人物、可提炼的概念、方法框架、判断哲学节点

**完成信号**：能一句话回答"这一集在讲什么"。

### Step 2: 建 frontmatter

```yaml
---
tags: [播客笔记, <节目名>, <主嘉宾>, <主题标签1>, <主题标签2>]
created: <YYYY-MM-DD>
source: <节目名>
author: <主播> / <嘉宾>
layer: extract
status: structured
confidence: 0.75
aliases: ["<集号>集 <关键词>", "<核心概念>"]
provenance: external
viewpoint_owner: external_author
raw_material: false
episode: <集号，如 101>
pubDate: <YYYY-MM，从原文/_episodes.json 取，缺则写"待补充">
extraction_status: complete
extracted_at: <YYYY-MM-DD>
---
```

**tags 顺序**：`播客笔记` → `<节目名>` → `<嘉宾/人物>` → `<核心概念>`，8 个以内。

### Step 3: 写摘要（3–5 段，≥ 250 字）

**结构**：
1. 本集基本场景 + 主嘉宾 + 讨论主线（1 段）
2. 把主线拆成 2–3 条子线（1 段）
3. 这集的独特价值 / 与本节目其他集的关系 / 适合什么读者（1 段）

**红线**：
- ❌ 禁止"这一集非常精彩"式空泛评价
- ❌ 禁止在摘要里堆金句
- ✅ 让读者只读摘要就知道要不要继续往下

### Step 4: 摘金句（6–12 条）

**入选标准（4 选 1）**：
- 观点凝练：一句话讲清一个判断
- 反常识：与主流认知相反
- 可迁移：脱离本集语境仍成立
- 情绪张力：主播/嘉宾独特表达

**格式**：用 `>` 引用块，条与条之间空一行，不加编号。

**红线**：不改写原话，一字不动；宁少勿多。

### Step 5: 拆核心要点（8–16 个编号小节）

- 合并同类项，按原文出现顺序编号
- 二级标题：`### N. <一句话概括本要点>`
- 每节 100–300 字：一句主张 + 展开（1–3 段）+ 例子（可选）

**判断分支**：
- 要点 < 8 个 → 该集可能不值得独立精读，考虑合并入主题笔记
- 要点 > 16 个 → 合并同类项，或拆成上/下两篇

### Step 6: 写关键问答（长集必填，4–8 组）

**触发条件（3 选 1）**：
- 原文是问答结构（如富女孩宝典的连麦咨询集）
- 长集（> 6000 字）需为读者建索引入口
- 该集会被后续多次回看

**格式**：
```markdown
## 关键问答

**Q：<用户视角问题>？**
A：<1-3 行答案，从要点里抽取，不重复展开>
```

短集可跳过。

### Step 7: 挂 Wiki Link（3 类必扫）

在文末追加"## 关联"章节：

- **人物** → `[[01人物原萃/<人名>]]`，只挂已存在文件
- **概念** → `[[03概念链接/[概念] <概念名>]]`，未存在挂 stub
- **方法** → `[[02方法流程/[SOP/框架/心法] <方法名>]]`，未存在挂 stub
- **判断哲学** → `[[04判断哲学/[判断] <决策节点>]]`，只有出现“为什么选 A 不选 B”的取舍链时才挂

**红线**：不创建死链；每类 ≤ 5 个。

### Step 8: 回链原文 + 更新索引

- 文末追加：
  ```markdown
  ## 原文
  - [[99原始资料/<节目>/NNN - <标题>|原文清洗稿]]
  ```
- 打开 `89单集笔记/<节目>/00-<节目>｜播客索引.md`，把对应集状态改为 ✅，完成数 +1

### Step 9: 自检

按下面 6 关自检清单过一遍，全绿再保存。

## 判断点 / 决策树

```
原文体量：
  < 2000 字      → 短集简化：摘要 / 金句 / 3-6 要点 / 关联（跳过关键问答）
  2000-6000 字   → 标准流程：8-12 要点
  > 6000 字      → 标准流程：12-16 要点 + 关键问答必填
  > 12000 字     → 考虑拆上/下集两篇笔记

原文格式：
  访谈对谈       → 摘要按"主嘉宾 + 主线"写
  连麦咨询集     → 关键问答必填，要点按"问题-诊断-建议"结构
  独白讲授集     → 要点按讲授顺序编号，问答可跳过
  多人圆桌       → 摘要标明每位角色，要点合并同类项而非按人拆

节目惯例：
  给女孩 / 富女孩    → 遵循节目已有惯例（案例卡可选补）
  张小珺 / 42章经    → 只需 89 主目录一篇
```

## 可复用产物 · 14 字段 frontmatter 自检卡

| 字段 | 说明 | 常见错误 |
|---|---|---|
| tags | 3–8 个，`播客笔记` + `<节目>` 打头 | 空格分隔 |
| created | 建笔记当天 | 抄了模板日期 |
| source | 节目全名 | 简写"给女孩" |
| author | 主播 / 嘉宾 | 只写嘉宾 |
| layer | 固定 `extract` | 误写 experience |
| status | 固定 `structured` | 抄成 stub |
| confidence | 0.6–0.85 | 抄成 1.0 |
| aliases | 2–4 个别名 | 空数组 |
| provenance | 固定 `external` | 抄成 self |
| viewpoint_owner | 固定 `external_author` | 抄成 user |
| raw_material | 固定 `false` | — |
| episode | 阿拉伯数字，去前导 0 | 保留"001" |
| pubDate | `YYYY-MM` 或"待补充" | 空缺 |
| extraction_status | 固定 `complete` | 抄成 pending |
| extracted_at | 完成当天 | 忘改 |

## 常见坑（硬红线）

1. ❌ **摘要堆金句** — 摘要是"要不要继续读"的判断入口，不是名言汇总
2. ❌ **金句改写原话** — 一字不动，改写就失去引用价值
3. ❌ **要点做成目录式提纲** — 每节要写完整观点，不是索引条目
4. ❌ **关联挂死链** — 目标不存在就先建 stub 再挂
5. ❌ **不更新节目索引** — 索引不同步 = 无法追踪完成率
6. ❌ **frontmatter 字段缺** — 尤其是 episode / pubDate / status / provenance

## 附录 A：短集简化流程（原文 < 2000 字）

```
frontmatter（14 字段全填）
## 摘要（1-2 段，≥ 150 字）
## 金句收藏（3-6 条）
## 核心要点（3-6 节）
## 关联
## 原文
```

跳过 Step 6 关键问答；要点粒度可缩到 80–150 字 / 节。

## 附录 B：批量作业节奏建议

- **单次批次上限**：5 集（超过质量会掉）
- **单集耗时估算**：短集 30 分钟 / 标准集 45 分钟 / 长集 60 分钟
- **一批完成后动作**：更新索引 → 随机抽查 1 集自检 → 记录新发现的 stub → 再进下一批
- **累积每 20 集**：回顾 stub 增长，判断是否要沉淀成 03 概念主区 / 02 方法主区

## 附录 C：来自 101 / 102 标杆的经验教训

- **101（春运学习班·刘润）** — 长集范例：16 节要点 + 关键问答 6 组 + 大量概念挂钩（本价值模型 / OKRAP / root cause / 反图书馆模型 / 认知差）
- **102（李欣频·木马程序）** — 中长集范例：13 节要点，无关键问答，金句 10 条，展示"金句 + 要点"并行支撑
- **共性**：摘要都是 3 段，都清楚交代"这集在讲什么、值不值得看"；tags 都是 8–10 个混合"节目名 + 嘉宾名 + 主题关键词"；aliases 都用了"集号 + 关键词"便于反向搜索
