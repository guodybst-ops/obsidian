# 030 - Cursor 刷屏背后，复盘 AI Coding 的现状与发展：对谈 Gru.ai 创始人张海龙

## 摘要

本期对谈 Gru.ai 创始人张海龙，围绕 Cursor 刷屏、AI Coding 工具、Copilot 与 Agent 的差异、国内外开发者工具生态、AI 软件工程创业机会展开。

张海龙长期服务程序员和软件工程领域，曾做开源中国程序员社区和 Coding.net / DevOps 平台。2023 年开始创业做 Gru.ai，核心判断是：过去为程序员做工具，而 AI 这波第一次可能直接生产“劳动力”。如果 Copilot 是提升程序员效率的电钻，那么 Agent 更像一个能异步接任务的小弟或数字员工。

本期最重要的区分是：AI Coding 并不是一个统一形态，至少分为 Copilot 和 Agent。Copilot 已经跑通商业模式，它是同步工具，人在场时辅助补全、编辑、问答；Agent 则是异步劳动力，能接收任务、自主规划、编写、运行、调试并交付结果。但张海龙认为，Agent 目前还没有真正跑通 PMF，无论 product-market fit 还是 product-model fit 都不清楚。

Cursor 的成功被拆解为一个产品形态创新：它不是重新做 IDE，而是 fork VS Code，突破插件限制，实现跨文件 / 全局补全和极低延迟体验。它的非共识在于：在 GitHub Copilot 已经成熟、微软拥有 IDE 和模型的前提下，仍然通过一个更好的局部体验跑出来。

对谈还讨论了为什么张海龙不相信“普通人一句话写软件”的愿景，为什么程序员仍然重要，为什么 AI Agent 应从 unit test 等窄任务切入，为什么业务上下文和工程上下文不会被通用模型自然解决，以及为什么硅谷 AI 基础设施和 To B 生态比国内更繁荣。

## 金句收藏

- 过去我们为程序员做工具，这一波 AI 可能第一次可以直接生产劳动力。
- Copilot 像电钻，Agent 像一个帮你拧螺丝的小弟。
- Copilot 是同步工具，Agent 是异步劳动力。
- Cursor 的贡献不是做了 IDE，而是打破了 GitHub Copilot 只能往后补全的限制。
- Cursor 的非共识是：拿微软的 IDE、微软投资的模型，去挑战微软的 Copilot。
- 很多 AI Agent 看起来很炫，但如果底层问题不 ready，所有解这个问题的人都不用看。
- 一个 Agent 说自己什么都能干，基本上就意味着它什么也不能干。
- Agent 最重要的品质不是聪明，而是可靠。
- 人不愿意写 unit test，不代表这件事没价值，反而可能是 Agent 的好切入点。
- 普通人不想写代码，普通人想喝咖啡、拍照、兜风。
- 我不相信任何把代码平民化的东西，软件工程历史上这件事没有成功过。
- 如果一个需求足够 common，就会变成一个专业软件，而不是每个人自己写代码。
- 模型进化不会让应用无意义，除非真正的 AGI 出现。
- 软件工程里有业务上下文和工程上下文，这两个问题是 company-specific / team-specific 的。
- 一个聪明的应届毕业生，也需要培训后才能在公司产生价值。
- 评估 Agent 就像员工上岗前考试，你得先有题库。
- 硅谷不是不卷，而是你以前看到的是卷完后的结果。

## 核心要点

### 1. 张海龙的背景：长期服务程序员和软件工程

张海龙从初中开始写程序，写了 20 多年代码。大学和研究生毕业后的工作，也几乎都与代码、软件工程和程序员有关。

他曾做过两个国内开发者生态相关项目：

- 开源中国：程序员社区；
- Coding.net：DevOps 平台。

后来相关业务合并到腾讯，他也继续做 To B 开发者工具。2023 年，他开始创业做 Gru.ai。

### 2. Gru.ai 的核心判断：AI 可能直接生产劳动力

过去开发者工具公司主要为程序员做工具，帮助程序员更高效地写代码。

但张海龙认为，AI 这波新技术带来了新变量：它可能第一次直接生产劳动力，而不是只生产工具。

这意味着：

- 不只是让程序员打字更快；
- 不只是 IDE 更好用；
- 而是让一个数字员工接收任务、自己完成部分软件工程工作。

这就是 Gru.ai 切入 Agent 赛道的原因。

### 3. 国内 To B / To Developer 生态长期难做

张海龙复盘国内开发者工具和 To B 生态时认为，国内开发者付费意愿弱，企业付费体系也不成熟。

Developer 是很聪明、精打细算的人群，很难从他们身上赚冲动消费或情绪消费的钱。生产力工具最终通常还是企业买单。

国内 To B 难做的原因包括：

- 客户招投标流程重；
- 开源项目容易被模改；
- 企业付费习惯弱；
- SaaS 生态不成熟；
- 很多公司更愿意免费或低价卷。

### 4. 海外并不是不卷，而是卷在 PMF 之前

张海龙在硅谷观察到，海外其实非常卷，只是过去大家看到的是卷完后的结果。

以 Agent observability 为例，他原以为海外只有 LangSmith、Langfuse 等少数团队，去了硅谷后发现至少五个团队在做，而且融资和商业化都不错。

他的判断是：

- 海外卷的是 PMF 之前的探索；
- 国内更多卷的是 PMF 之后的复制和交付；
- 当海外把产品形态和商业模式跑通后，国内会有大量团队杀进来卷落地。

### 5. AI Coding 需要区分 Copilot 和 Agent

很多人混淆了 AI Coding 的不同形态。

张海龙明确区分：

- Copilot：工具，辅助人写代码；
- Agent：独立完成任务的数字劳动力。

Copilot 是同步的，人必须在场；Agent 是异步的，人可以不在，Agent 自己规划、执行、调试、提交。

这一区分决定了产品形态、商业模式、定价和技术难度完全不同。

### 6. Copilot 已经跑通商业模式

GitHub Copilot 已经证明 Copilot 这件事成立。

Copilot 的核心不是问答，而是代码补全。它的本质价值是减少程序员打字成本，在 IDE 中润物细无声地出现。

张海龙认为 GitHub Copilot 的贡献在于找到了两个 PMF：

1. Product-market fit：开发者愿意为这种能力付费；
2. Product-model fit：模型能力到了某个程度后，这种实时补全场景才成立。

### 7. Cursor 的核心创新：全局补全和体验突破

Cursor 的成功不是因为重做了 IDE。它 99% 的 IDE 能力来自 fork VS Code。

它真正做的是：突破 VS Code 插件机制限制，直接修改 IDE 体验，实现 GitHub Copilot 没做出的全局补全。

GitHub Copilot 主要是往后补全，而 Cursor 的假设是：当我改某个变量、函数或某段代码时，相关位置也应该同时改掉。

这种跨位置、跨文件、全局 diff 式的补全体验，是 Cursor 最关键的创新。

### 8. Cursor 的体验好在“猜得准 + 延迟低”

Cursor 会根据上下文和当前输入，猜测用户想改什么，然后用大模型提前生成结果，再和当前文件做快速 diff。

用户看到的是：多个位置同时出现修改建议，只要 tap / tab 确认即可。

关键在于：

- 猜测延迟极低；
- 修改建议出现得像瞬时；
- 用户只需要连续确认；
- 多处改动一并完成。

这种体验是之前 Copilot 没有做到的。

### 9. Cursor 的非共识：用微软生态挑战微软产品

Cursor 早期路径很不被看好。

原因是：

- 它没有自己的 IDE，基于 VS Code；
- 它没有自己的基础模型，用 GPT 或 Anthropic；
- 它挑战的是 GitHub Copilot，而 Copilot 背后也是微软；
- GitHub Copilot 已经成熟商业化。

某种意义上，它拿着微软的 IDE 和微软投资的模型，去挑战微软的产品。

这听起来不合理，但 Cursor 通过局部体验突破跑出来了。

### 10. 大厂反应慢，是创业公司的机会

Cursor 的做法被验证后，GitHub Copilot 理论上可以跟进。但微软并没有立刻做出同样体验。

张海龙认为，一部分原因是插件机制限制：GitHub Copilot 若要做 Cursor 的体验，可能要先完善 VS Code 插件机制。

这也说明，美国大厂反应慢对创业者是巨大优势。

### 11. Agent 赛道还没有真正跑通 PMF

相比 Copilot，Agent 还没有严肃意义上的 PMF。

张海龙认为两个 PMF 都没通：

1. Product-market fit：Agent 应该在什么场景、以什么形式存在，怎么交互，怎么定价，都不清楚；
2. Product-model fit：什么模型能力足以让 Agent 工作，也不清楚。

如果 Agent 真正跑通，会像 Cursor 一样出现大规模口碑传播，但目前还没有。

### 12. Devin 让 Agent 进入视野，但愿景不可实现

Devin 的 PR 非常成功，让 AI Coding Agent 进入大众视野。

但张海龙认为，Devin 式“什么都能干”的愿景目前不可实现。硅谷也逐渐形成共识：如果一个 Agent 说自己什么都能干，那基本意味着它什么也不能干。

当前更现实的路径，是找到细分切入点，让 Agent 专注做好一件事。

### 13. Code Agent 应从窄任务切入

AI Coding Agent 可以有很多窄场景：

- code review；
- 文档生成；
- 重构；
- 单元测试；
- 算法复现；
- bug 修复中的一小段流程。

张海龙团队当前选择主攻 unit test，因为它价值明确、通用性强、准确率更容易做高。

### 14. Unit test 是 Gru.ai 当前主攻场景

Unit test 是为已有代码写另一段测试代码，验证输入输出是否符合预期。

它的价值在于防止 regression：系统在后续开发中被修改时，原有功能不会被破坏。

许多团队单元测试覆盖率低，往往低于 30%，因为开发者不愿意写。这项工作无聊、重复，但很有价值。

这让它成为 Agent 的好切入点：人不愿意干，任务有套路，价值可衡量，且相对不依赖复杂业务上下文。

### 15. Copilot 和 Agent 会长期并存

张海龙认为，Copilot 和 Agent 解决的是不同问题，会长期并存。

Copilot 像电钻，帮助人更快完成手头工作；Agent 像小弟，可以接收一个独立任务去做。

只要程序员仍然重要，Copilot 就重要。人需要更好的装备，也可以同时带一些机器小弟。

### 16. 张海龙不相信“普通人一句话写软件”

他不相信任何把代码完全平民化的愿景。

原因有三点：

1. 软件工程历史上，低代码 / 无代码从未大规模降低软件工程门槛；
2. 普通人没有写代码需求；
3. 复杂需求很难用自然语言讲清楚。

普通人想喝咖啡、拍照、兜风，不想写代码。真正普遍的需求会被专业团队做成成熟软件，而不是每个人自己生成。

### 17. 通用“一句话做应用”会成为 ChatGPT 的事

如果一个需求足够 common、足够简单，那么它更可能成为 ChatGPT 或通用超级 Agent 的能力，而不是某个垂直创业公司的生意。

垂直公司要做的是更专业、更可靠、更能产生生产力价值的窄任务。

### 18. Agent 最重要的品质是可靠

一个数字劳动力最重要的不是看起来聪明，而是可靠。

张海龙类比：招一个实习生，不太能干可以接受；但如果经常不靠谱、瞎折腾、浪费你的时间，就不能忍。

所以 Agent 产品不能只追求炫酷，而要追求稳定完成任务、可评估、可复现。

### 19. 模型进化不会让应用无意义

张海龙去年曾担心 GPT-5、GPT-6 甚至 GPT-10 会让上层应用无意义。现在他更坚定地认为不会。

除非真正 AGI 出现，否则模型进化更多是在准确率、上下文长度、速度、聪明程度上提升。

这些提升会利好 Agent，而不是消灭 Agent。

### 20. 软件工程有业务上下文和工程上下文

Agent 难做的核心，是软件工程存在两类上下文：

- 业务上下文：公司业务、产品逻辑、用户场景；
- 工程上下文：代码架构、团队规范、历史实现、依赖关系。

这两个问题都是 domain-specific、company-specific、team-specific 的，不会被通用模型自然解决。

模型越聪明，只是让 Agent 更容易吸收给定上下文，但上下文本身仍需要产品和系统提供。

### 21. 未来仍然需要学编程

张海龙认为，程序员岗位依然会被需要。编程教育可能会变化，但学习编程仍然重要。

AI 可能改变程序员数量和类型，但不会让软件工程师整体消失。

### 22. Evaluation 是 Agent 上岗前考试

做 Agent 必须构建 evaluation。

如果你制造一堆数字员工，上岗之前必须有考核方式。对于 unit test Agent，就要构建题库：从开源仓库、自己的仓库、早期客户商业仓库中，整理不同语言、框架、类型的任务。

每次 Agent 改进后，都要跑题库，看 1000 道题做对多少。

这类数据以前不存在，需要自己构建，也涉及合成数据。

### 23. 硅谷 AI 生态各层都很繁荣

张海龙观察，硅谷 AI 生态在每个层面都非常欣欣向荣。

不只是投资金额，而是项目种类和数量都很丰富：AI + 假发、AI + 时尚、AI + 选品等各种方向都有团队在做，并且是正经创业项目。

更硬核的是 infrastructure 层，非常卷，投入可能是国内的 10 倍以上。

### 24. 美国 SaaS 生态形成付费循环

张海龙在硅谷发现，自己买的 SaaS 越来越多：LinkedIn 高级版、Zoom、Calendly、邮箱等。

在美国商业场合，这些都是 common practice。没有免费替代，大家都收费，大家也都付费。

这种生态和国内不同。国内用户习惯免费，工具服务很难收费，这也是国内 SaaS 和开发者工具难做的重要原因。

### 25. 给 AI 创业者的建议：理解底层，自己动手

张海龙不轻易给泛化建议，但分享了自己的路径：对底层理解非常重要。

能自己看论文就自己看，能自己手写就手写。等到一定程度，再用现成工具或 infrastructure，才会真正带来价值。

AI Agent 是新领域，不像软件工程已有几十年成熟范式。如果一上来就使用别人铺好的东西，可能会误以为某些问题解不了；自己做过底层后，会形成体感，这种体感会改变认知，并在关键问题上发挥作用。

## 关键问答

### Q1：Gru.ai 为什么选择做 AI Coding Agent？

**A：**因为张海龙判断，AI 这波不只是提升程序员工具，而是可能第一次直接生产劳动力。相比 Copilot 这种电钻式工具，Agent 更像能独立接任务的数字员工，生产力提升空间更大。

### Q2：Copilot 和 Agent 的根本区别是什么？

**A：**Copilot 是同步工具，人必须在场，主要辅助补全和编辑；Agent 是异步劳动力，能接收任务后自主规划、执行、调试和交付。

### Q3：为什么说 Copilot 已经跑通？

**A：**GitHub Copilot 找到了产品形态、使用场景和收费方式：它寄生在 IDE 中，在用户写代码时自动补全。模型能力到位后，这种场景成立，开发者和企业愿意付费。

### Q4：Cursor 真正做对了什么？

**A：**Cursor 不是重新发明 IDE，而是 fork VS Code，突破插件限制，实现全局补全、多处 diff 修改和极低延迟确认体验。它让用户感觉“我刚要改的地方，它都提前猜到了”。

### Q5：Cursor 的非共识是什么？

**A：**在 GitHub Copilot 已成熟、微软拥有 IDE 和模型资源的情况下，Cursor 仍然选择用 VS Code 和外部模型挑战微软产品。这个故事看起来不通，但它靠产品体验跑出来了。

### Q6：为什么 Agent 还没跑通 PMF？

**A：**因为 Agent 的场景、交互、定价、产品形态都还不清楚；同时什么模型能力足以支撑 Agent 稳定工作也不清楚。很多产品只是 PR 火，留存和实际生产力未被证明。

### Q7：为什么不看好“什么都能干”的 Agent？

**A：**因为软件工程任务太复杂。一个说自己什么都能干的 Agent，往往说明它没有明确边界。当前更现实的是做窄任务，把某一类任务做到可靠。

### Q8：为什么 Gru.ai 选择 unit test？

**A：**因为单元测试有价值、开发者不愿意写、任务相对有套路、不同团队实践较接近、对业务上下文依赖较低，更适合作为通用 Agent 的切入点。

### Q9：AI 会让 Copilot 消失吗？

**A：**不会。Copilot 和 Agent 是两类工具：人仍然需要电钻，也可以同时让小弟干活。只要程序员存在，Copilot 就仍然有价值。

### Q10：普通人未来会用 AI 写软件吗？

**A：**张海龙不相信这个愿景。普通人通常没有写代码需求，复杂需求也讲不清。如果需求足够普遍，专业团队会把它做成软件；如果足够简单，可能成为 ChatGPT 的通用能力。

### Q11：模型进化会不会干掉 AI Coding 应用？

**A：**不会，除非真正 AGI 出现。模型变强会提升 Agent 的能力，但业务上下文和工程上下文仍然需要产品系统提供。

### Q12：为什么业务上下文和工程上下文重要？

**A：**因为每个公司、团队、项目的业务逻辑、工程规范、历史代码和依赖关系不同。通用模型不知道这些，Agent 必须通过系统获得这些上下文，才能稳定完成任务。

### Q13：如何评估一个 Coding Agent？

**A：**要建立题库，覆盖不同语言、框架、仓库和任务类型。每次 Agent 迭代后跑题库，看成功率、正确率、可靠性，而不是只看单个 demo。

### Q14：硅谷 AI 生态给张海龙最大的感受是什么？

**A：**项目类型丰富，基础设施层投入巨大，SaaS 付费习惯成熟。海外不是不卷，而是卷在更早阶段，并且付费生态支持更多公司活下来。

### Q15：给 AI Agent 创业者的建议是什么？

**A：**尽量理解底层，自己看论文、自己手写、自己做一遍。不要一开始就完全依赖现成工具。底层体感会塑造认知，帮助你判断什么问题真正可解。

## 润色版逐字稿

### 开场：从开发者工具到 AI 劳动力

曲凯：最近国内互联网圈能看到很多和 AI Coding 相关的工具、软件和讨论，典型的像 Cursor，之前特别火。但这些主要还是美国的产品，国内还比较少。今天正好请到国内做这块我觉得最专业的创业者之一，Gru.ai 的创始人海龙。海龙可以简单介绍一下你自己的经历。

张海龙：我从小就是程序员，从初中开始写程序，算下来可能写了 20 多年。所以一路以来，我都和软件工程、写程序有渊源。

大学、研究生毕业后，几乎所有工作都和代码、程序员有亲密关系。之前做过两件大家可能知道的事情：一个是开源中国程序员社区，另一个是 Coding.net，一个 DevOps 平台。这两件事情在国内做了很长时间，后来合并到腾讯，也做整个 To B 的研发工具。

2023 年开始，我们创业做一个新项目，叫 Gru.ai。本质上是觉得新技术来了以后，可能产生一些新的变量。

以前我们总是为程序员做工具。但 AI 这一波可能第一次可以直接生产劳动力，也就是 labor。你不用再只是做工具了。

我觉得这对整个效率和生产力的提升应该更大，非常令人激动。所以我们积极在做这件事。简单来讲，它就是 Agent 这个大赛道。

### 国内 To B 与 To Developer 的难题

曲凯：你觉得国内之前几年，不管是 Git 还是什么，好像没有特别做起来。你总结原因是什么？Coding 本来就是全球性语言，也许不需要一个中国版？

张海龙：这是个好问题。我一直在反思。其实国内不光是这个，讲大一点就是整个国内 To B 生态。

我们可以聊两条线。一条是 To B；但如果真的是 to engineer，它是 to developer，有一点小区别。

曲凯：To developer 最后真正变现还是企业买单，虽然最早可能是 PLG。海外也是这样吗？

张海龙：我觉得也是。最近我在硅谷，看到这边买 Cursor 的，很多后面都是企业报销。

Developer 很难变现。他想的是怎么薅你羊毛，你还想着怎么赚他钱，怎么可能？Developer 是一群很聪明的人，思维习惯上也精打细算，这和他的工作专业性有关。

如果想从他身上赚冲动消费、情绪消费，很难。但生产力工具最后买单的其实都是企业，因为它真的解决问题。

我们以前做开源中国、Coding 到第三第四年时，就有这种感受：developer 很难变现。

### 海外不是不卷，是卷在更早阶段

张海龙：我最近在硅谷看到很多公司，有一个和以前直觉相反的深切感受。

我们以前觉得国内卷，同质化竞争严重；海外好像很多产品赛道没那么卷。但这是错误认知。

我最近的认知是：海外更卷。我们以前看到的海外不卷，是海外卷完了，你看到的是结果。

比如我们做 Agent，有一个重要 infra 需求，就是可观测性，类似 Datadog 那个赛道。但 Agent 是全新的东西，需要新的可观测性工具。我一开始以为海外这个赛道没什么人做，只有 LangSmith 和开源的 Langfuse 等。

这次来了以后，遇到至少 5 个团队在做这件事，而且都融了很多钱，商业化也很好。这个赛道其实很卷。很有意思的是，国内没有人做。

曲凯：落回 AI Coding。我特别好奇的一件事是，美国当下最热门赛道，AI Coding 一定算其中之一。我看到至少几十家创业公司在做，拿到上亿美元融资的公司都有好几家。国内与此同时几乎没有，这是为什么？

张海龙：国内不能说没有。我们当时做 Coding 时，你去卖给客户，客户招投标，会发现国内有很多传统 ISV 能做。因为 GitLab 开源了，很多人可以贴着客户需求魔改开源项目。

现在 AI Coding 相关工具也是一样，大厂每个都在做。只是很多都做得太浅，也没有进入国内主流资本视野。

我觉得国内很多是在卷 PMF 之后的事情，海外更多是在卷 PMF 之前的事情。PMF 之后，国内有一帮人杀进来。东西看清楚了，大家知道怎么做了，就开始卷。

### Copilot 与 Agent 的区别

张海龙：很多人会混淆 AI Coding 里的不同形态。现在真正跑通商业模式的是 Copilot。

Copilot 是什么概念？它还是工具范畴。需要一个人用这个 Copilot 去生产更多、更好的代码。本质上，Copilot 是减少你打字，也就是代码补全及其衍生品。

很多 Copilot 还会做问答等功能，但这些不重要。真正看 Cursor 为什么火，本质是补全补得特别好。

Agent 是完全不一样的概念。它是一个独立完成任务的个体，不用你管。一旦领到任务，它会自己想办法 figure out 怎么做、做什么、怎么改，最后完成任务，包括提交代码。

也就是说，Agent 和人的工作是异步的。人可以睡觉，人可以不在。这也是为什么 Agent 赛道叫 digital worker，它是数字员工。

Copilot 是同步的，你用的时候人必须在场。

我一直把 Copilot 比作电钻。以前拧螺丝，需要用螺丝刀慢慢拧；现在 Copilot 来了，像电钻，很快就进去了。

但 Agent 的逻辑是：这个螺丝我已经拧了一万遍，我不想拧了，我有个小弟帮我拧，我去干别的。

### GitHub Copilot 跑通了两个 PMF

张海龙：Copilot 赛道国外卷了很多年。GitHub Copilot 最大的贡献是找到了一个合适的 PMF。这里的 PMF 有两个：product-market fit 和 product-model fit。

它找到了产品应该以什么形式出现，以及在什么场景下出现：寄生于 IDE 的插件，在用户打字时润物细无声地出现。

它也找到了收费方式。

GPT-3 时就有类似产品，但做得不好，很多人用完后弃用。真正大规模商业化，被大家认识到并开始付费，是 GPT-3.5 出现以后。也就是说，模型到了那个份上，这个设想的场景才成立。

GitHub Copilot 的贡献是找到这两个点。但一旦这两个点被找到，它就变成大家都会的东西。国外以前有 Tabnine，后来有 Codeium、Ament 等公司。

这些公司大多是在 Copilot 的现有形式上做一点改进，或者做垂直领域化。

### Cursor 的产品创新

张海龙：Cursor 最大的贡献在于，它在 Copilot 基础上颠覆了交互形式。虽然沿用了 Copilot 的 PMF，但在产品体验上做了比较大的创新。

曲凯：展开讲一下 Cursor 的产品创新，也顺便解释一下 IDE。

张海龙：IDE 是 integrated development environment，集成开发环境。可以理解为程序员用的特别专业的 Word。普通打字用记事本就可以，但专业排版需要 Word；程序员写代码，需要 IDE。它不只是打字，还有运行、debug、调试等功能。

我其实不觉得 Cursor 能称为一个 IDE 公司，这是误解。Cursor 99% 的东西都是 VS Code 开源后直接复用。它更多是因为没有在现有 VS Code 上做插件，而是 fork 了 VS Code 的代码，然后魔改成自己的 IDE。

它 IDE 的内核不是自己做的，而是改了 IDE 的一些用户体验。

为什么要这么做？因为 VS Code 插件机制比较受限，限制了插件能做什么。Cursor 想做的事情，在插件机制上不能实现，被束缚住了。所以它必须魔改代码，实现想要的效果。

这条路很大胆。去年他们成立开始干这件事时，很多人不看好，觉得这条路太难。但 anyway，人家跑出来了。这也是创业迷人之处：这么不靠谱的项目，也能跑出来。

Cursor 打破的非共识是：GitHub Copilot 只能往后补全，也就是你打到这一行这一列时，它帮你补后面几行。

Cursor 的巨大假设是：这不够。我们要做整个文件的全局补全。当我改某个变量、某个函数时，相关地方都应该同时改掉。扩展一下，整个项目其他文件也可能要同时改掉。

它本质上就是在干这件事。

你用 Cursor 爽的一点是，当你打字打一半，它会补全；同时页面上好几个地方也出现补全。你要做的只是 tap、tab，补这里，再跳到下面一个位置，整个文件好几个地方都改掉。

这是以前没有的体验。

### Cursor 为什么体验好

曲凯：它这个补全更多是简单参数替换，还是会自己 debug、做很多衔接或修改？

张海龙：它不会 debug，本质上还是纯文本修改。它根据上下文，以及当前修改打的几个字，猜测你要干什么。猜出来后，把你要干的结果提前通过大模型生成出来。

然后它会把生成好的东西和当前编辑文件做一个非常快速的 diff，也就是差异比较。它告诉你：第三行、第十八行、第五十七行是不是要改这些，改完是什么。

体验好在猜测延迟非常低。它用各种办法，把延迟控制在 0.5 秒以内，让你感觉好像是瞬时的。你要做的就是确认、确认、确认。

曲凯：这感觉用在法律文件、律师场景也很适合。

张海龙：对，这就很合理。

曲凯：当时大家为什么不信？

张海龙：有几个原因。

第一，它没有自己的模型，用 GPT 或 Anthropic。

第二，它没有自己的 IDE，用别人的。

某种意义上讲，它拿着微软的 IDE，用微软投资的模型，去 PK 微软的 Copilot。而且 GitHub Copilot 已经非常成熟，大规模商业化，所有开发者都在用。

你觉得这个故事通吗？在国内肯定不通，在美国听起来也不通。

我写过一篇文章，讲美国大厂反应慢是创业者的巨大优势。

Cursor 核心就是把体验做得特别好，大家觉得好用，就传开了。而且它要的体验，恰好是 GPT-4 都做不出来，要 GPT-4o 或 Claude 3.5 Sonnet 才能做出来。

它一直坚持要做这个体验，想各种办法，等啊等，终于等到 Claude 3.5 Sonnet 出来。这个模型非常适合这个场景，所以也有一定运气元素。

但其实 AI 产品没有那么玄妙。扒开 transformer 看原理也没那么神秘。一旦被证明可行，谁都能做。但干得好是另外一件事。

Cursor 也是一样，不是里面有特别玄妙的高科技，都是工程。问题是你能不能提出正确问题。Cursor 在 2023 年提出了正确问题，等到 2024 年基础设施改进，这个问题能被解决。

### GitHub Copilot 为什么没立刻跟进

曲凯：与此同时，GitHub Copilot 有做任何事情吗？

张海龙：这件事情令人困惑。Cursor 怎么做已经不是秘密，但 GitHub 没有跟进。

我跟微软开发者相关部门的人聊过，他们内部其实也不是很着急，因为这东西不是很 hard core。他们不做，可能有几个原因。

第一，它是插件做不出来的东西。GitHub Copilot 如果要做，得先把 VS Code 的插件机制完善一遍，才可能在现有基础上做出 Cursor 的体验。

这可能阻止它快速模仿。但我觉得它一定会做，只是反应慢一点，没有理由不做。

### Agent 还没有 PMF

曲凯：最近的 Bolt.new 也是 Copilot 方向上的延伸吗？

张海龙：Bolt.new 可能不能算 Copilot，有点像 Replit Agent。你告诉它要做什么，它帮你把代码、开发环境都搭好。

曲凯：正好进入 Agent。Agent 代表性公司有哪些？

张海龙：严肃意义上，我认为 Agent 没有跑通 PMF。两个 PMF 都没通。

第一，product-market：Agent 在什么场景、以什么形式存在、怎么和人交互、怎么定价，一切都不清楚。

第二，product-model：Agent 到底需要什么模型、什么能力，才能让这件事 work，也不清楚。

所以 Agent 赛道虽然拥挤，但我目前看到没有 PMF。

如果真的 PMF 了，你会看到大江南北都有像 Cursor 这样口碑传播特别好的产品。

曲凯：Bolt.new 确实有人在传、在用。

张海龙：这个赛道有很多 PR。Devin 出来时，也有很多人在传。你要看留存。很多 Agent 产品上来一波宣传，看起来很炫酷。但本质上要看你要解的问题底层是不是 ready。

如果底层不 ready，所有解这个问题的人都不用看，因为不可能做出来。

Devin 算是从 PR 层面让 Agent 进入视野，但目前也没有看到特别好的产品。

### 不要做“什么都能干”的 Agent

张海龙：Agent 赛道里很多公司拿了很多钱。比如 Ament 做 Copilot，Magic、Cognition 这些典型公司要搞模型。我认为非常困难。

你不用 OpenAI，不用 Anthropic，不用任何一家，自己搞模型，本质上就是挑战整个 AI 赛道格局：我是不是能做一个自己的模型，for 这个领域，比通用大模型更好。

我对这件事持巨大怀疑态度。因为 intelligence 这件事可能就是需要很大的模型、更通用的模型来实现。垂直应用更多是在上面做 engineering、RAG、fine-tuning 等。

我们不做 pre-training，很多应用公司也不做。

为什么还要做 Agent？因为 Copilot 还是工具，而 Agent 市场是劳动力，它自己就是 labor，这是完全不一样的体验。

比如有一篇论文，里面讲了一个算法，你想试试这个算法靠不靠谱，甚至把代码移植到某个项目里。你可以把 PDF 扔给 Agent，说：帮我把 PDF 里的算法弄一下，做点测试数据，看执行结果。

Copilot 做不到。这相当于给小弟安排了一个任务。输入明确，输出也明确。理论上，小弟可以自己搜索网站、编译、运行、调试代码，最后给你报告。

这就是我们想做的 Agent 逻辑。

### 找窄切入点：unit test

张海龙：做 Agent 赛道有很多不同切入点。不靠谱的切入点，是 Devin 那种：做一个 Agent 啥都能干。

硅谷这边基本形成共识：现在如果做一个 Agent，说什么都能干，基本上就说明你什么也不能干。

更现实的是找到细分切入点，让 Agent 只干一件事。

Code Agent 里，有人做 code review，有人做写 documents，有人做重构。我们现在要做 unit test，因为我们觉得它可能是最容易落地，准确率最容易做高，甚至比人都高的场景。

Unit test，单元测试，就是你写了一段代码后，要确保这段代码正确，于是写另一段代码去测试它的输入输出是否符合预期。

比如写了一个排序算法，我输入 1、3、9、7、6，它能不能输出 1、3、6、7、9。

单元测试最大的作用是防止 regression，也就是这段代码本来运行好好的，但系统复杂，后续开发中有人为了别的原因修改，改完后破坏了之前某个功能。

系统大了以后，可能有几十万个功能，功能之间关系复杂。Unit test 是保证改这个东西时，原来的东西不被改坏的有效手段。

为什么我们觉得它能做？

第一，防止 regression 有价值。当然对小团队价值不一定大，更多是 enterprise。

第二，开发者不愿意写，因为这东西很无聊。写功能代码还有成就感，但写 unit test 是组织输入输出、做周边配合工作，不太好玩。

所以大部分团队单元测试覆盖率都很低，基本在 30% 以下。能不写就不写，实在不行再写。

这种人不愿意干的活，是不是可以让 Agent 去干？我不是抢你饭碗，你都不愿意干，那我来干。

另外，它对软件工程其他信息的需求相对低。比如你这个业务到底是抖音还是美团外卖，关系没那么大。Unit test 已经被实践几十年，有套路。不同团队里的工程实践也比较接近。

这两件事让我们觉得，它有可能做成一个相对通用的 Agent 来解决这个问题。

### Copilot 与 Agent 会并存

曲凯：按这个思路推演，Copilot 和 Agent 能够并存吗？还是 Agent 起来后 Copilot 会消失？

张海龙：我觉得这是两件完全不一样的事情，Copilot 会一直存在，并且很重要。

你找了个小弟去拧某个螺丝，不代表你不需要一把电钻去拧更复杂的螺丝。

我依然坚信人很重要，软件工程师很重要。AI 把程序员干下岗这种事情我不信，除非你本来水平很差很差。

只要人还存在，Copilot 就很重要。Copilot 确实帮人解决问题，提高效率。就像科幻片里，人需要一套很牛逼的装备打怪，同时还可以带一帮机器小弟。

### 不相信“代码平民化”

曲凯：你是不太相信 AI Coding 能力未来会高级到，一个人说帮我搭一个 TikTok，就自动完成？

张海龙：我不信。我不信任何把代码平民化的东西。

第一，软件工程历史上这件事没有成功过。很多人尝试过各种办法，最后发现所有低代码、无代码产品都只能局限在很小领域，才有商业价值。没有出现过任何一个把软件工程门槛大幅下降，并大规模广泛使用的产品。

第二，普通人没有写代码需求。很多人觉得，如果降低门槛，就会有 1 亿人写代码，这也是 Replit 的 vision。我以前深信不疑，但从去年开始动摇了。现在已经不相信这个 vision。

因为普通人不想写代码，普通人想喝咖啡，想拍美美的照片，想兜风。甚至他连跟程序员说话都觉得累。

这不符合人性。

写代码依然会是小部分人创造大量软件，让大部分人使用。如果一个东西变成特别 common 的需求，就会变成一个独立软件，就像现在 SaaS 一样。

只有非常小、没有办法普世的需求，可能找朋友帮你弄一弄。

一句话做 Agent，我也不相信。复杂 Agent 背后的工程复杂度远超想象，不是说两句话、拖几个方块就能做出来。

如果一个需求 common 且简单，那就是 ChatGPT 的生意，不是你的生意。

### 模型进化不会消灭应用

曲凯：最终模型本身和这些 Code Agent 的关系会怎样？ChatGPT 现在也集成开发环境，Anthropic 也有 Artifacts，ChatGPT 有 Canvas。

张海龙：这些都是轻量级的，在办公白领场景下做一些事情。比如你用 Notion，在里面插入代码片段，这种程度普通人可能就够了。

我们去年做过类似“一句话生成应用”的产品，踩过坑。做过很多方向，最后发现这也不 work，那也不 work。

后来想明白，不要天花乱坠，不要有太多幻想，不要想科幻片，要想商业片：到底怎么商业化，怎么真的产生生产力价值。

往这个方向想，会越来越窄，找到一个劳动力最重要的品质：可靠。

一个实习生不太能干，可能可以忍；但经常不靠谱、瞎折腾、浪费你时间，就不能忍。

我们现在做 unit test，有客户在试，我们自己也在用，感觉这条路有可能通。

至于 GPT-5、GPT-6、GPT-10 会不会让上面应用都没意义？我现在很坚定地认为不会，除非真正 AGI 出现。否则 AI 进展更多是在准确率、上下文长度、速度、聪明程度上提升。

一个再聪明的应届毕业生，也很难直接在公司产生价值。进公司后要培训，要理解公司干什么、为什么、怎么干活。

软件工程有两个重大问题：业务上下文和工程上下文。这两个问题无论模型怎么进化、怎么 training，都不可能自动解决，因为它们是 domain-specific、company-specific、team-specific 的。

模型进化只能正向促进 Agent：本来 Agent 有 80 智商，现在有 100。你把合适信息给它，它会更快 pick up，更好解决实际场景问题。

### 未来还要不要学编程

曲凯：这回答了一个问题：未来还要不要学编程？按你的讲法，肯定还是要。

张海龙：肯定要。我不确定未来编程教育会演进成什么样，但目前坚定认为，程序员依然是会被需求的岗位。

量有没有那么大、类型会不会变化，现在不好说。

曲凯：你完全不相信未来会有 C 端用户用它做东西？

张海龙：我不相信。如果这件事成立，那也是 ChatGPT 的事。ChatGPT 直接成为超级 Agent，帮你干很多通用事情，比如订机票。但我没想清楚模型能力如何让这件事特别靠谱。

### Evaluation：数字员工上岗考试

张海龙：我们花很多时间 build evaluation，也就是如何评估 Agent。

你制造了一堆数字员工，上岗之前得有考核方式。

以 unit test 为例，你真正考核一个人，不能只问一道题。所以很重要的一点是 build 题库。

我们会拿开源仓库、自己的仓库、早期客户的商业仓库，综合起来，在里面找不同语言、不同框架、不同类型写法，整理比如 1000 道题。

每次 Agent 改进一版，就跑这 1000 道题，看做对多少道。这是一件非常耗时的事，因为这些数据以前不存在。

### 硅谷 AI 生态：各层都很热

曲凯：你这几个月都在硅谷。从你的视角看，整个硅谷的 AI 发展情况怎么样？

张海龙：硅谷目前每个层面都非常欣欣向荣。我不是说投资额多少，而是项目种类多样性和数量丰富程度，各种奇怪东西都有人做。

AI 鉴定假发、AI + 时尚、AI + 选品，全都有成立的公司、拿了钱，而且是正儿八经项目，不是抖音搞教程。

更硬核的是 infrastructure 层，卷得非常严重。我不确定，但 infrastructure 这一层投入可能比国内高 10 倍以上。

当然 AI Coding 这一层也很热。美国反而做模型的比较少，主要就剩那几家。

回到最早的问题：为什么我们都在用海外的东西？因为人家投入得多、投入得早。

### 美国 SaaS 付费生态

张海龙：我在硅谷待得越久，发现自己买的 SaaS 越多，因为没办法必须买。

比如 LinkedIn，高级版有些功能要用；Zoom 要开会，不能一个会 45 分钟就到上限；Calendly 用来约会，邮件来回约很累，直接发链接是 common practice。

各种东西越买越多，全是 SaaS，被逼的，没办法。

在国内几乎什么 SaaS 都不买。但老美这边某种意义上效率比国内高，这些 SaaS 工具确实带来提效，而且没有免费可选项，所有人都收费。

国内竞争维度不一样，可能上来就免费，导致大家都收不到钱。也有文化习惯差异。来了以后，就自然而然开始买这些东西，因为别人都这么干，你会照葫芦画瓢。

这也是为什么我们产品商业化想在硅谷做：付费意愿、付费能力、产品早期接受度都会高一些。

### 给 AI Agent 创业者的建议

曲凯：最后一个问题。如果给现在 AI 里的创业者一些建议，尤其你们去年走过一些弯路、踩过坑，你会给什么建议？

张海龙：我可能没有足够信息给所谓建议，因为找 PMF 的困难度比我想象中高太多。好的是别人也没找到，坏的是我们也没找到。

但我为什么一直还有信心？因为我不觉得我们的认知落后，或者技术落后。

我的感受是，对底层的理解特别重要。能自己看论文就自己看，能自己手写就手写。到一定程度，再用现成工具或 infrastructure，才会真正给你带来价值。

因为这是一个新领域，不像软件工程已经做了几十年，大家熟门熟路，上来就应该这样那样。

如果你一上来就开始用别人铺好的东西，不理解底层很多东西，你可能以为某些问题解不了，但实际上可以解。你自己做了以后会有体感，而这个体感会对你的认知产生很微妙的变化。

某天你遇到一个问题时，这种体感带来的微妙变化就会起作用。

我们很大的收获，来源于去年开始大量做底层。所以这不是泛化建议，只是我们的路径。
