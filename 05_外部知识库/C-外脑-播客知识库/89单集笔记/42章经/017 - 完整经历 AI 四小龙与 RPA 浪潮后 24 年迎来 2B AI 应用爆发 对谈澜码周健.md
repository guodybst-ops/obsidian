# 017 - 完整经历 AI 四小龙与 RPA 浪潮后，他觉得 24 年会迎来 2B AI 应用的爆发｜对谈澜码创始人周健

## 摘要

42 章经请到澜码创始人周健——拥有 ACM 冠军、Google、阿里云创始团队、AI 四小龙依图 10 号员工 + 7 年（带过 1000+ 人）、宏基 RPA CTO 的完整履历，2026 年初因 ChatGPT 出来当即决定创业、做下一代 To B 业务流程自主化。核心观点：(1) AI 1.0 失败的关键不是技术——是 CV 不是通用技术，安防场景到天花板后没有商业模式弹性，最终被海康威视用国家标准社会资源碾压。(2) 大模型 ≠ 单点工具，是**通用智力**——把治理变成生产力，可以变成「专家时间」，这给了商业模式新空间。(3) 大模型与四小龙最大不同——四小龙必须端到端打通，而大模型公司**只能围绕生态链竞争**，因为头部企业找上来根本服务不过来。(4) 当下 To B 真正落地的应用只有四类：知识问答、指标查询、任务完成、流程提醒——只有代码生成是 PMF 已成立的。(5) **RPA 不应该再被讨论**——它没有理解数据的能力；流程自主化是任务自主化升级版，需要 Agent 来做。(6) **CPU → GPU 的价值链迁移**——5 年内企业 IT 预算的 30% 会从 CPU 切到 GPU；银行已经投亿级算力。(7) 央国企买完算力反过来会要求「我已有 10 张卡，你的应用要把利用率提升 10%」——这个奇怪的逻辑只在当下成立。(8) 大 B vs 中小 B：现在只能做大 B + 部分中小 B 标准岗位（招 3-5 年工程师）——技术不通用导致没法服务长尾。(9) AI Agent 真正缺的是**「世界模型」**——预训练模型只能从语料学，但企业内部的「武汉地区 Java 工程师薪酬」这种数值经验它没有。(10) 这一波 AI 最缺的不是模型，是**好的 AI 原生产品经理**——产品多了一个维度叫「数据集」。(11) AGI 周健持不可知论——倾向于「人机协同 / 人机融合」最终是大脑 offloading，而不是 AI 接管人类。

### 2. AI 1.0 失败的真正原因——不是技术，是商业模式

- **CV 不是通用技术**——在企业内只是「点状」，无法拿到「面状」业务。
- 依图找到的 PMF 是安防——但安防是孤立场景，新场景不断解锁能维持高毛利，**到天花板就后继乏力**。
- 真正杀死四小龙的不是友商之间——是**海康威视用国家标准 + 社会资源降维打击**，依图准备做的事被国标一夜圈走。
- **教训**：到达体量以后，不是拼技术，是综合性商业竞争；当年早期投资人和创业者过度技术理想主义，世界比想象复杂得多。

### 3. AI 2.0 与 1.0 的本质差异

| 维度 | AI 1.0（四小龙） | AI 2.0（大模型） |
|---|---|---|
| 突破点 | 计算机视觉 | 自然语言理解 |
| 通用性 | 点状、垂直 | 通用智力，各行各业各职能都能用 |
| 商业模式弹性 | 安防到顶就没了 | 把治理变生产力，把生产力变专家时间，**有持续打开商业模式的可能** |
| 价值链位置 | 必须自己端到端打通 | 偏底层技术，**横向整合靠生态链** |
| 竞争方式 | 端到端正面对抗 | 头部企业自己服务不过来，**竞争以生态链为单位** |

### 4. To B 真正落地的应用只有四类 + 一个 PMF

- **PMF 已成立**：代码生成（GitHub Copilot、智谱代码模型、CodeGeeX 等）。
- **有价值但成本未盖过价格**的四大类（澜码给客户的总结）：
  1. 知识问答
  2. 指标查询
  3. 任务完成
  4. 流程提醒
- **当下的真相**：更多是政策引导大家拥抱，而不是商业价值已经超出成本。

### 5. 资本游戏的镜像——四小龙剧本正在大模型公司重演

- **当年商汤策略**：把所有钱拿了，把所有好人招了，慢慢发展。
- **机构站队**：钱集中在头部，给 A 就不给 B；逼大家先抢最大那一笔。
- **本质判断**：过去多年市场不是面向用户，是面向资本——垄断资本式发展路径。
- **大模型四家**（智谱 / 百川 / Moonshot / Minimax）+ 月之暗面、阶跃星辰——剧本相似度极高。

### 6. RPA 的判决书 + RPA + AI 组合并不成立

- RPA 本质是**用 accessibility 技术模拟鼠标操作**，是「爬虫的高级版」。
- **不是技术壁垒，是经验性壁垒**——不同行业 IT 系统框架不同，靠多年踩过的坑积累。
- **RPA 解决的是任务自动化**——人知道怎么做，只是偷懒不想一步步干。
- **流程自动化 = 任务自动化 + 人与人协作**——协作必须理解语言，RPA 不行。
- **「RPA + AI」其实并不对**：RPA 偏系统连接，对数据没理解；大模型擅长文本，结合点目前只在流程提示——内部小事，跟外部协作无关。
- **结论**：「RPA 应该慢慢不被讨论了。」

### 7. 低代码也会被封死天花板

- Java/Python/JavaScript 这些语言不应该再有大量人去写。
- **方向**：出一种「声明式语言」，像当年数据库出现 SQL 一样——人描述问题与思路，至于用 RPA / DB / BI / Prompt，**交给机器决定**。
- 低代码不会消失，**但天花板会被封住**。

### 8. To B 这一波卡住的不是技术，是产品思路

- 「To B 里现有技术已经够用——是开发厂商思路的转化、探索、摸索需要时间。」
- 套 AI 壳的逻辑只在 C 端成立，To B 不需要假装。
- 周健把澜码定位在**下一代 To B 产品应该长什么样**这个问题上。

### 9. 在依图踩到的两个深坑——做澜码会用上的教训

**坑一：技术驱动公司容易自嗨**
- 2018 年人脸识别（演唱会场景）在多城达到 PMF，年终奖很好、团队亢奋。
- 春节前老板拿来几份国标——海康威视已经把后续要做的事用国标圈了。
- **「人家根本不跟你在你的战场上玩。」**
- 现在做 AI 这一波，最后最大的竞争者可能也是浪潮或某些大公司。

**坑二：组织从 10 人到 2000 人的踩刹车关**
- 创业成功一般 7-10 年，老兄弟（子弟兵）会跟不上。
- 引入职业经理人有两个问题：(1) 他们没 0→1 经验，是「电梯往上走，他以为是俯卧撑使的」；(2) 他们是雇佣军，upside 没事，**踩刹车时职业经理人最容易走**。
- 老兄弟是压舱石——如果处理不好，老兄弟先走，组织基石就坏了。
- **「踩刹车那一关，是所有创业公司必经的一道坎。」**

### 10. 创业的「慢变量感知」是核心难度

- 创业难在判断**新变化**：技术尺度、社会反应、行业 merge 速度、甲方变化速度——每次速率都不一样。
- 案例：周健去年花了 20-30% 时间做品牌——按过去经验是不对的；但现在很多央国企真的通过邮件主动找上门——**赌对了，全社会的关注大到这个地步**。

### 11. CPU → GPU 的价值链迁移（核心判断）

- **判断**：5 年内企业 IT 预算的 30% 会从 CPU 切到 GPU 这条线（算力 + 模型 + 应用 + 中间件）。
- **当下证据**：四大行 / 股份制银行投在算力上是亿级，大模型采购单基本千万起。
- **奇怪的甲方逻辑**：客户先投了 10 张卡，反过来要求「你的应用要把利用率提高 10%」——价值反转，**只在当下市场成立，一年后就没了**。

### 12. 大模型应用的「企业级管控」是甲方刚需

- **场景错配组合**：单应用单模型 / 单应用多模型 / 多应用单模型 / 多应用多模型；财务月底用得多，HR 招聘季用得多——QPS 错峰调度、LoRA 编排都是真问题。
- **甲方做不了，大模型公司不能做**（大模型公司一上场就把自己的模型绑过来）。
- **30 万、100 万级别的项目可以不考虑，但亿级单子甲方一定会想这件事。**
- 「新质生产力」的治理、运营、培训怎么建——这是央国企真实诉求。

### 13. 大 B vs 中小 B vs 私有化

- **大 B**：私有化定制贵，但能买 1000 张显卡——澜码可以在大 B 平台上锤炼产品，**换来 enterprise quality**，比友商有领先优势。
- **中小 B**：现在做不了——技术不通用，单个岗位（如招 3-5 年工程师）只在大 B + 部分有重复岗的中小 B 上立得住，财务、HR 看似通用其实每家都个性化。
- **未来要变成毛利高生意，必须解长尾**；但现状是**「先占根据地」**。

### 14. 澜码现在做什么 + 为什么是它跑出来

**做什么**：
- 业务流程自主化（替代 RPA），用 AI Agent 技术。
- 主要场景：企业内部后台办公、职能类（财务、HR），不做营销 / 生产类。
- 客户：央国企为主，To G 仅一两单。

**为什么是它**：
- **时机**：2026 年 2 月就出来；3 人时就和金山办公 Excel 合作 GPT-3.5 + Excel 落地；早早拿到 IDG 投资，**比同行早一个身位摸到模型边界**。
- **节奏**：5-6 月已心里清楚现有模型能干什么；7-9 月跑各行各业 POC（零售、电网、政府、银行、保险、券商）；现在收回来聚焦银行、央国企的财务业务。
- **资源利用**：依图、宏基积累的商业化团队 + 行业人脉——主动 inbound 来了之后能精准发动。

### 15. AI Agent 真正缺的是「世界模型」

- 预训练模型只能从语料学经验——**「文本和视频学不会游泳。」**
- 企业内部数据是大数据 + 数值经验（如「武汉地区 Java 工程师薪酬」）——**预训练大模型是文科生，搞不定**。
- 澜码在做 Agent 的两件事：
  1. **环境感知**：能感知数据变更、文档替换、流程变化，作为上下文；
  2. **跟传统数值大数据结合**：让 Agent 既能读文本也能调数值经验。
- 周健最近写文章观点：**「AI Agent 还缺一个精确的世界模型。」**

### 16. AI Agent 算力 / 成本现状

- 公有云端（GPT-4）：1 元 RMB ≈ 1 万汉字。
- 私有云端（6B / 13B 模型）：1 元 RMB ≈ 200 万汉字——**差 200 倍**。
- 单应用调度有优化算法；多应用调度还没积累，估计还需 3-6 个月成熟。

### 17. 政策矛盾怎么办——列出来给人看

- 客户问：政策有冲突怎么办？
- 周健：**列出 A 和 B 给用户看，让人来定**——好在是给内部员工用，不是直接对外部客户交付。

### 18. 给 AI 创业者的建议

- 这一波最缺的不是技术，**是好的 AI 原生产品经理**。
- 过去做产品是二维的，现在多了一个维度——**数据集**。
- 端到端应用准确率能不能上生产，**难点全在如何定义数据集**。
- 看到很多老朋友带着错误的假设认知做 AI——这是完全不一样的范式。
- **「我反而希望友商更多——一家公司不断培训客户太累。把市场做大对所有人都好。」**
- 当年四小龙一开始也不觉得在竞争，**互相帮衬把资本市场和客户带起来**才是关键。

### 19. AGI / Transformer 的看法（不可知论）

- **Transformer 不是通向 AGI 的路径**——同意 Yann LeCun，需要世界模型。
- **AGI 持不可知论**：本质是「人类能否创造比自己更聪明的东西」的递归问题——西方对「奇点」的思考一直没停。
- 人类与机器的区别仍然巨大：
  - 进化：从无生命到有生命到自我意识，是一套递进；机器对应的强化学习、遗传算法都有，**但 SOTA 没整合在一块**。
  - 学习：人能小样本学习，机器需要大样本。
- **更倾向**：「人机协同 / 人机融合 / 人机共生」——大脑 offloading 到某些场景上，**放大人类智能**。
- **不太可能**：机器产生自我意识、接管人类社会。

## 关键问答

**Q1：你在依图带的时间最长，正好经历了 AI 四小龙的青年期。今天大模型也剩四家——会不会是同一个故事？**
A：当年最大的问题是 CV 不是通用技术，安防到天花板就完了。这一波不一样：(1) 自然语言理解是通用技术；(2) 大模型把治理变生产力，商业模式还会演进。但和四小龙最大区别是，**四小龙必须自己端到端打通，大模型公司只能围绕生态链竞争**——智谱已经服务不过来找上门的客户了，这个生态位本身就在。

**Q2：那为什么大模型公司收入比四小龙还少？**
A：To B 现在真正有 PMF 的是代码模型——其他知识问答、指标查询、任务完成、流程提醒都还盖不住成本。**更多是政策引导大家积极拥抱**，而不是商业价值真的超出成本。

**Q3：当年商汤的那套「先把钱拿了把人招了」的剧本是不是又在重演？**
A：是。机构会站队，给完 A 不会再给 B；这一波不是面向用户，是面向资本——这是垄断资本式发展路径。

**Q4：怎么用一句话解释 RPA？为什么说它不应该再被讨论？**
A：RPA = 模拟人对系统的操作，本质是「爬虫的高级版」，靠 accessibility 技术。**没有壁垒，是经验性技术**——多行业积累的工程落地。它**对处理的数据没有理解能力**，所以「RPA + AI」结合点只在内部流程提示。RPA 解决任务自动化（人知道怎么做只是偷懒），但流程自动化要解决人与人协作——必须理解语言。

**Q5：低代码呢？**
A：不会消失，但天花板被封住了。Java/Python/JavaScript 不应该再有大量人写——未来应该出声明式语言，人描述问题，机器决定用什么去实现。

**Q6：To B 的 AI 应用现状卡在哪——技术还是认知？**
A：**To B 现有技术够用了，卡的是开发厂商思路转换的速度**——不是技术不达标，是探索还没到位。

**Q7：在依图踩过最深的两个坑是什么？**
A：(1) 技术驱动公司容易自嗨——2018 年人脸识别 PMF 后，海康威视用国标一夜圈走，**人家根本不跟你在你的战场上玩**；(2) 组织从 10 人到 2000 人，**踩刹车那一关——职业经理人是雇佣军，老兄弟是子弟兵**，处理不好基石就坏。

**Q8：To B 这么久了，市场环境最大的变化是什么？**
A：这次区别是大家都特别热情，主动想参与；上市公司 CEO 半年见十几个不难。但热情很难转换成实际落地——容易做成「咨询 + 项目」。**真正不一样的是甲方先投了算力，反过来要求应用提高利用率**——这个奇怪逻辑只在当下成立，一年后就没了。

**Q9：为什么坚定做国内 To B？**
A：(1) 结构性 gap——国外有 Salesforce / ServiceNow / Workday 百亿美金体量，国内没有；过去是 low-hanging fruit 太多不需要管理要效率，现在地缘政治压力倒逼管理升级；(2) **To B 慢，但做进去就不容易死**——客户还在你就一直在那边解决他的问题。

**Q10：To 大 B 还是中小 B？**
A：现在只能做大 B + 部分中小 B 的标准岗位（如招 3-5 年工程师）——技术不通用，每家公司财务、HR 看似一样其实个性化定制成本太高。**好处是大 B 已经有 1000 张显卡，澜码的产品在那上面锤炼过，比友商有 enterprise quality**。

**Q11：为什么澜码这一年能跑出来，做的最好的地方是什么？**
A：核心是**时机 + 节奏**——2 月就出来；3 个人时就和金山办公 Excel 合作做 GPT-3.5 + Excel 落地；快速拿到 IDG 投资；5-6 月就摸清模型边界；7-9 月跑各行业 POC；现在收回聚焦银行 + 央国企。

**Q12：AI Agent 出来一年了，为什么落地这么少？真正缺什么？**
A：现有架构有结构性缺陷——**预训练模型只能学语料经验，文本视频学不会游泳**；企业内部的数值经验（如武汉 Java 工程师薪酬）大模型解决不了——它是文科生。澜码在补两件事：(1) 环境感知，主动观测数据变更；(2) 跟传统数值数据结合。**精确的世界模型——这是缺的核心**。

**Q13：模型政策有冲突怎么处理？**
A：列出 A 和 B 给用户看，让人来定。好在是内部用，不是直接对外部客户交付。

**Q14：算力成本差距有多大？**
A：公有云 GPT-4：1 元 / 1 万汉字；私有云 6B-13B 模型：1 元 / 200 万汉字——**差 200 倍**。单应用调度有优化算法，多应用调度还没积累，估计 3-6 个月成熟。

**Q15：今年 To B 会爆发吗？**
A：会。**技术不缺、用户需求都在、预算在投、算力在投、大模型在投**——中间缺的是好产品把这些应用做出来；产品打通了，水就灌过去了。

**Q16：对这一波 AI 创业者最大的建议？**
A：**最缺的不是技术，是好的 AI 原生产品经理**。过去产品二维，现在多了一个维度叫数据集——端到端准确率能不能上生产，全在如何定义数据集。我反而希望友商更多——把市场做大对所有人都好，当年四小龙一开始也是互相帮衬。

**Q17：你信 AGI 吗？Transformer 是路径吗？**
A：**Transformer 不是路径，同意 Yann LeCun 需要世界模型**。AGI 我持不可知论——本质是人能不能创造比自己更聪明的东西的递归问题。我更倾向人机协同 / 人机融合，**大脑 offloading 放大人类智能，但不太可能 AI 自我意识接管人类**。

## 润色版逐字稿

### 开场 + 嘉宾介绍

**曲凯**：今天很高兴请到澜码创始人周健。澜码是去年很多人提到的项目，是 AI + To B 领域里很有代表性的一家。周健的履历里我觉得几段最有意思：02 年首次为亚洲拿下 ACM 冠军；后来加入了谷歌；最有代表性的两段经历——一段是 AI 四小龙之一依图的 10 号员工；上一份是宏基（弘玑）RPA 的 CTO；去年开始出来做澜码。先请你简单自我介绍一下吧。

**周健**：好。学生时代拿过 ACM 冠军是个光环。一毕业开复老师就把我招到谷歌中国，但我很快去了美国，负责中文网页搜索质量调优，做了两三年。然后王坚从微软去了阿里，我加入阿里云的创始团队，负责底层存储的第一个团队。再后来就是 AI 1.0 时代在依图做 AI 产品和 AI 工程，再到一家做企业服务、业务流程自动化的公司做 CTO。

**曲凯**：你怎么想的就出来做澜码？

**周健**：下决心其实就是 ChatGPT 出来没几天。本身我也觉得业务流程自动化是一年内需要被解决的问题；今天有了大语言模型，是一种通用性技术，而且十分便宜可获得，整个技术可实现性高了很多——值得重新做一遍。

### 经历过四小龙——大模型这一波是同一个故事吗

**曲凯**：你在依图大概多少年？

**周健**：大概六七年，基本经历了它最快发展的青年期。当时我们叫 AI 四小龙——你看现在大模型大家讲的也是四家：MiniMax、百川、Moonshot、智谱，加上月之暗面、阶跃星辰之类。也有人不看好这一波，他们会拿四小龙的故事来讲：融了那么多钱，最后商业回报未必好。你正好经历过，怎么看？

**周健**：我觉得 AI 1.0 主要还是计算机视觉。CV 第一次证明了：人脸识别、OCR、工厂质检这些事不用过去那种很重的方式也能做。但 CV **不是通用技术**——它在企业内基本是「点状」的，很难拿到「面状」业务。依图找到的 PMF 是安防——技术不断演进、新场景不断解锁，作为技术领先方就能要求高毛利。但只在安防有这个机会——商业模式上没有给你弹性的可能性。**到天花板就后继乏力**——这是 AI 1.0 最大的问题。

现在很大区别：第一，突破的是自然语言理解，从 ChatGPT 来看是通用技术——文字各行各业各职能都用。澜码在做的事，是把大模型这种「治理」变成生产力，再变成「专家时间」——这时候适用面打开，商业模式也有可能改变，**两者兼有**。

对大模型公司来讲，跟四小龙又有不同：当年 CV 四小龙必须自己端到端打通，但大模型在价值链上**仍偏底层**——横向整合需要应用方或中间层接到各行各业。比如智谱，我知道好多行业的头部企业都已经找到他了——**他根本不可能服务过来**。这就有了生态位，竞争会复杂，**很可能大模型公司是要以生态链为单位来竞争**。

### To B 现在真正落地的应用只有四类 + 一个 PMF

**曲凯**：但当年四小龙至少还有不少实际收入，这一波大模型基本很少。

**周健**：对，现在两种：一种是 To B——真正有 PMF 的是代码模型（GitHub、智谱代码、CodeGeeX 等），价值是真的转过来了。其他的我给客户总结过四大类——**知识问答、指标查询、任务完成、流程提醒**——有价值，但价值还盖不住要付的代价。所以**更多还是政策在引导大家积极拥抱**，并不是商业价值已经超过成本。

**曲凯**：当年商汤的策略——把所有钱拿了、把好人都招了——这一波是不是又在重演？

**周健**：是。我前几天看一篇文章讲得挺有意思——这个市场其实不是面向用户，是面向资本，**垄断资本式发展路径**。机构会站队，**给完 A 就不会再给 B**——所以大家都赶紧把最大的一笔先拿了。

### RPA 是什么——为什么不应该再被讨论

**曲凯**：你从依图出来去了宏基，那两年 RPA 也很热。能简单解释一下 RPA 吗？

**周健**：RPA 本质是用一些技术模拟人对系统的操作——核心能力是：原来用户鼠标点击屏幕上某个按钮，RPA 通过技术让下次屏幕上一出现这个应用，机器就能选中并点击。**相当于是爬虫的高级版**——过去爬网站要写复杂程序，现在你点一下机器就能模仿。这能解决数字化转型里大量重复的「数据搬运工」工作。

**曲凯**：听起来好像没什么壁垒？

**周健**：它更多是经验性技术——不同行业 IT 系统的程序框架不一样，每个行业都得一个个啃过去。做过的行业越多，效率越高。**它是工程落地的活，不是深度技术**。

**曲凯**：那 OpenAI 现在做手机端 Agent，模拟人在 APP 上的操作呢？

**周健**：移动端难度更高——iOS 封闭性强。但有人用服务器虚机模拟手机端，**因为是虚拟出来的，权限问题反而可以解决**。OpenAI、腾讯、阿里、Adept（创业公司）都在试。OpenAI 用 Sora 那种「真引擎生成数据 + 学习」的暴力路线我不意外。但 Adept 拿了三四亿美金，工程副总裁出走，至今没放出 production——这事我不确信。

**曲凯**：很多人说 RPA + AI 是好的结合？

**周健**：我觉得**并不对**。RPA 偏系统连接，**对处理的数据没有理解**；大模型擅长文本处理。所以现在能看到的 RPA + LLM 结合点，**基本只在 RPA 流程的提示**——是内部小事，跟外部协作关系不大。RPA 解决的是任务自动化——人知道怎么做，只是偷懒不想一步步干。但流程比任务多了一个东西——**人与人协作**。协作必须理解语言，所以 **RPA 应该慢慢就不被讨论了**。

低代码也一样——不会消失，但天花板被封住了。Java/Python/JavaScript 不应该再有大量人写——以后应该出一种声明式语言，像 SQL 一样，人描述问题和思路，至于用 RPA、DB、BI 还是大模型 prompt 实现，**交给机器决定**。

**曲凯**：但现在 AI 本身还没到内部，所以大家拿点 AI 套个壳？

**周健**：在 C 端可能是这样，但 To B 不是。**To B 现有技术其实够用了——卡的是开发厂商思路的转化和探索的速度**，不是技术问题。所以澜码站在「下一代 To B 产品长什么样」的位置上来做。

### 在依图踩到的两个坑——做澜码会用上的教训

**曲凯**：从依图、宏基到现在创业，你觉得有哪几件事是当年的经验现在用得上？

**周健**：第一件，在依图是技术驱动公司，内部很「自嗨」——很 enjoy 自己的成长。2018 年人脸识别在很多城市的演唱会场景达到 PMF，整个团队那年很兴奋。但快到春节，老板拿来几份国家标准——海康威视已经在这个领域制定了国标。**依图准备后面要做的事，海康用国标一夜圈走了**。这件事印象太深——**人家根本不跟你在你的战场上玩**。海康作为大公司能动用的社会资源比你大很多。**到达某个体量以后，就不只是拼技术了——是综合性商业竞争**。最大的竞争者不是四小龙之间，是海康或类似的大公司。我现在做 AI 这一波，最后最大的竞争者也可能是浪潮或者类似的。

第二件是组织。我走时依图 1000+ 人，最多到过 2000。CEO 一开始离一线员工很近、组织有活力。但创业成功一般 7-10 年——一开始的「老兄弟」肯定有弱点、跟不上，必然要引入职业经理人。这有两个问题：(1) 职业经理人没 0→1 经验，是从成熟体系里来的——**「电梯往上走，他以为是俯卧撑使的」**；(2) 职业经理人是雇佣军，老兄弟是子弟兵——upside 时大家都好，**踩刹车时职业经理人最容易走**。这时候老兄弟是压舱石。如果处理不好，老兄弟先走，组织基石就坏了。**所有创业公司都要过踩刹车这一关**。这次我先要让公司飞起来；但很快就要考虑怎么平稳 landing、怎么做到现金流为正。

### 创业核心难度是「慢变量感知」

**周健**：创业的难，是判断**新变化**——你赌对了一些非共识的事，但这事到底是什么尺度的，会给客户、社会、技术、产品带来什么变化——**这是难的**。我经历过深度学习、RPA，这是第三次了，但感受跟前两次不同。

举个例子——去年我花了 20-30% 的时间做品牌。**按过去经验这是不对的**——你这么花下去效果不会那么好。但现状是很多央国企真的通过邮件主动找到我了，说明我赌对了——**全社会对人事感的关注大到这个地步**。

慢变量很多：社会反应、技术成长速度、行业 merge 水平、甲方变化速度——每次速率不一样。**怎么感知到温度并提前预判，这是挑战，也是有意思的地方**。

### 这一波 To B 真正不一样的地方——甲方先投算力

**曲凯**：依图是市场好的时候拿榔头找钉子；宏基是市场好、但偏工程落地；现在 AI 也是市场热点高、也有点榔头找钉子，关键这个榔头还不太好用。

**周健**：这次区别是大家都特别热情，**所有人都动起来**——去年上半年我通过各种关系，很容易就见到十几个上市公司 CEO，每个人都很关心。Sora 这种事情会引起他们巨大变化。但热情很难转换成实际落地——To B 在行业早期容易做成咨询 + 项目，有时这是不可避免的。

但这次真正不一样的是——**他们会先投算力**。投完算力之后责任和压力就到他们这边——他给领导汇报「我花了 3000 万」，领导问「做了啥」，他说「做了个企业知识问答」就交代不过去。这时候算力本身应该是我们价值的一部分；**今天反过来了——客户已经有 10 张卡，要求我把利用率提高 10%，我从那 10% 的价值里分**。这个逻辑很怪异，**只有在现在这个阶段成立**——一年以后估计就没有这种机会了。

**曲凯**：澜码现在主要是 To B 还是 To G？

**周健**：To G 很少，主要是央国企。

### 为什么坚定做国内 To B

**曲凯**：很多人做 To B 久了就不想做了，国内 SaaS / To B 这几年又是泡沫又是泡谷。21 年最夸张时 SaaS 估值能到 PS 50-60 倍，现在 5-6 倍都合理。你为什么仍然坚定做国内 To B？

**周健**：第一，**国内 To B 跟海外有巨大 gap**——C 端阿里腾讯跟谷歌 Facebook 大概差 3-5 倍；但 To B 这头 Salesforce、ServiceNow、Workday 都是百亿美金体量，国内是巨大空白。我不觉得中国管理水平不需要这样的软件——过去 low-hanging fruit 太多，经济发展不需要管理要效率；现在地缘政治压力倒逼管理升级。**结构性机会就在这。**

第二，**To B 慢，但做进去就不容易死**——客户在你就一直在那边解决他的问题。

### To 大 B vs To 中小 B

**曲凯**：现在国内机构一听 To 中小 B 就否了。

**周健**：国内 IT 预算分布问题——基本都来自央国企。今天 AI 这一波生产力还不通用——我们做招聘只能针对招 3-5 年工程师；这种「单个岗位有重复性」的需求只在大公司和**部分中小 B**有。财务、HR 看似一样，每家都有特殊性，**个性化定制成本太高，今年还做不到**。

如果做大 B，私有化定制的钱也躲不过去。但好处是——**我们这种创业公司没钱买 1000 张显卡，但大 B 已经买了**。**我的产品在 1000 张卡的平台上锤炼过，就比友商有 enterprise quality**。所以现在是有他需要个性化的部分，但也换来产品质量上的领先。未来要变成毛利高的生意肯定要解长尾，但**现状是先占根据地**。

### 澜码现在做什么 + 为什么是它跑出来

**曲凯**：澜码这一年收入听说还不错。到底落地了什么？

**周健**：场景大家应该都见过——问答 + 数据查询 + 自动完成任务，三大类。我们做的是控制合成类，不做生产类（如营销）。**主要解决企业内部后台办公、职能类（财务、HR）场景**，今天蛮普遍。

但这些做下来变成大模型应用，**个性化定制开发成本不低**。对央国企来讲，今天有一个刚需是**企业级管理**——**以 CPU 为核心的价值链会迁移到以 GPU 为核心**。比如某行 250 亿 IT 预算，过去基本全是 CPU；现在大模型一定会投——**我相信 5 年内整体预算的 30% 会切到 GPU 这条线（算力 + 模型 + 应用 + 中间件）**。

那企业级管理就是怎么把过去 CPU 那套迁过来——单应用单模型 / 单应用多模型 / 多应用单模型 / 多应用多模型；财务月底用得多、HR 招聘季用得多——**QPS 调度、LoRA 编排都是真问题**。甲方做不了，大模型公司做了又会绑自己模型——**所以这种功能甲方特别看重**。

「新质生产力」治理、运营、培训怎么建——**30 万、100 万的项目可以不考虑，但亿级的他一定会想这事**。我知道四大行、股份制银行投在算力上是亿级，大模型采购单基本千万起。

**曲凯**：现在主要做内部知识库，是不是因为这个最容易落地？

**周健**：对。比如银行保险的差旅政策——「我去攀枝花，攀枝花算几级城市，政策是多少钱」——这种很浪费时间的事现在大模型能解决；保险产品推荐、保险条款问答也都是。

**曲凯**：去年也很多人想做这条路径，最后跟你们差距大。澜码做得最好的地方是什么？

**周健**：核心是**时机 + 节奏**——
- 2 月就出来；
- 我们 3 个人时就和金山办公（几十人）合作做 GPT-3.5 + Excel——**真实落地、奔着上线去**。这让我们一方面快速拿到 IDG 投资，一方面比同行早一个身位摸到模型边界。
- 5-6 月已经心里清楚现有模型能干什么，唯一变量是开源模型什么时候能用（Llama 2 还没出）；
- 7-9 月跑各行业 POC（零售、电网、政府、银行、保险、券商）——**摸感知**；
- 现在收回来——重点做银行 + 央国企的财务业务。

竞争上**大模型几乎不竞争，但跟大厂会有**。我们的商业化团队过去就一直在做——**主动 inbound 进来时我们能精准发动资源**。这是配合关系。依图、宏基积累的认知和人脉确实用得上。

### Agent 与世界模型——AI 落地的真正瓶颈

**曲凯**：你们对外的核心技术是 AI Agent。

**周健**：对，**用 AI Agent 技术做业务流程自主化**——过去用 RPA，现在用 AI Agent。

**曲凯**：但你刚才说 RPA + AI 不是好方案。

**周健**：要做到业务流程自主化，**关键是有环境感知**——能感知企业内部数据变更、文档替换、应用流程变化，作为解决任务的上下文。比如客户希望用拜访记录生成客户画像，再根据标准销售话术生成定制话术——这都是自主化能力（planning / tool use / 长短时记忆）——**有些信息需要被遗忘**（政策更新了）。这是现在的技术突破点。

**曲凯**：政策有矛盾怎么办？

**周健**：列出 A 和 B 给用户看，让人来定。好在不是直接对外部客户交付。

**曲凯**：AutoGPT 出来后 Agent 火了一年，但实际能落地的少。问题在哪？

**周健**：现有模型都是预训练——**只能学语料里的经验**。**你只通过文本和视频学不会游泳**——但 AI Agent 强调对世界模型的理解。这是已有架构的结构性缺失。

所以澜码在做：
1. **环境感知**——主动观测，比如客户问什么、销售反馈什么；
2. **跟传统数值大数据结合**——比如「武汉地区 Java 工程师薪酬空间是多少？要 propose 一个薪资」——**这种数值经验大模型解决不了，它是文科生**。

我最近写文章观点是——**「AI Agent 还缺一个精确的世界模型」**。这是做 Agent 必须要补的两个环节。同时大模型本身也在不停换——不像过去用 MongoDB 就一直 MongoDB——这是中间层的挑战。

### 算力成本现状

**周健**：这事还比较早期。一方面大模型自己也在优化成本。另一方面——**公有云端 GPT-4：1 元 RMB / 1 万汉字；私有云端 6B-13B 模型：1 元 RMB / 200 万汉字——差 200 倍**。本质上应用这端没完全打通——单应用调度有优化算法，多应用调度没积累，**估计还需 3-6 个月**。

### 今年 To B 会爆发吗

**曲凯**：所以今年 To B 应用会爆发？

**周健**：会。**技术不缺，需求都在，预算在投，算力在投，大模型在投，业务需求在那里——中间缺的是好产品**。产品打通了，**水就灌过去了**。

### 给 AI 创业者的建议 + AGI 看法

**曲凯**：经历过 AI 1.0 完整周期，对这一波 AI 创业者有什么建议？

**周健**：**最缺的不是技术，是好的 AI 原生产品经理**。过去做产品是二维的，现在多了一个维度——**数据集**。任何一个模型能力不够时，怎么把端到端应用准确率做到能上生产，**难点全在如何定义数据集**。我有不少师兄师弟在 AI 公司，他们身上还带着错误的假设认知——这是完全不一样的范式。

**我反而希望友商更多**——一家公司不断培训客户太累，大家把市场做大对所有人都好。当年四小龙一开始也不觉得在竞争——**大家互相帮衬把资本市场和客户带起来**。

**曲凯**：你信 AGI 吗？Transformer 是路径吗？

**周健**：**Transformer 不是。我同意 Yann LeCun——需要世界模型**。AGI 我持不可知论——本质是「人能不能创造比自己更聪明的东西」的递归问题——这是为什么西方有「奇点 / Singularity」这一思考脉络。

人类与机器的区别仍然巨大：
- 进化：从无生命到有生命到自我意识，是递进；机器对应的强化学习、遗传算法都有，**但 SOTA 没整合在一起**；
- 学习：人能小样本，机器需要大样本。

我更倾向「**人机协同 / 人机融合 / 人机共生**」——**大脑 offloading 到某些场景上放大人类智能**——这事我觉得一定会发生。但 AI 自我意识、接管整个人类社会这种——我更偏觉得不太可能。

**曲凯**：好，差不多了，感谢。
