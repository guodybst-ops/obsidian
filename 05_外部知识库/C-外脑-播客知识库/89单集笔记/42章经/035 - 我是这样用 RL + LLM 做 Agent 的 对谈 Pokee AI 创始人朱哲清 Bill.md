# 035 - 我是这样用 RL + LLM 做 Agent 的｜对谈 Pokee AI 创始人朱哲清 Bill

## 摘要

本期对谈 Pokee AI 创始人朱哲清 Bill，讨论强化学习（RL）、大语言模型（LLM）与 Agent 的结合。Bill 曾在 Meta 工作多年，负责将强化学习框架落地到广告推荐系统和基础设施场景，同时在 Stanford 攻读强化学习博士。创业后，他希望用 RL + LLM 做出具备更强推理、规划、个性化和工具使用能力的 AI Agent。

Bill 的核心观点是：RL 不是与 LLM 平行竞争的技术路线，而是一种学习方式，可以建立在 LLM 提供的世界理解、语言表示和抽象能力之上。LLM 擅长理解人类语言、生成候选步骤和表达结果，但在复杂规划、多步决策、探索未知路径、处理不确定性方面存在局限；RL 则更擅长在环境中评估 action 的长期价值，并寻找更优路径。

Pokee AI 当前先从电商场景切入，目标是做一个能够自主调用大量 API、完成多步规划和工具使用的 Agent。Bill 认为，很多现实业务并不需要 Agent 从零写完整代码，而是需要它理解用户目标、选择合适 API、组合服务、执行任务并返回结果。未来，Agent 可能广泛进入电商、广告、旅行、教育、健身、金融等 API 丰富的领域。

## 金句收藏

- “RL 和现在的大模型不是平行关系，RL 是一种学习方式，可以和 LLM 结合。”
- “LLM 给了强化学习一个基础的世界理解，让 RL 可以产生更强的交互能力。”
- “语言模型容易沿着高概率路径走，RL 更关注不确定性在哪里，以及怎样更有效地探索。”
- “复杂规划不是穷举问题，而是搜索问题。”
- “LLM 更像知识库和输入输出接口，RL 更像决策模型。”
- “我们最终想做的是一个可以自主调用上千上万个 API、完成复杂规划和推理任务的 Agent。”
- “很多工程问题，本质上是在组合各种 API。”
- “我们不是大模型公司，我们是强推理和规划型工具使用 Agent 公司。”
- “明年也许不是 Agent 元年，但会是很多公司真正把 Agent 落地的一年。”

## 核心要点

### 1. Bill 的背景：从 Meta 强化学习落地到 Agent 创业

Bill 曾在 Meta 工作七年多，前期做机器学习落地，负责 Meta Ads To B 业务中的推荐系统和强化学习应用，后来在应用强化学习团队担任负责人。他参与过强化学习在广告折扣、推荐、竞价和基础设施等方向的落地。

同时，他在 Stanford 攻读强化学习博士，研究方向与 RL 相关。创业后，他创立 Pokee AI，希望以 RL + LLM 为核心，做出推理能力、个性化能力和多步决策能力更强的 AI Agent。

### 2. 强化学习为什么重新变热

Bill 认为，强化学习在 AlphaGo 和游戏环境中取得突破后，一度被认为难以迁移到真实世界，因为游戏环境可以无限交互、反复试错，而真实环境往往很难获得同样的反馈。

后来，Transformer 和 LLM 兴起，很多人认为复杂规划和多步决策也许可以直接由 LLM 完成。但最近大家发现，在更复杂的推理、规划和未知路径探索中，单纯依赖过往数据和模仿学习仍不足够，因此 RL 重新受到重视。

以 O1、O3 等推理模型为代表的方向，也让行业重新关注搜索、规划、长思考和类 RL 技术。

### 3. RL 与 LLM 不是替代关系，而是组合关系

Bill 强调，RL 不是对大模型的倒退，也不是和 LLM 二选一。LLM 是模型架构和表示能力的进步，RL 则是一种学习和决策方式。今天的 LLM 能把环境、动作、状态、反馈等信息转化为语言和 embedding 表示，这让强化学习不再必须为每个场景手工设计复杂特征和环境抽象。

在他的理解中，LLM 提供了基础世界理解，RL 则在此基础上学习如何与世界交互、如何探索不确定性、如何选择更优 action。

### 4. Agent 的基本流程：理解目标、规划路径、执行并返回结果

Bill 描述了一个 RL + LLM Agent 的基本结构：用户或终端给 Agent 一个需求，Agent 先拆解目标，识别当前状态、可采取措施和可能步骤。接下来，RL 决策模型评估不同路径的成功概率和长期价值，寻找更优路径。完成任务后，结果再交给语言模型整理成人类可读的表达。

在这个流程中，LLM 可用于理解自然语言需求、生成候选步骤、把具象信息抽象成 action，也可用于最终结果表达；RL 则负责策略选择、路径评估和多步决策。

### 5. action 是否由 LLM 生成，取决于环境是否被完整定义

Bill 区分了两类环境：

- **action 被完整定义的环境**：例如供应链中把货物从一个点调配到另一个点，可执行动作是明确的，Agent 可以直接调用对应 action。
- **action 未完整定义的环境**：例如解数学题、复杂推理、开放式规划，需要 LLM 参与生成中间步骤，并结合 value 评估判断路径是否合理。

当路径走不通时，系统需要回退并重新选择分支。RL 的作用在于不只随机尝试，而是更有效地探索不确定性更高、潜在价值更大的路径。

### 6. LLM 的局限：容易卡在高概率路径和局部循环

Bill 认为，LLM 以数据集和概率预测为基础，容易沿着高概率路径往前生成。当它陷入某个思路时，可能很难主动跳出，也不擅长评估“如果采取另一种策略会发生什么”。

他用吃饭选择举例：如果一个人常去第一家店，第二家店体验很差，第三家店从未去过，那么为了知道哪家最好，人不会随机选择，而会优先探索第三家，因为那里不确定性最高。RL 的优势就在于识别不确定性，并以更高效率探索。

### 7. 强化学习处理的是“平行路径”的价值评估

Bill 提到，强化学习常要解决类似“如果我采取另一组行动会怎样”的问题。现实世界中很多事情从未发生，也未必会发生，但 Agent 需要基于已有经验和当前状态，估计不同决策路径的条件期望价值。

这与 LLM 固定角色、沿既有分布推理不同。RL 关注的是在某个状态下采取不同策略后，成功概率和预期回报分别是多少。

### 8. 复杂场景中，RL 尤其适合大量 action 与多步决策

Bill 总结了 RL 适用的典型条件：

- 可采取 action 数量很大；
- 很多 action 的结果尚未充分观察；
- 需要探索不确定性；
- 当前 action 会影响后续 action；
- 优化目标不是单点结果，而是整体长期结果。

他以 Meta 广告竞价为例说明：某个时间点花费多少会影响后续预算和效果，因此需要多步决策。又以 Facebook Reels 推荐为例：对兴趣不明确的新用户，探索型推荐能显著提升 engagement，因为系统主动探索用户可能喜欢的方向，而不是只依赖已有预测。

### 9. Agent 概念被泛化，但真正难点在复杂规划

Bill 认为，“Agent”这个词已经被泛化，很多简单自动化任务也被称作 Agent。例如订机票在简单条件下靠工程规则就能完成，不一定需要 LLM。

真正困难的是复杂多层规划。例如用户要在多个城市出差、安排多个地点、考虑交通、住宿、时间窗口和返回路径，这类任务每增加一步，复杂度都会指数级上升。LLM 可以处理短路径规划，但在长路径、多约束任务中容易在后续步骤发现无法继续，却不知道该回退到哪一步。

因此，复杂规划需要的不是简单穷举，而是搜索能力和对未来状态的预估能力。这正是 RL 可以发挥作用的地方。

### 10. 在 Bill 的架构中，RL 是决策核心，LLM 是接口和抽象层

Bill 直言，在 Pokee AI 最新产品中，外部 IO 接口由 LLM 处理，所有决策由 RL 模型完成。他把 LLM 类比为知识库、语言理解和表达模块，把 RL 类比为决策模型。

但他也强调，没有 LLM，RL 很难在开放世界中发挥作用。因为现实任务需要把具象的人类语言、API 文档、页面信息和业务结果抽象成 action、state 和 reward。LLM 提供了从具象到抽象的桥梁，也能辅助生成训练数据和评估结果质量。

### 11. Pokee AI 的目标：会使用大量 API 的规划型 Agent

Pokee AI 的最终目标，是做一个可以自主调用上千上万个 API，进行多步决策，完成复杂规划与推理任务的 Agent。

早期产品先从 Shopify 电商场景切入。Bill 介绍，他们用较小规模的 RL Agent 加较小规模语言模型，在不到一个月训练时间里，就能掌握几十个 Shopify API 的基础搜索、推荐和客服能力，并能较通用地迁移到不同店铺。

### 12. 电商场景的价值：减少插件、工程师和割裂系统

对于 Shopify 商家，Pokee AI 的核心价值是：商家不再需要安装几十个不可控插件，也不再需要雇多个工程师去维护搜索、推荐、客服、折扣、页面调整等功能。

传统 Shopify 生态里，搜索、品类搜索、推荐、客服等功能常由不同插件提供，数据和体验割裂。Pokee AI 希望用一个 Agent 统一调用底层 API，生成搜索、推荐、客服等前端交互，并让它们基于一致的数据和策略协同工作。

### 13. Agent 学的是 API 能力与调用策略

Bill 解释，Pokee AI 并不是学习每个插件表层，而是学习 Shopify 底层 API 的能力。系统把 API 从具象文本和接口描述转成抽象 action，RL 通过 self-play 学习不同 API 能解决什么问题、何时调用、使用哪些参数，以及用户是否满意。

LLM 在其中的作用包括理解需求、生成需求、将 API 文档和业务语义 embedding 化，以及辅助判断结果质量。

### 14. 长思考、MCTS 与世界模型

Bill 认为，O1 等推理模型可能在 inference 层面做了类 RL 的优化，例如使用类似 MCTS 的探索型规划算法。系统尝试一条路径，评估效果，再回退尝试其他路径，从而规避明显不可能成功的路径。

这种长思考会带来更高推理成本和更长响应时间。类似地，世界模型的思路是：当 Agent 采取一个 action 后，模型能够预测下一个状态是什么，从而让规划更容易。

### 15. Agent 现阶段：垂直场景正在落地，通用工具使用仍未出现

Bill 认为，目前大多数 Agent 仍基于 LLM 加工程调整。Coding 是落地最多、也最复杂且价值最高的方向之一，但复杂工程架构问题现阶段仍难完全解决。

除 coding 外，每个垂直领域都有公司在尝试做工程化落地，但能够横跨很多领域、通用调用 API、无需大量特殊 prompt 的 Agent 还不存在。Pokee AI 想做的正是这种通用工具使用 Agent：当进入某个场景时，给它一组 API，它就能理解每个 API 能解决什么问题，并组合完成任务。

### 16. 现实业务中，很多工程问题本质是 API 组合

Bill 认为，在现实业务里，真正从零写完整代码的场景越来越少。即使在大厂，很多工程工作也是把已有 API、函数、服务组合起来完成业务目标。

因此，很多场景并不需要 Agent 从零写出完整代码库，而是需要它理解任务、选择 API、设置参数、执行多步调用、观察结果并调整路径。只有金字塔尖的一类任务才需要 Agent 从零建立新业务系统或新代码库。

### 17. 电商 Agent 的未来使用方式

Bill 举了一个成熟电商 Agent 的使用例子：商家只需输入“圣诞节要做促销”，Agent 就能自动完成：

- 给圣诞相关产品设置折扣；
- 修改运费和运输时间；
- 调整首页推荐、搜索排序和页面主题；
- 上线指定产品和 promotion code；
- 给老客户发送促销邮件。

现在这些事情往往需要销售、运营、工程师、第三方推荐服务商和插件供应商协同，耗时且成本高。Agent 成熟后，商家通过自然语言对话就能快速完成。

### 18. Agent 与 Agent 协作：业务后台可能自动化

Bill 判断，未来每家公司都可能有自己的 Agent，后台的 Agent 之间通过 API 协作。例如电商 Agent 发现库存不足，可以调用供应链或库存系统的 API 下单补货；如果对方系统也由 Agent 管理，双方无需人工介入即可完成闭环。

但他也指出，现实中很多供应链和库存流程仍靠电话、邮件和人工处理，如果没有通用化接口，自动化闭环会受限。因此 Pokee AI 会优先选择能亲自做闭环的场景。

### 19. 小模型与低成本是 Pokee AI 的重要差异

Bill 表示，Pokee AI 的 RL 模型很小，训练成本也很低：一个月训练成本不到一万美元，推理模型可以在 CPU 上运行。相比直接用 GPT-4o 等大模型完成全流程，成本可能低两个数量级。

他认为，关键不是模型越大越好，而是能否以合适工具解决问题。Pokee AI 不把自己定义为大模型公司，而是定义为“强推理和规划型工具使用 Agent 公司”。

### 20. 市场判断：Agent 会进入落地年

Bill 不认为“Agent 元年”是准确说法，因为 Agent 概念已存在多年。他更愿意说，2025 年可能是很多公司真正把 Agent 落地的一年，即 Agent 开始采取真实措施、产生业务结果的一年。

从美国市场观察，投资人对垂直 Agent 仍很有兴趣，尤其关注准确性、可靠性和商业化能力。Bill 认为，资金并不缺，真正难的是找到清晰、可靠、能落地的标的。

## 关键问答

### Q1：为什么强化学习在今天重新变重要？

A：Bill 认为，过去 RL 很难离开游戏和模拟环境，因为真实世界反馈难以获得。LLM 出现后，它提供了语言理解、世界知识、embedding 和抽象能力，让 RL 可以更容易连接真实环境。同时，复杂推理和规划任务证明单纯模仿学习不够，行业因此重新重视 RL、搜索和规划。

### Q2：RL 和 LLM 是竞争关系吗？

A：不是。Bill 认为 LLM 是模型和表示能力，RL 是学习和决策方式。LLM 可以帮助 RL 理解语言、环境和 API，把具象任务抽象成 state、action 和 reward；RL 则负责探索、规划和长期价值评估。

### Q3：为什么 LLM 做复杂规划会遇到问题？

A：LLM 基于既有数据分布预测下一个 token，容易沿高概率路径生成，也可能在某个局部路径循环。复杂规划需要理解每一步对未来状态的影响，并在路径失败时回退到合适节点重新搜索。Bill 认为这更适合由 RL 或规划模型处理。

### Q4：RL 在 Agent 中具体做什么？

A：RL 评估不同 action 和路径的成功概率、长期价值和不确定性，帮助 Agent 在多步任务中选择更优策略。它特别适合 action 很多、结果不确定、当前动作影响后续动作、目标是整体长期收益的场景。

### Q5：Pokee AI 为什么从电商切入？

A：电商有大量明确 API、插件生态复杂、商家有实际运营需求，也存在搜索、推荐、客服、折扣、页面调整、促销等多步任务。Agent 可以统一调用底层 API，减少插件和人工工程成本。

### Q6：Pokee AI 是在替代 Shopify 插件吗？

A：Bill 的说法是，纯工程类插件中的相当一部分可能会被替代，因为 Agent 可以直接调用底层 API 完成搜索、推荐、折扣、客服等任务。但非工程类、特殊服务类插件未必会被覆盖。

### Q7：Agent 一定要会写代码吗？

A：不一定。Bill 认为很多现实业务并不需要从零写代码，而是需要组合已有 API 完成任务。代码生成更适合解决“从零建立系统”的问题，而 Pokee AI 更关注“基于已有业务和 API，完成多步执行”的问题。

### Q8：为什么小模型路线可行？

A：如果 Agent 的决策单位是 API action，而不是每个 token，那么需要决策的空间和成本会小很多。Bill 认为，用小型 RL 模型做规划和工具选择，再用 LLM 做接口与表达，可以比全程依赖大模型更便宜、更可靠。

### Q9：未来 Agent 会怎样进入企业？

A：Bill 认为，IT 类公司会先在代码生成和工程工具上使用 Agent；非工程类公司更需要 Agent 帮它们对接外部 API、组合服务商、完成业务流程。未来每个公司可能都有自己的 Agent，Agent 之间通过 API 协作。

### Q10：2025 年会是 Agent 元年吗？

A：Bill 不喜欢“元年”说法，因为 Agent 概念早已存在。他判断 2025 年更可能是 Agent 真正落地的一年：许多公司开始让 Agent 采取真实动作，并产生可衡量业务结果。

## 润色版逐字稿

### 开场与嘉宾背景

主理人介绍，本期嘉宾是 Pokee AI 创始人朱哲清 Bill，两人也是校友。Bill 简要介绍自己：他曾在 Meta 工作七年多，后几年在应用强化学习团队担任负责人，主要负责把强化学习框架和研究落地到广告推荐系统及基础设施场景。同时，他过去六年多在 Stanford 攻读强化学习博士。

最近，Bill 出来创办 Pokee AI，核心目标是用强化学习加 LLM，做出推理能力、个性化能力和多步规划能力更强的 AI Agent。

主理人说，海外 AI 市场中强化学习和 Agent 都非常热，而 Bill 正好站在二者交叉点上，因此希望围绕 Meta 经历、强化学习、Agent 和美国 AI 市场展开讨论。

### 强化学习为什么重新受到关注

Bill 回顾，强化学习在 2016 年 AlphaGo 和游戏环境中取得突破后，行业一度认为它进展放缓。核心原因是，游戏环境可以反复交互并获得结果，但真实世界很难提供同样的试错条件。

大约 2020 年后，GPT 系列逐渐变热，很多人开始认为规划和多步决策问题也许可以由 LLM 解决，甚至出现了一些用 Transformer 做决策和推理的研究方向。那时有人认为，可以不再依赖强化学习。

但最近行业重新发现，在复杂规划和推理问题上，只通过过往经验和模仿式学习不够。模型需要搜索未知路径，探索训练数据之外的能力。Bill 认为，这正是 RL 擅长的地方。

他提到，O1、O3 相关研究让很多人重新重视 RL 和规划。一些研究者甚至说，发现 RL 很 powerful 后，自己的思考方式都变得“RL 化”。

### RL 与 LLM 的关系

Bill 强调，RL 与大模型不是平行竞争关系。大模型可以和传统神经网络类比，而 RL 是一种学习方式，可以与 Transformer 和 LLM 并行结合。

在他看来，LLM 的出现反而让 RL 有了更好的发展基础。过去 RL 很难处理开放世界，是因为它需要理解环境、action、状态和反馈。现在，LLM 可以用语言和 embedding 表示这些内容，不需要人为为每个场景设计复杂架构。

换句话说，LLM 提供了对世界的基础理解，RL 则在这个基础上学习如何与世界互动、如何探索和规划。

### 一个 RL + LLM Agent 如何工作

Bill 描述了 Pokee AI 设想中的技术架构：用户给 Agent 一个需求，Agent 先拆解目标，理解当前状态、可采取措施和要完成的步骤。它可能知道需要做三步，但不确定这三步的最佳顺序和具体路径。

这时，RL 可以尝试并评估不同路径：先采取 action 1、再 action 3、再 action 4，或者换一种顺序，分别估计成功概率和预期结果。找到较优路径后，Agent 执行任务，获得结果，再由语言模型重新组织成用户能读懂的表达。

主理人追问，这些步骤是从 LLM 已有的步骤库里选择，还是现场生成。Bill 回答，这取决于环境。如果 action 被完整定义，例如供应链中从一个点调货到另一个点，就可以直接调用已有 action。如果是解数学题或开放式推理，action 没有完整定义，就需要 LLM 辅助生成中间思考步骤，并用 value 评估其质量。

### 为什么 LLM 会陷入局部路径

主理人提到，如果用 LLM 自己生成路径、验证结果、失败后再换路径，直觉上似乎也能完成。Bill 解释，问题在于语言模型的探索接近随机，而且常受已有数据分布限制。当它只想到一条路径时，就可能一直沿着这条路径前进，甚至陷入重复。

他用选择餐厅举例：如果有三家店，一家每周常去，一家去过且很差，第三家从没去过。如果目标是找到最喜欢的店，人通常会优先尝试第三家，因为不确定性最高。RL 的探索不是随机选，而是基于对不确定性的判断，主动选择最值得探索的方向。

因此，RL 在复杂规划中的优势，是能判断“我不知道哪里”，并更高效地探索未知区域。

### 强化学习处理的是平行路径问题

Bill 进一步解释，RL 的核心不是知道世界上所有变化，而是在当前状态下评估不同 action 的成功概率和预期回报。它关心的是：如果我采取这组三步，成功概率是多少；如果换一组策略，结果又会怎样。

这类似在思考平行路径。很多事情没有发生过，也未必会发生，但 Agent 需要估计如果采取某一系列行动，未来可能如何变化。Bill 认为，LLM 并不擅长这种基于策略变化的反事实推理和价值评估。

### RL 最适合什么场景

主理人问，现实生活中很多任务并没有明确标准答案，例如陪伴聊天，这时如何做人类反馈和优化。Bill 回到 Meta 的经验说明：RL 最擅长优化整体期望，而不一定是单点结果。

例如广告竞价中，某些竞价可能效果一般，但另一些竞价可能带来明显提升，总体广告效率因此提高。推荐系统中，对兴趣不明确的新用户，探索型算法可以通过尝试不同内容，迅速找到用户偏好，提升 engagement。

他总结，RL 更适合 action 很多、需要探索、多步决策、前一个 action 影响后一个 action、目标是整体收益的场景。如果只是单一 action 的预测问题，且结果已知，RL 的价值就不大。

### Agent 的定义与真正难点

主理人提到，Agent 从 AutoGPT 开始就被不断讨论，但一直在等待落地。Bill 认为，Agent 这个概念确实有些被泛化了。简单如订机票，很多情况下靠工程规则就能完成，甚至不需要 LLM。

真正复杂的是多层规划。例如用户要去上海出差，访问三个地点，再去杭州，两天内回北京。这类任务涉及时间、地点、交通、住宿、约束和偏好，工程规则很难覆盖。

Bill 曾在创业早期给投资人展示过城市旅行规划 demo。他说，短路径规划 LLM 可以做，但多层规划会出现复杂度指数级上升。模型可能规划到第十一步时发现走不下去，却不知道该回退到哪一步。复杂规划需要搜索和未来状态预估，而不仅是穷举。

### 为什么 RL 是决策核心

主理人追问，如果按这个逻辑，RL 是否才是核心，LLM 只是输入输出翻译。Bill 说，在 Pokee AI 最新产品里，所有决策确实由 RL 完成，外部 IO 接口由 LLM 负责。

他把 LLM 比作知识库和语言接口，负责理解人类语言、图像和 API 文档，把具象信息变成抽象表示；RL 则基于这些抽象 state 和 action 做决策。

但 Bill 也强调，没有 LLM，RL 无法进入开放世界。过去在大公司做广告竞价或推荐落地时，有大量人力把具象问题抽象成模型可处理的问题。现在，LLM 可以承担这个抽象过程，并生成线下训练数据，还能辅助判断 RL Agent 做得好不好。

### Pokee AI 要做什么

Bill 介绍，Pokee AI 的最终目标是做一个可以自主调用上千上万个 API、进行多步决策、完成复杂规划和推理任务的 Agent。

早期，他们发布了一个电商方向的 beta 产品，架在 Shopify 生态上。Bill 表示，在不到一个月训练时间里，他们用 1500 万参数左右的 RL Agent，加一个十亿参数级别以下的语言模型，就已经掌握了几十个 Shopify API 的基础搜索、推荐和客服能力。把这个 Agent 放到不同 Shopify 店铺上，不需要特殊个性化训练，也能具备通用能力。

### 电商商家的痛点与 Pokee AI 的价值

主理人要求 Bill 用客户语言解释产品价值。Bill 说，对 Shopify 商家而言，Pokee AI 的价值是：不再需要安装几十个不可控插件，也不需要雇几个工程师维护功能；商家可以更完整地掌控自己的店铺参数、搜索、推荐、客服和促销策略。

传统插件往往彼此割裂。搜索、推荐、客服、品类搜索、关联产品推荐等功能可能由多个插件提供，数据不统一，体验也不统一。Pokee AI 希望用一个 Agent 调用底层 API，把这些功能整合成一个协同系统。

在前端，除产品展示页面外，搜索、推荐、客服 chatbot 等交互都可以由 Agent 基于模板生成；在后端，Agent 调用 Shopify 底层 API 和必要存储完成操作。

### Agent 如何学习 API

主理人追问，Pokee AI 是学习插件，还是学习 Shopify 底层 API。Bill 回答，他们学习的是底层 API。

具体来说，系统会把 API 从具象文字描述转化为抽象 action，RL 通过 self-play 学习调用不同 API 会得到什么结果、用户是否满意、什么场景下该调用哪个 API、参数该如何设置。

语言模型在这里负责几个关键环节：理解需求，生成训练需求，把 API 文档和业务含义转成 embedding，并辅助判断最终结果是否好。

### 长思考与世界模型

谈到 O1、O3 等模型时，Bill 认为它们很可能在 inference 层面使用了类 RL 的优化，例如 MCTS 这种探索型规划算法。系统尝试一条路，评估是否可行，再回退尝试另一条路，反复进行。这能规避明显失败的路径，但也会带来更高推理成本和更长响应时间，这就是所谓长思考的一部分含义。

他还提到，世界模型的思路是让模型在采取 action 后预测下一状态。如果模型知道每一步之后世界会怎样变化，规划就会容易很多。没有这类搜索或世界模型，系统就容易退化成随机探索或穷举。

### Agent 当前阶段与通用工具使用

Bill 判断，目前大多数 Agent 仍是基于 LLM 加工程实现。Coding 是落地最多、也非常复杂的方向之一，但当问题涉及复杂工程架构时，现有 LLM 仍难以完全解决。

在非 coding 领域，许多垂直公司都在尝试借助 Gemini、OpenAI 等模型做工程化落地，但能够跨越多个领域、通用调用 API、理解工具能力并完成任务的 Agent 还不存在。

Pokee AI 的目标是训练一个“见过大多数 API 工具使用方式”的 Agent。当它进入某个新场景，只需给它一组 API，它就能知道哪个 API 可以解决什么问题，而不需要大量特殊 prompt 或微调。

### API 世界里的 Agent

Bill 认为，未来 Agent 每天都可能与各种 API 打交道。很多现实世界中的人类动作，也可以用 interface 包装成某种 API。例如发送邮件、等待回复、提交表单、调用客服系统，本质都可以被 Agent 作为工具使用。

他指出，在今天的大型工程系统中，真正从零写一个完全独立函数的情况已经越来越少，更多是组合已有 API 和服务完成任务。因此，能够整合 API 并进行多步决策的 Agent，已经能完成大多数现实业务需求。

当然，另一类更困难的 Agent 是从零写代码、搭建完整代码库和业务系统，这可能是 coding Agent 公司追求的终极方向。但 Bill 认为，大多数场景暂时不需要这种能力。

### 电商 Agent 的成熟场景

主理人问，如果一年后电商 Agent 成熟，商家会怎样使用。Bill 举例：圣诞节到来，商家只需告诉 Agent 要做圣诞促销，Agent 就会自动给相关产品打折，修改运费和配送时间，调整首页推荐、搜索结果和页面主题，上线指定产品和优惠码，甚至给老客户发送促销邮件。

现在，这些工作往往需要运营、销售、工程师和第三方插件供应商配合，可能要花大量时间和预算。Agent 成熟后，商家通过文字说明目标，几分钟内就能完成。

### 企业中的 Agent 网络

Bill 认为，未来很多公司都会有自己的 Agent。尤其是非工程类公司，痛点常常在于整合外部服务商和 API，完成一整套业务流程。供应链、制造业、电商、广告等领域都有大量重复性工作，可以由 Agent 执行。

未来，一个电商 Agent 发现库存不足，可能会直接调用供应链 Agent 或库存系统 API 下单补货。人类则可以把更多时间投入创造性工作，而不是盯订单、派发、查询和沟通。

### 成本、模型大小与商业化

Bill 强调，Pokee AI 的训练和推理成本很低。他们一个月训练成本不到一万美元，RL 模型可以在 CPU 上运行。相比用 GPT-4o 全程推理，成本可能低很多。

他认为，市场不应只追求更大的模型。解决问题才是关键。如果一个任务用小模型和合适算法能完成，就没有必要把工具做成过大的“榔头”。Pokee AI 因此不会自称大模型公司，而是强推理和规划型工具使用 Agent 公司。

### 市场与融资观察

主理人最后询问 Bill 对 2025 年 AI 市场的看法。Bill 从美国市场观察认为，投资人对 Agent 仍很感兴趣，尤其是垂直 Agent。投资人关注的核心问题包括准确性、可靠性和盈利方式。

他认为，市场并不缺钱，AI 投资基金仍然活跃；难点在于标的混乱、大公司和高融资公司很多，小团队需要找到清晰差异化。Pokee AI 虽然现在还属于小团队，但他们希望凭借 RL 技术路线、低成本和可靠规划能力形成护城河。

对于“明年是不是 Agent 元年”，Bill 表示自己不太认同“元年”说法，因为 Agent 概念早就存在。但他相信，2025 年会是很多公司真正把 Agent 落地的一年，也就是 Agent 开始采取行动并产生结果的一年。
