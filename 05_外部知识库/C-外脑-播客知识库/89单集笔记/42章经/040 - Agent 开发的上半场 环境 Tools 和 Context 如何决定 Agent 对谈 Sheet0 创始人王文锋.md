# 040 - Agent 开发的上半场：环境、Tools 和 Context 如何决定 Agent｜对谈 Sheet0 创始人王文锋

## 摘要

本期《42章经》邀请 Sheet0 创始人王文锋，围绕 Agent 的定义、工具调用、环境反馈、上下文工程、AI Coding 与 Workflow 的关系，以及垂直 Agent 的产品设计展开讨论。

王文锋认为，Agent 可以理解为“模型基于环境反馈使用工具的程序”。过去两年 Agent 的真正进展，除了底层模型能力增强，尤其是推理与长思维能力提高之外，更重要的是工程与产品层面对 context 的构建能力提升。Agent 的关键不只是“能调用工具”，而是能在一个可反馈、可收敛的环境中，持续获得状态、执行 action，并根据奖励信号修正路径。

节目中还讨论了 MCP、Function Call、Browser Use、Computer Use、AI Coding、Workflow 等概念之间的关系。王文锋强调，MCP 的意义主要在于工具调用标准化；浏览器与 GUI 方式并不和代码方式冲突，它们往往是组合使用的；AI Coding 更像是 Agent 的一种强工具或“灵巧手”，适合在现有工具不足时临时生成代码，但高可靠任务仍需要复用经过验证的工具。

在产品层面，王文锋主张垂直 Agent 会长期优于通用 Agent，因为垂直场景更容易定义环境、行动空间和反馈信号。好的 Agent 产品应减少用户认知负担，让用户尽量不用动脑，同时通过透明过程、结构化结果与可校验反馈建立信任。Sheet0 的定位是“表格 Agent”，核心是把非结构化数据收集、清洗为结构化表格，再基于表格做定量分析和后续行动。

## 金句收藏

> Agent 是模型基于环境反馈去使用工具的程序。

> 你如何把产品变成一个环境，是 Agent 创业公司非常关键的问题。

> 环境的核心作用，是提供奖励信号的反馈机制。

> 用户交互的自由度，比用户交互的准确度更关键。

> 聊天框仍然是 Agent 产品最重要的交互入口，但合适的组件应该在合适的时机出现。

> AI Coding 是大模型的灵巧手，也是 Agent 的一个强工具。

> Workflow 是人驱动的，Agent 是 AI 驱动的；二者会长期共存。

> 越通用，方法越泛化，随机性也越高。

> 大模型的输入可以是非结构化的，但输出最好是结构化的，因为只有结构化才能被校验。

> 判断 Agent 的关键，不是看它演示时能做什么，而是看它最终 deliver 的 result。

## 核心要点

### 1. Agent 的三要素：模型、环境反馈、工具

王文锋引用 Anthropic 式的定义，将 Agent 概括为：模型基于环境反馈使用工具的程序。这个定义中的三部分分别是：

- **模型**：负责理解、规划、推理和生成。
- **环境反馈**：告诉 Agent 当前状态如何、行动是否接近目标。
- **工具 / action**：让模型能够真正执行动作，而不是只生成文本。

他认为，Agent 与传统大模型应用的关键差异，在于 Agent 能够在执行过程中不断获取反馈，并据此调整下一步行动。

### 2. Agent 的进展不只来自模型，也来自 context 工程

过去两年 Agent 之所以从玩具走向可落地应用，一方面是模型能力显著提升，尤其是推理、规划与长上下文能力增强；另一方面是 Agent 工程对 context 的组织方式发生了进步。

在代码场景里，context 包括代码库结构、源码、API、用户输入和运行反馈；在 Sheet0 的数据场景里，context 包括网页、已收集的数据表、用户目标、生成的 SQL 或脚本、执行结果等。王文锋强调，关键不只是把信息塞给模型，而是这些 context 如何自动化获取、筛选、校验和更新。

### 3. MCP、Function Call、A2A 与 Browser Use 的关系

王文锋认为，Function Call 是大模型使用工具的早期机制，MCP 则进一步把工具调用标准化，类似统一度量衡。MCP 的意义不只是某个工具本身，而是降低不同工具接入模型的门槛。

他对 A2A 的评价较保留，认为 Agent 与 Agent 之间的交互也可以被抽象为工具调用，因此 A2A 更像是标准话语权之争，而不是工程上提供了本质新东西。

Browser Use 或 Computer Use 则是把浏览器或电脑界面当作工具。它可以通过视觉坐标模拟人类操作，也可以通过浏览器 API 或 MCP 封装成更稳定的工具调用。现实产品通常不会纯用视觉方式，而是结合 API、代码和浏览器操作。

### 4. 浏览器方式的价值不只是技术，也包括用户信任

对于为什么 Manus 等产品会使用可视化浏览器过程，王文锋给出两个视角：

- **技术视角**：浏览器方式成本可能更低，某些场景比后端 API 接入更快。
- **产品视角**：用户能看到 Agent 如何一步步完成任务，会更容易建立信任。

他将这种透明性类比为人与人协作中的信任建立：如果用户能看见过程、理解思路，就更愿意相信结果。Agent 在用户心中仍然不够可靠，因此展示过程、允许用户介入，是产品设计上很重要的一环。

### 5. AI Coding 是 Agent 的工具，而不是 Agent 的全部

王文锋认为，AI Coding 与 Agent 的关系不是替代，而是补充。Agent 在解决问题时，应优先寻找现成、可靠、可复用的工具；当没有合适工具时，才退化为通过 AI Coding 临时生成代码。

AI Coding 的优势在于能把某些模糊任务转化为可执行程序，使每一步结果可以被测试、校验和复用。它像大模型的“灵巧手”，可以提高准确率，减少前一步错误对后续步骤的影响。

但如果每次都从零生成代码，成本和随机性都会很高。因此，王文锋强调工具复用：经过人类验证的小工具，比每次临时生成代码更稳定。

### 6. 垂直 Agent 会长期存在，因为它更容易定义反馈信号

王文锋认为，行业会长期处于垂直 Agent 时代。通用 Agent 的问题在于目标太泛，难以定义统一的环境、状态、行动空间和奖励信号；垂直 Agent 则更像专业厨师，能在具体场景里做出远超普通人的结果。

他建议 Agent 创业者从强化学习视角理解产品：

- **状态**：Agent 当前看到和记住的一切，也就是 context。
- **行动**：通过工具、函数或代码执行的动作。
- **奖励信号**：判断某个行动让结果更接近还是更远离目标。

只有把结果定义清楚，Agent 才能收敛；只有环境能提供反馈，Agent 才能迭代。

### 7. 好的 Agent 产品应该降低用户认知负担

王文锋认为，上一代软件往往功能越多、学习成本越高；Agent 产品则应该相反：越强大，用户越不用动脑。

这意味着 Agent 产品需要：

- 充分理解用户偏好；
- 主动积累 context；
- 在合适时机提出澄清问题；
- 让用户用自由自然语言表达意图；
- 把复杂组件隐藏在后台，只在必要时呈现。

他因此认为，聊天框仍是 Agent 产品最重要的交互入口，因为它最大化了用户表达自由度。准确度不应由用户承担，而应由产品通过记忆、澄清、预置流程和系统提示词提升。

### 8. Workflow 与 Agent 会长期共存

王文锋将 Workflow 与 Agent 的区别概括为：Workflow 是人驱动的，Agent 是 AI 驱动的。

Workflow 的优点是稳定、可靠、可预期；缺点是不够泛化。Agent 的优点是能处理开放问题；缺点是随机性更高。未来更可能的状态是：常见、稳定、高频的问题由 Workflow 承担，开放、长尾、复杂的问题由 Agent 处理。

### 9. Sheet0 的定位：面向高质量数据抓取与表格分析的 Agent

王文锋介绍，Sheet0 的目标是打通数据收集、数据处理和基于数据的行动。与调研型 Agent 主要输出报告不同，Sheet0 更强调定量分析，核心中间产物是结构化表格。

典型场景包括：

- 根据开源用户线索识别其所在公司；
- 抓取 YC 公司列表、创始人信息和社交账号；
- 在表格基础上继续补全、清洗和执行后续动作。

他认为，报告很难精确校验，但表格天然结构化，空值、错误字段、缺失行都更容易被发现，因此更适合作为 Agent 的反馈与校验载体。

### 10. 判断 Agent 公司要看反馈机制，而不只是演示效果

如果要判断一家 Agent 公司是否有潜力，王文锋最想问的问题是：产品里的环境反馈和激励信号是怎么设计的？

因为只有定义了什么行为是好的、什么行为是坏的，模型才有迭代方向。单靠另一个 prompt 让模型评价自己，容易陷入循环；真正有效的反馈应来自模型本身不具备的信息，例如代码运行结果、结构化字段校验、真实数据库返回、用户操作结果等。

## 关键问答

### Q1：Agent 与两年前的 AutoGPT 式产品有什么不同？

**王文锋：** 两年前很多 Agent 更像玩具，没有真正解决实际问题。现在变化主要来自两方面：一是底层模型能力提升，尤其是推理和长思维能力；二是 Agent 工程本身进步，开发者更会构建合适的 context，让模型能在真实环境中解决问题。

### Q2：Context 为什么这么重要？

**王文锋：** Context 是大模型需要利用的信息总和。它不仅包括用户输入，也包括环境、历史步骤、工具结果、网页内容、数据表、代码执行结果等。Agent 的能力很大程度取决于能否自动获取、筛选和校验这些信息。

### Q3：MCP 和 Function Call 的区别是什么？

**王文锋：** Function Call 是大模型调用工具的早期方法；MCP 更进一步，把工具调用标准化。它的价值像统一度量衡，让不同开发者和工具可以用同一套协议接入模型。

### Q4：为什么有些 Agent 要用浏览器，而不是直接调后端接口？

**王文锋：** 技术上，浏览器方式在某些情况下成本低、接入快；产品上，浏览器过程更可视化，能让用户看到 Agent 如何完成任务，从而建立信任。并且现实中浏览器方式也不一定是纯视觉模拟，很多时候背后仍然使用 API 和代码。

### Q5：AI Coding 会不会成为 Agent 的基础？

**王文锋：** AI Coding 是 Agent 的强工具，但不是全部。Agent 应先复用现有可靠工具；没有工具时，再用 AI Coding 临时造工具。AI Coding 的价值在于把任务转为可执行、可测试、可复用的代码，从而提升准确率。

### Q6：通用 Agent 和垂直 Agent 谁更有机会？

**王文锋：** 目前以及相当长时间内，垂直 Agent 更有机会。垂直场景更容易定义环境、行动空间和结果标准，因此更容易设计反馈信号，让 Agent 收敛并持续优化。

### Q7：Agent 产品最重要的交互形态是什么？

**王文锋：** 聊天框仍然是最重要的入口，因为它给用户最高的表达自由度。但这不意味着只有聊天框，产品应该在适当时机把合适组件呈现给用户，降低认知负担。

### Q8：Workflow 会被 Agent 取代吗？

**王文锋：** 不会。Workflow 稳定可靠，但泛化不足；Agent 泛化更强，但不够稳定。二者会长期共存，Workflow 处理常见稳定问题，Agent 处理开放复杂问题。

### Q9：Sheet0 和 Manus、Genspark 等产品有什么区别？

**王文锋：** 很多产品更像调研 Agent，最终交付报告；Sheet0 更关注表格和定量分析，先把数据源变成完整、干净、结构化的表格，再做后续分析和行动。表格也更容易校验准确性。

### Q10：判断 Agent 创业公司的关键问题是什么？

**王文锋：** 要问它的环境反馈和激励信号如何设计。没有反馈信号，Agent 很难自我迭代；没有结构化结果，质量也难以校验。

## 润色版逐字稿

### 开场：Agent 热潮与基本定义

主持人提到，今年 AI 领域最热的关键词之一就是 Agent，并邀请 Sheet0 创始人王文锋介绍自己。王文锋表示，自己是程序员出身的创业者，已经做 Agent 两年，目前团队在做的产品是 Data Agent，主要帮助用户收集和分析数据。

在谈到 Agent 的定义时，王文锋认为，一个较好的定义是：Agent 是模型基于环境反馈使用工具的程序。这个定义可以拆成三部分：第一是模型，第二是环境反馈，第三是工具调用或行动。模型本身大家较容易理解，但环境反馈和工具调用是 Agent 与普通大模型应用的重要区别。

主持人问，为什么这一轮 Agent 热与过去不同。王文锋认为，2023 年 AutoGPT 等产品流行时，Agent 更多还是玩具；两年后，Agent 已经能在真实工作和生活场景里解决问题。变化主要来自两点：一是底层模型进步，尤其是推理能力增强；二是 Agent 工程进步，开发者更懂得如何构建合适的 context。

### Context：Agent 工程的核心变量

王文锋解释，context 是大模型需要利用的信息总和。以代码场景为例，它包括代码库结构、源码、可用 API、人类输入等；以 Sheet0 的产品为例，它包括网页、收集来的数据表、用户想要什么数据、分析过程中生成的 SQL 或脚本等。

主持人追问，这些信息过去不也会通过 prompt 或 RAG 输入模型吗？王文锋指出，核心差异在于 context 从哪里来。网页里有大量无关信息，需要自动抽取关键部分；生成 SQL 后，需要用数据库执行结果校验；这些信息需要通过自动化方式提炼出来。过去很多 context 主要依赖人输入，而 Agent 更强调从环境中自动获取。

### 工具调用：Function Call、MCP、A2A 与 Browser Use

主持人提出，外界常听到 Function Call、MCP、A2A、Computer Use、Browser Use 等概念，希望王文锋分类解释。

王文锋认为，这些概念都在解决同一件事：给大模型提供更好的工具使用方式，让模型能 take action。Function Call 是 OpenAI 较早提出的工具调用方法，可以看作 0.1 版本；MCP 在此基础上推进一步，可以看作工具调用标准化的 0.2 版本。MCP 的意义类似统一度量衡，让不同开发者不必各自定义工具接口。

对 A2A，王文锋认为它更像标准话语权之争。A2A 强调 Agent 与 Agent 之间通信，但在工程视角里，一个 Agent 也可以被包装成工具，被另一个 Agent 调用，因此并没有带来本质不同。

Browser Use 则是把浏览器作为一种重要工具。浏览器可以通过视觉坐标模拟人类操作，也可以通过浏览器 API 被包装成工具，由模型通过代码或 MCP 方式调用。

### API 与 GUI：两条路径并不冲突

主持人总结，似乎一类方式是用代码解决问题，另一类是模拟人操作。王文锋补充说，两者并不矛盾。纯视觉坐标点击目前并不成熟，很多 Browser Use 的背后仍是调用浏览器 API，或者把浏览器能力包装成类似 MCP 的工具。

当某个 SaaS 或软件有 Open API 时，开发者可以在 Open API 外包一层 MCP；但如果没有 API 或 SDK，只能尝试视觉识别和模拟鼠标键盘操作。在海外，Open API 比较常见；国内很多软件没有开放 API，因此 GUI 方式可能更重要。

同时，GUI 方式虽然稳定性和准确度不如 API，但成本可能更低。有时只需截图让模型判断，速度更快、token 消耗更少。不过问题在于坐标和元素判断可能出错，例如按钮位置识别不准。

### 为什么 Agent 要展示过程

主持人提到，有专业人士不理解 Manus 为什么要用浏览器展示过程，认为后端代码完全可以接通并直接实现。王文锋认为，可以从技术和产品两个角度回答。技术上，浏览器方式有时成本更低；产品上，用户是否相信 Agent 的结果非常重要。

如果用户能看到 Agent 一步步如何完成任务，就会更容易建立信任。王文锋将其类比为同事协作：如果一个人能展示自己如何做事、思路是什么，另一个人就更容易相信他。Agent 产品需要给用户一种安全感，而过程透明是建立安全感的重要方式。

主持人也指出，Manus 这类产品有时会在中途提问，如果用户没看到，任务就停住。王文锋认为，这是 UI 和通知机制可以优化的问题。未来通过邮件、短信或 IM 打通，可以让用户更及时地看到 Agent 的问题。

### AI Coding 与 Agent 的关系

主持人问，AI Coding 与 Agent 是否会走到一起。王文锋认为，AI Coding 可以理解为 Agent 的一种工具。Agent 解决问题时，最优选择应先寻找现成可用工具；如果没有合适工具，再用 AI Coding 临时生成一个工具。

他强调两个关键词：协作与复用。现代软件开发强调复用，因为复用可以降低成本、提高效率。对 Agent 也是如此，如果每次都从零生成代码，效率低、成本高、随机性强；如果能复用经过测试的小工具，结果更稳定。

主持人进一步问，是否所有任务都可以通过 AI Coding 转化成程序来提高准确率。王文锋认为，从 MCP 的角度看，工具背后本质上都是代码。AI Coding 像大模型的“灵巧手”，可以把任务拆成可执行、可测试的程序步骤，降低多步任务中错误累积的问题。

### 垂直 Agent：像五星级厨师，而不是普通会做饭的人

主持人问，未来是通用 Agent 还是垂直 Agent。王文锋认为，行业会长期处于垂直 Agent 时代。

他用做饭作比喻：很多人都会做饭，但普通人对着菜谱做，与五星级酒店大厨的水平不同。垂直 Agent 就像专业厨师，能在特定领域中凭借知识、工具和反馈机制达到更高结果质量。

当主持人问到强化学习与 Agent 的关系时，王文锋指出，Agent 的概念本来就来自强化学习。在强化学习里，Agent 包括状态、行动和奖励信号。对应到产品中，状态就是 context，行动就是工具调用，奖励信号则用来判断某一步是否让结果更接近目标。

因此，对创业公司来说，关键是让产品成为一个环境：定义状态是什么、行动空间有多大、结果如何衡量。只有结果定义清楚，模型才能知道自己做得更好还是更差，才能自我迭代。

### 什么是好的环境

主持人提到，IDE 显然是一个很好的环境，但浏览器是否也是好环境。王文锋认为，判断环境好坏，要看它能否基于行动结果提供奖励信号。

IDE 是好环境，因为代码生成后可以直接运行，运行失败会产生错误信息，这就是天然反馈信号。Ubuntu 更像容器，本身不一定提供反馈机制，开发者需要在它之上搭建一套反馈系统。

因此，环境不是简单指软件界面，而是能否帮助 Agent 识别当前状态、执行行动并得到有效反馈。

### Agent 产品设计：让用户不用动脑

王文锋总结自己做 Agent 的经验时，强调好的 Agent 应尽可能不让用户动脑。上一代软件功能越多，用户学习成本越高；Agent 产品应反过来，能力越强，用户越轻松。

他认为，聊天框仍然是 Agent 产品最重要的入口，因为用户可以自由表达。用户交互的自由度比准确度更关键。准确度应该由产品方通过记忆、偏好积累、澄清问题和系统提示词来提升，而不是要求用户学习固定格式。

主持人补充，纯聊天框未必最高效，但在合适时机弹出合适组件是合理的。王文锋同意，后台可以有很多组件，但用户只应在需要时看到与自己相关的少数部分。

### Context 与用户意图

主持人提到，用户打开某个 App 本身就是强 context。例如打开美团表示可能要点外卖，打开滴滴表示可能要打车。王文锋认同，产品场景本身把用户拉入共同氛围，降低了意图识别难度。

他进一步指出，想理解用户意图，需要看用户从哪里来、中间路径是什么、过去做过什么。高质量数据不仅要知道输入和输出，还要知道中间过程。这种序列数据对 Agent 很关键，就像下围棋时不能只看当前一步，还要看前面很多步如何形成当前局面。

### Sheet0：从非结构化网页到结构化表格

主持人请王文锋介绍 Sheet0。王文锋表示，Sheet0 的目标是把数据收集、数据处理和基于数据的行动闭环。当前团队在数据收集和处理上已经做得较好。

一个典型场景是销售线索发现：例如某个开源项目有很多用户，团队希望知道这些用户来自哪些公司，方便销售商业化版本。Sheet0 会访问用户主页，分析代码提交、社交账号等线索，推断其公司信息。

另一个例子是找到 YC 某几期公司列表，再找到创始人、Twitter 账号，并进一步关注或私信。王文锋强调，Sheet0 内部做了许多小工具，并经过测试验证，因此相比每次动态生成代码，准确率和稳定性更高。

### Workflow 与 Agent 的共存

主持人问，Workflow 会不会被 Agent 颠覆。王文锋认为不会。人们喜欢制造对立，但现实中二者会长期共存。

Workflow 是人驱动的，优点是稳定可靠，缺点是不够泛化；Agent 是 AI 驱动的，优点是能处理未预设的问题，缺点是可能出错。未来可能是 Agent 负责开放场景，Workflow 负责常见、稳定、高频任务。

### Sheet0 与调研 Agent、Coding Agent 的区别

王文锋将市面上的 Agent 分为几类：Genspark、Manus 等更像调研 Agent，最终交付报告；Coding Agent 的结果是代码；Sheet0 则是表格 Agent。

他认为，分析问题有两种方式：定性分析和定量分析。调研报告更偏定性，帮助用户建立感觉；表格则适合定量分析，需要准确数字和完整数据源。Sheet0 的核心是先把各种数据源整理成完整、干净、结构化的表格，再基于表格分析。

结构化表格也有利于解决幻觉问题。表格中空值、缺失列、错误字段都更容易被发现和校验，而报告很难精确判断哪一行哪一个字有问题。

### Agent 开发者要解决两类信任

王文锋认为，Agent 开发者需要解决两类信任。

第一是开发者自己要相信大模型。如果开发者不相信模型，就会在代码里加大量限制，用传统规则方式束缚模型，导致模型智能利用率下降。很多产品过度封装后，效果反而不如直接把需求交给大模型。

第二是产品要解决用户对结果的信任。Deep Research 和 Manus 类产品通过展示 reasoning 或执行过程，让用户看到结果如何产生，从而降低不确定感。透明过程是 Agent 产品建立信任的重要方式。

### 未来半年到一年的 Agent 变量

被问到未来预测时，王文锋认为，Agent 的关键变量是 context 和模型能力。模型层面，要看新一代模型何时出现，以及成本何时下降到可大规模使用的水平。工程层面，要看团队能否围绕具体场景构建足够好的 context。

他以 Cursor 为例，指出 Cursor 围绕 VS Code 做了大量二次开发，才把 coding 场景的 context 做好。Agent 的工程复杂度远超很多人的想象，需要长期工程积累。

### 如何判断一家 Agent 公司

主持人问，如果作为投资人，要如何判断 Agent 公司。王文锋说，他最想问的是：产品里的环境反馈和激励信号如何设计？

如果一个产品无法定义什么行为好、什么行为坏，就很难让模型迭代。结构化输出非常重要，因为大模型输入可以非结构化，但输出必须结构化，才能用代码或规则校验。

对于 Sheet0，反馈信号来自两方面：一是代码执行结果，二是表格本身的结构化特征。数据抓取过程由模型分析页面结构，再生成脚本执行；表格中是否缺字段、是否为空，也能直观提供反馈。

### 收尾：为什么选择 Sheet0

最后，主持人请王文锋给出选择 Sheet0 的理由。王文锋认为，如果用户有高质量数据抓取需求，Sheet0 的核心价值是准确、稳定、不丢数据。

他表示，Sheet0 会开放 waiting list，用户注册后可在之后使用产品。节目最后，双方互致感谢。
