# 042 - 关于 AI、开源、商业化与全球化的经验、教训和方法论：对谈 PingCAP CTO 东旭

## 摘要

这一期是曲凯与 PingCAP 联合创始人兼 CTO 东旭的对谈，围绕 TiDB、开源基础软件、商业化、全球化和 AI 时代的数据库机会展开。

东旭先用「数据的容器」解释 PingCAP：TiDB 是一个分布式关系数据库，解决的是数据规模持续增长之后，传统数据库「杯子容量有限」的问题。它让开发者仍然像使用一个数据库一样工作，但底层可以随数据量自动扩展。

回顾 PingCAP 十年，东旭认为几个关键选择决定了公司的路径：第一，从第一天选择开源，而且是全生命周期的开源；第二，选择关系型、交易型数据库这个难度最高但天花板也最高的市场；第三，从 Day One 把全球化写进公司基因；第四，在近几年完成从软件公司向数据库云服务公司的转型。

在开源商业化上，他强调代码本身不是全部价值，真正的价值在于持续演进的方向控制、社区信任、工程投入和认知领先。早期商业化如果只是向大用户「收保护费」，会破坏开源信任；直到云服务和 SaaS 模式成熟，开源生态与商业化才找到了更不冲突的结合方式。

在全球化上，东旭反复区分「出海」与「本地化」：前者容易停留在外来者、出差和试试看心态；后者则要求创始人亲自投入，在当地生活、招本地团队、建立本地客户关系，并用全球化工作语言和组织体系倒推公司建设。

对 AI，他认为数据库公司的机会在于「context」与「memory」。未来数据库的使用者不只是人类开发者，也可能是 agent。企业软件会被新的 AI interface 重构，而企业最宝贵的资产仍然是数据。AI 时代的数据层、上下文层和记忆层，会成为新的基础设施机会。

## 金句收藏

> 数据库可以理解为数据的容器。过去的杯子容量有限，TiDB 要做的是一个能随水量自动变大的魔法杯。

> 顶级开源项目不是把最终代码放出来，而是从第一天开始，把构建过程、文档、决策和演进路径都开放出来。

> 源代码本身没有价值，真正有价值的是做题过程中的思路，以及持续演进的方向和速度。

> 对基础软件创业公司来说，开源既是获取客户信任的方式，也是撬动外部人才的方式。

> 方向比跑得快更重要。

> 你必须找到一个和开源不冲突的商业模式；传统授权模式容易冲突，云服务给了新的答案。

> 很多人的国际化是被迫的，被迫就容易有看牌心态；真正的全球化需要从第一天就当成战略。

> 我不喜欢「出海」这个词，它默认你的屁股还在中国，只是出去一趟；真正重要的是在当地成为 local。

> 如果做美国市场，创始人至少要去当地生活一段时间，尽早亲自卖东西。

> 做海外市场没有什么神秘方法，很多坑本质上是不尊重常识。

> 中国创业者常常高估语言障碍，也高估海外商业化的难度。

> 现在的 AI 时代像狂野西部，小公司也有机会定义开放标准，关键是足够开放、有人用、形成网络效应。

> 企业运营的核心是数据和常识；常识 LLM 有，但企业自己的数据最宝贵。

> 尊重常识，不要总想着搞花活。

## 核心要点

### 1. PingCAP 做的是「数据容器」：让数据库容量随业务增长自动扩展

东旭把 TiDB 解释为一个分布式数据库，也可以理解为「数据的容器」。在数字世界中，小红书、微信支付、外卖、银行卡交易等行为背后，都依赖数据库来存储和处理数据。

传统数据库像一个容量有限的杯子。当业务增长、数据越来越多时，工程师可能需要管理很多个杯子，这会带来很高的复杂度。TiDB 要解决的问题，是让使用者仍然像面对一个杯子，但底层的杯子可以自动扩展，承接不断增长的数据。

因此，TiDB 的价值不只在技术指标，而在于降低快速增长公司管理数据基础设施的复杂度。它尤其适合移动互联网、金融交易、大型企业等数据量和并发需求快速增长的场景。

### 2. 从第一天开源：开源不是发布代码，而是开放构建过程

东旭特别强调，很多人误解了开源，以为开源就是把写完的代码放到 GitHub 上。真正顶级的开源项目，应该是全生命周期开放：从文档、设计、讨论、代码到版本演进，都能让外部参与者看到路径。

他用餐厅后厨做比喻：如果只是给用户菜谱，不足以建立信任；真正的透明，是让用户看到食材采购、加工、烹饪的全过程。

对数据库这样的基础设施软件来说，客户会把关键业务托付给它。如果软件是黑盒，用户很难放心。开源让客户能看到系统如何被构建、如何演进、如何处理问题，因此是建立信任的重要机制。

### 3. 开源的护城河不是代码，而是认知、方向和持续投入

曲凯追问：既然全部开放，是否会被大公司或竞争者复制？东旭的回答是，答案本身不够，做题思路才有价值。

软件不是一次性完成后放在那里，而是持续演进的系统。PingCAP 作为 TiDB 从第一天开始的领路人，掌握项目方向、迭代速度和大量历史 know-how。随着投入累积，后来者即使看到代码，也很难复制多年工程投入和社区信任。

当项目进入成熟阶段，护城河已经包括：

- 持续多年投入形成的工程复杂度；
- 核心团队对系统历史问题和设计权衡的理解；
- 用户社区和企业客户的心智占位；
- 对项目未来方向的控制能力；
- 由开源协作带来的外部人才网络。

### 4. 十年中的关键战略：开源、关系数据库、全球化、云服务

东旭总结 PingCAP 的几个关键节点：

1. **选择开源**：对基础软件来说，开源带来客户信任，也能吸引全球开发者和外部工程资源参与。
2. **选择关系型交易数据库**：这是数据库领域最难的方向之一，但市场空间也最大。选择更大的市场，意味着一旦做成，商业上限更高。
3. **选择全球化**：PingCAP 从早期就认为技术软件不带强文化属性，有机会做成全球标准，因此全球化不是后期补救，而是基因。
4. **转向云服务**：公司从卖软件 license 和服务，转向数据库云服务。东旭表示，今天 PingCAP 已经有大部分 ARR 来自云服务，而不是传统私有部署软件售卖。

### 5. 为什么 2015 年仍有数据库创业机会

虽然 2015 年不是移动互联网最早期，但东旭认为当时底层条件刚好成熟。

一方面，数据中心硬件发生变化：网络带宽提升、SSD 普及、存储价格下降，这让大规模分布式数据库具备了现实可行性。许多算法和设计过去就存在，但受限于硬件条件，很难真正落地。

另一方面，互联网技术开始向传统企业扩散。银行、大型企业等客户有真实的传统数据库替换需求，互联网公司验证过的新技术开始进入 enterprise 场景。PingCAP 正好站在底层硬件成熟和企业技术栈更新的交汇点上。

### 6. 早期融资的非共识：看代码价值，还是看短期收入

PingCAP 早期收入并不高，但估值一路上升。东旭认为，基础软件像 moonshot，杠杆很高；数据库是所有公司都要用的基础设施，如果能成为通用型数据库，价值空间巨大。

但早期项目高度非共识：懂技术的人能从源代码、架构设计和工程能力中看到潜力；看不懂的人只能用收入、客户数等传统指标判断，而这些指标无法充分反映基础软件的长期价值。

当时虽然很多客户不付钱，但已经有大量互联网企业深度使用 TiDB 解决重要问题，甚至愿意派工程师参与开源贡献。对投资人来说，这种 adoption 代表真实社会价值，只是商业化还没有完全捕获。

### 7. 开源商业化的教训：不能用「收保护费」破坏信任

PingCAP 早期曾尝试让销售向大用户收费，但东旭后来认为这不是好的商业化方式。

如果销售只是利用信息不对称，告诉用户「不给钱就无法获得支持或保障」，这会和开源信任机制冲突。开源用户之所以信任项目，正是因为它透明、开放、可验证。一旦商业化策略让用户感觉被要挟，就会损害社区根基。

因此，PingCAP 前几年主动克制商业化，把重点放在产品、社区和基础能力建设上。直到云服务模式成熟，开源生态与商业收入之间才有了更自然的结合：社区负责生态和信任，云服务负责商业转化和持续服务。

### 8. 云服务是开源商业化的关键答案

东旭认为，现在做开源基础软件比十年前更幸福，因为路径更清晰：默认开源做社区和生态，商业化依靠 SaaS 或云服务。

MongoDB、Databricks、Snowflake 等公司的发展路径，都验证了「软件公司转向软件服务公司」的价值。对数据库来说，云服务不仅是交付方式变化，更是公司形态变化：从卖一次性软件，变成长期运营服务。

他也指出，国内企业对软件价值的认知和云化速度相对慢一些，私有化部署、软硬结合、人天服务仍然普遍。相比之下，海外客户更习惯为软件和云服务付费，云厂商生态也更成熟。

### 9. 全球化不是出差，而是在当地成为 local

东旭非常反感「出海」这个词，因为它隐含一种外来者心态：总部在国内，海外只是出去看看、试试看。

在他看来，真正的全球化至少包括几个后验指标：

- 文档和产品从一开始就英文优先；
- 代码、注释、文档不依赖中文语境；
- 内部会议和 IM 逐渐使用英文，方便未来全球团队回看和协作；
- 海外员工的招聘、入职和工作体验，不会强烈感知这是一家「中国公司」；
- 各区域形成自己的 CEO、CTO、技术和商业团队，而不是「中国总部 + 海外分支」。

PingCAP 第一个客户拿到软件时甚至没有中文文档，后续才临时翻译。这不是刻意「去中国化」，而是顶级开源软件默认面向全球开发者协作。

### 10. 创始人必须亲自进入海外市场

东旭认为，海外业务前几年通常是在交学费，不能指望一开始就赚钱。如果只是招一个职业经理人或海外大佬试试看，很难真正建立业务。

创始人需要亲自去当地，建立客户关系、招本地销售、理解当地 GTM 方式，甚至生活在当地。他认为自己最大的坑之一，就是没有更早搬到美国。

选择美国而非其他市场，是因为软件产业的两个高峰在中国和美国，尤其是硅谷。先占据美国这个软件产业高地，反过来辐射日本、欧洲和其他区域，会更省力。

### 11. 给 AI 创业者做美国市场的建议

东旭给出的建议很直接：

- 不管用什么签证，先去当地生活一段时间，至少半年；
- 尽早开始商业化，不要只用技术视角做产品；
- 找本地销售一起行动，创始人亲自卖东西；
- 学习美国市场讲故事、包装 message、做 GTM 的能力；
- 不要高估语言障碍，敢说、敢交流比完美英语更重要；
- 不要低估自己产品的价值，很多中国创业者不敢卖高价。

他认为，很多海外商业化并没有想象中神秘，关键是尊重常识、做重的事情、长期经营客户关系。

### 12. AI 时代数据库的新机会：context、memory 与 agent

对 AI 未来，东旭最关注的是记忆和上下文。LLM 要真正理解企业或个人，需要更好的 context。数据库公司天然站在数据和上下文这一层。

过去数据库的用户主要是程序员、DBA 和开发者；未来使用数据库的，可能是 agent。站在 agent 视角，什么是好的 database、如何访问数据、如何管理记忆，都会和人类使用数据库不同。

他提出，MCP 定义了 agent 与 tool 的交互，A2A 定义了 agent 之间的交互，但通用的 sharing memory layer 仍有大量探索空间。AI 时代像狂野西部，小公司也有机会定义开放标准，只要协议足够开放、有人用，并形成网络效应。

### 13. 企业服务会被 AI interface 重构

东旭看好企业服务端机会。DeepSeek 等模型的出现，标志着 LLM 基础能力已经足以做有用的事情，第一波被改造的会是企业软件。

企业软件过去常常是大而全、静态、需要专人操作的系统。未来可能被切成更小的能力块，由 LLM agent 串联起来。每个员工都可能拥有一个个人助理，通过对话访问企业数据、生成报表、分析客户、推动工作流。

但企业最宝贵的东西仍然是数据。常识模型可以提供，企业自己的客户、销售、运营和产品数据却不能轻易交出去。正因如此，数据库和数据层的重要性会继续上升。

### 14. 十年创业带来的个人变化：更有耐心，尊重常识

东旭回顾十年创业，认为自己最大的变化是更有耐心。早期想到什么就马上动手，容易焦虑和乱动；后来发现，如果方向经过反复验证是对的，就应该给时间，而不是频繁折腾。

他也强调精力管理和个人爱好。创业是长期消耗，不能只有工作。音乐、运动、艺术创作等出口，有助于维持心态和韧性。

最终，他把很多经验归结为一句话：尊重常识，不要搞花活。很多道理听起来简单，但真正长期做到并不容易。

## 关键问答

### Q1：PingCAP 到底做什么？

A：PingCAP 做的是 TiDB，一个分布式关系数据库。可以把它理解为数据的容器：传统数据库容量有限，而 TiDB 希望让这个容器随数据规模自动扩展，让开发者仍然像使用单个数据库一样管理大规模数据。

### Q2：为什么选择从第一天开源？

A：因为基础设施软件需要极高信任。开源让用户看到软件如何被构建和演进，也能吸引外部工程师参与。真正的开源不是最后发布代码，而是全生命周期开放。

### Q3：开源会不会被复制？

A：东旭认为，代码不是全部价值。真正的竞争力在于持续演进的认知、方向控制、工程投入、历史 know-how 和社区心智。后来者看到答案，不代表能复制做题过程。

### Q4：为什么早期不急着商业化？

A：数据库是长期投入的基础软件，过早商业化可能牺牲产品根基。早期向开源大用户收费，如果只是制造信息不对称，会破坏开源信任。PingCAP 后来把商业化重点转向云服务。

### Q5：开源商业化的标准答案是什么？

A：东旭认为今天较清晰的路径是：开源做生态和社区，商业化靠 SaaS 或云服务。云服务让商业模式和开源信任更不冲突。

### Q6：全球化和「出海」有什么不同？

A：「出海」容易是外来者心态，像出差或试试看；全球化是从产品、文档、组织、语言、客户关系到团队构成，都按全球公司建设。关键是在当地成为 local，而不是从总部远程管理海外。

### Q7：创始人做海外市场最该避免什么？

A：避免只待在国内想海外市场，避免把海外当短期试验，避免只招职业经理人代替自己进入市场。创始人必须亲自去当地生活、见客户、招人、卖东西。

### Q8：AI 创业者进入美国市场应该先做什么？

A：先去当地生活至少半年，尽早做商业化，和本地销售一起跑客户，学习讲故事和 GTM message，不要高估语言障碍，也不要低估产品价值。

### Q9：AI 时代数据库公司有什么机会？

A：机会在 context、memory 和 data layer。未来 agent 需要访问企业数据、构建长期记忆、理解业务上下文。数据库不再只服务开发者，也会服务 AI agent。

### Q10：创业十年最大的收获是什么？

A：更有耐心，尊重常识，少搞花活。方向对时要给时间，同时管理好精力，保持工作之外的爱好和出口。

## 润色版逐字稿

### 开场：从程序员、音乐爱好者到基础软件创业者

本期嘉宾是 PingCAP 联合创始人兼 CTO 东旭。东旭介绍自己一直在写代码，喜欢软件、开源文化，也喜欢艺术和音乐，平时玩乐器、做音乐。

曲凯提到，PingCAP 在程序员圈和投资圈都很有知名度：程序员熟悉它的技术和开源项目，投资人知道它融资和估值很高，但更广泛的人群未必清楚它具体做什么。

东旭解释，PingCAP 的核心产品 TiDB 是一个分布式数据库，可以理解为「数据的容器」。我们每天使用外卖、支付、社交产品，背后都有数据库在存储和处理数据。传统数据库的容量有限，而今天的数据越来越多、增长越来越快，工程师不能一直用一堆杯子装水。TiDB 希望让这个杯子自动变大，让用户仍然像使用一个数据库，却能承载越来越大的数据量。

### TiDB 的价值：看不见，但支撑很多数字生活

东旭举例，很多互联网、金融和交易场景背后都可能使用 TiDB。用户未必直接知道 TiDB 的存在，但只要生活在数字世界中，就可能间接使用到它支撑的系统。

PingCAP 2015 年成立，前两年主要在写代码。它从第一天就是开源项目，但东旭强调，这里的开源不是写完代码再上传，而是从写文档、记录设计、开放演进路径开始。

在他看来，顶级开源项目应该是全生命周期开放。就像餐厅不只是给你菜谱，而是让你看到透明后厨，看到食材如何被采购、加工和做成菜。基础软件尤其需要这种透明，因为用户会把关键业务交给你。

### 开源不怕被抄：答案之外，还有做题思路

曲凯问，既然一开始就开放，是否担心别人看到思路后复制，甚至大公司下场做同样的东西。

东旭回答，考试时给你答案也不够，真正有价值的是做题过程中的思路。源代码本身不是最核心的价值，因为软件一直在快速迭代。PingCAP 作为项目从第一天开始的领路人，掌握项目方向、迭代速度和大量历史 know-how。

随着多年投入累积，后来者即使想进入，也需要投入巨大的工程资源。即便是大云厂商，也很难一下投入足够多熟悉这个系统历史的人。开源项目的护城河不是某一份代码，而是持续演进的组织能力和认知。

### 十年关键选择：开源、关系数据库、全球化和云

回顾 PingCAP 十年，东旭认为第一天就做了几个关键战略选择。

第一个是开源。对基础软件公司来说，开源能带来企业客户信任，也能撬动外部人才。

第二个是选择关系型交易数据库。这个方向像数据库领域的珠穆朗玛峰，复杂、困难，但商业天花板非常高。选择大市场，哪怕难度更高，一旦做成，价值也更大。

第三个是全球化。东旭相信技术软件天然有机会成为全球标准，不需要每个市场重复造一个系统。PingCAP 从早期就希望做全球公司。

第四个是云服务转型。过去 PingCAP 是卖软件 license 加服务的公司，现在更多是数据库云服务公司。东旭认为，数据库和数据库服务听起来接近，但公司形态和商业模式有天壤之别。

### 为什么当时能做数据库创业

东旭回忆，三位创始人原来都在豌豆荚做底层数据基础设施。对程序员来说，做分布式关系数据库本身就是极具吸引力的工程挑战。

后来复盘，他们也正好踩中了底层硬件条件成熟的时点。数据中心网络带宽提升，SSD 开始普及并降价，大规模分布式系统有了更好的硬件基础。过去许多算法和设计早已存在，但底层条件不成熟，难以落地。

与此同时，互联网技术开始影响传统企业。银行、大型企业等客户需要替换传统数据库，互联网公司验证过的技术开始进入企业技术栈。PingCAP 正好出现在这个窗口期。

### 估值、adoption 与非共识

曲凯提到，PingCAP 在规模化收入真正起来前，估值已经很高。东旭认为，基础软件的杠杆很高，数据库是所有公司都会用的基础设施。如果能做成通用数据库，价值空间巨大。

但早期非常非共识。懂技术的人能看出代码和架构背后的价值；不懂的人只能看收入和客户数字，而这些短期指标无法反映软件的真实价值。

PingCAP 当时不是没有客户，而是很多客户不付钱。大量互联网公司使用 TiDB 解决关键问题，甚至有企业愿意派工程师参与项目贡献。东旭认为，这代表真实的社会价值，只是还没有转化成收入。

### 商业化的坑：不要向开源用户收保护费

PingCAP 早期也尝试过销售策略。东旭发现，如果销售跑去向大开源用户收费，潜意识动作很容易变成「不给钱就不给支持」，这像收保护费。

这种方式和开源逻辑相反。开源建立在透明和信任之上，如果商业化靠制造信息不对称，会损害根基。因此 PingCAP 早期宁愿不做低级商业化，继续投入产品和社区。

今天东旭认为，开源商业化更标准的路径是开源做生态、社区和信任，收入靠 SaaS 和云服务。这也是为什么他觉得现在做开源软件比十年前更清晰。

### 云服务与海外市场

PingCAP 转向云服务，一方面来自技术判断：云会成为未来的计算机，数据库系统也要云原生化；另一方面也来自商业模式变化的外部验证。MongoDB 等公司展示了软件公司转向软件服务公司的价值。

东旭认为，云和国际化紧密相关。国内对软件价值和云服务的付费认知相对慢一些，很多企业仍然习惯私有化部署、软硬结合、人天服务。海外市场更愿意为软件和云服务付费，云厂商生态也更成熟。

### 全球化：英文文档、英文会议和本地组织

曲凯问，很多公司口头上说国际化，但只是「不拒绝国际化」。东旭认为，真正全球化要看几个指标。

第一，文档是否英文优先。PingCAP 从第一份文档开始就是英文，代码注释也不依赖中文语境。第一个客户反而需要临时翻译中文文档。

第二，内部 IM 和会议能否使用英文。PingCAP 大约在 2022 年做到这一点。即使会议上全是中国人，只要会议需要留档、未来可能被全球团队回看，就应该使用英文。

第三，海外新员工是否能在招聘、入职和工作体验中感受到一家全球公司，而不是一个来自中国的外派组织。

东旭认为，这不是刻意去除某种身份，而是按全球协作的默认方式做事。

### 出海心态与 local 心态

东旭不喜欢「出海」这个词，因为它默认人还在原地，只是出去做业务。真正重要的是在当地成为 local：创始人搬过去，建立本地团队、本地客户关系和本地组织。

他认为，海外业务前三年常常是在交学费。如果没有前三年亏损的心理预期，只是试试看，很难成功。

PingCAP 也踩过坑，比如一开始用中国团队加少量 local team 去做海外，或者在海外商业化中仍由中国人主导。但真正面对美国客户时，本地销售、本地关系和本地表达非常重要。

### 为什么先做美国市场

曲凯问，为什么不是日本或新加坡。东旭认为，软件产业的高峰主要在中国和美国，尤其是硅谷。打仗要占山头，先在美国建立影响力，再辐射其他 region，效率更高。

比如进入日本市场时，如果客户认为你是一个顶级美国项目，认可度会更高。先做美国，再反向影响其他区域，可能比一个个市场逐个推进更省力。

### 给 AI 创业者的海外建议

东旭建议，AI 创业者如果想做美国市场，第一步是不管签证方式，先去当地生活一段时间，至少半年。

第二步是尽早商业化。很多技术背景创始人容易只看产品和技术，但商业才是最直接的指南针。产品 ready 后，就找本地销售一起跑客户，创始人亲自卖。

第三步是学习讲故事。美国市场在 GTM、message framework 和品牌表达上有成熟方法论，中国创始人往往太踏实，不够会讲故事。英语不是最大障碍，敢交流、敢表达更重要。

东旭还提醒，不要低估自己的产品价值。很多创业者产品很好，但不敢卖高价；而海外客户往往更愿意为好产品直接付钱。

### AI 时代：数据库要服务 agent

谈到 AI，东旭最关注的问题是记忆和上下文。LLM 要真正服务企业，需要理解企业自己的数据、流程和背景。

数据库公司天然提供 context 工具。但未来数据库的用户不只是程序员，也可能是 agent。站在 agent 角度，什么是好数据库、如何访问数据、如何共享记忆，都需要重新设计。

他提到，MCP 定义了 agent 和 tool 的交互，A2A 定义了 agent 之间的交互，但通用的 sharing memory layer 还没有行业标准。这个方向仍有很多机会。

### 企业软件的新 interface

东旭认为，LLM 基础能力已经到达可以做有用事情的阶段，第一波改造会发生在企业软件。

企业软件过去是复杂的大系统，需要人去学习界面、配置报表、操作流程。未来可能变成一个新的 interface：每个人都有个人助理，助理访问企业数据池，替人完成分析和动作。

例如销售管理系统中，过去需要专人做报表、查数据；未来可以直接问 data agent：最近销售在看哪些客户？过去一个月谁跑得最勤？哪些客户值得关注？

因此，企业软件会从大而全的静态系统，被拆成小块能力，由 LLM agent 串联。

### 数据仍然是企业最宝贵的资产

曲凯追问，未来入口是否会被 OpenAI 这样的模型公司掌握。东旭认为，模型要真正有用，必须连接企业数据。

运营企业有两个关键：数据和常识。常识 LLM 有，但企业最宝贵的是自己的数据。过去很多交互数据可能被丢掉，因为用不上；现在它们会成为未来个性化服务和企业智能的关键。

因此，企业会越来越重视数据所有权和数据安全。数据库公司的生意，反而会因为 AI 变得更重要。

### 创业十年的个人变化

最后，东旭回顾自己的成长。他说自己以前想到什么就干什么，动手太快；十年后变得更有耐心。很多时候如果方向是对的，就应该少一点乱动，交给时间。

他也强调精力管理。能长期创业，需要保持心态、身体和爱好。音乐、艺术、运动都是出口。不要只有工作。

最后的建议仍然是尊重常识。很多方法论学到最后，会发现其实都是常识。难的是长期做重的事，而不是追求花活。
