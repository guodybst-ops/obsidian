## 📌 摘要

这一期是对大模型落地和 LLMOps 的一站式解释。路宇从 Dify 的定位讲起：它不是简单的开发框架，也不是传统 DevOps，而是一套面向大模型应用的开发和运营工具。传统 DevOps 里的 ops 更偏运维，关注服务器、可用性和性能；而 LLMOps 里的 ops 更偏运营，因为 AI 应用需要业务人员、运营人员、销售人员等非技术角色不断参与，把经验和反馈灌进大模型应用里。

节目围绕大模型应用从易到难拆了几层：Prompt 工程、Embedding、Fine-tuning、Agent，以及中间层平台为什么存在。路宇认为，大多数应用开发者不应该一上来就投入大量成本解决模型技术问题，而应该学会利用已有模型能力，找到足够精确、足够小、能落地的用户问题。Dify 的价值，正是在上游多模型和下游海量应用之间，替开发者处理重复、脏、工程化的基础设施工作。

这期也呈现了 2023 年大模型创业的关键张力：一方面大家容易高估大模型能力，以为它什么都能做；另一方面又容易在落地挫折后迅速悲观。曲凯和路宇都更接近中间态：大模型像一手不完美但不差的牌，真正重要的是怎样通过策略、产品定位、工程化和中间层，把这手牌打好。

## 📌 核心要点

### 一、LLMOps 的核心不是运维，而是让 AI 应用持续被业务塑造

- 路宇把 LLMOps 解释为大模型应用开发和运营的一套完整技术栈。
- 它和 DevOps 一样强调持续迭代，但传统 DevOps 的 ops 更偏服务器、性能和可用性；LLMOps 的 ops 更偏运营和业务反馈。
- AI 应用不是一次性开发上线，而是要不断根据用户反馈、业务知识和运营经验调整 Prompt、Agent、模型调用和知识库。

### 二、大模型应用工程化可以分成 Prompt、Embedding、Fine-tuning 三层

- Prompt 工程是最轻量的方式，通过指令、样例和上下文控制模型输出。
- Embedding 可以把私有知识以“外脑”的方式嵌入到调用过程中，让模型回答超出自身训练截止时间和公共知识范围的问题。
- Fine-tuning 门槛更高，需要大量高质量样本和算力资源，只有在必须改变模型默认行为或风格时才更适合。

### 三、Agent 代表从“帮你更快完成事”走向“替你完成事”

- 路宇把 Agent 定义为模型利用上下文、推理能力和工具，完成连续动作、达成目标的技术形态。
- 当前 Agent 有三种形态：手工编排、完全自主，以及两者之间的混合状态。完全自主往往不可控，混合状态更接近现阶段可落地路径。
- Agent 的吸引力在于技术平权：一个工程师第一次如此接近一个强大的自动化武器，有机会用小团队做过去大公司才能做的事情。

### 四、中间层机会来自模型和应用之间的大量重复脏活

- 曲凯看好 Dify 的原因，是他们从应用层出发，看见大量团队把时间浪费在基础设施、可控性和可落地性问题上。
- 如果未来模型是多模型共存、应用是海量分散的，那么中间层就有机会成为连接上游模型和下游开发者的平台。
- 但中间层不能离模型太近，否则容易被模型厂商吃掉；也不能离 C 端太近，否则会变成竞争激烈的 To C 平台。Dify 的位置在开发者和应用工程化中间。

### 五、落地 AI 应用不应从“大问题”开始

- 节目后半段强调，应用公司不适合把大量精力投入突破底层技术局限。
- 更好的路径是利用已有技术，找到更小、更精确、更容易出结果的问题。
- 像妙鸭、绘读这类产品的启发在于：它们并不等模型完美，而是用现有能力做出用户能理解、能使用的产品定位。

### 六、未来大模型发展的三个方向：多模态、小型化、数据向量化

- 路宇认为，多模态训练会显著提升模型能力，因为当前文本模型还像只“看小说”，未来需要“看 4D 电影”。
- 模型小型化和移动化会让大模型不完全依赖云端，未来可能像家庭 Wi-Fi 一样部署在本地设备中。
- 所有有知识产权的内容，未来都可能以 AI 可读的形式重新出版，即向量化之后让模型像加载 U 盘一样使用。

## ❓ 关键问答

**Q1：Dify 到底解决什么问题？**

A：Dify 解决的是大模型应用开发和运营中的工程化问题。它帮助开发者把模型、Prompt、私有知识、工具调用、Agent 和反馈迭代组织起来，让 AI 应用从实验走向可投产。

**Q2：LLMOps 和传统 DevOps 有什么不同？**

A：传统 DevOps 的 ops 更像运维，关注基础设施和应用可用性；LLMOps 的 ops 更像运营，强调业务人员持续参与，把领域经验、用户反馈和运营判断注入 AI 应用。

**Q3：Prompt、Embedding、Fine-tuning 应该怎么区分？**

A：Prompt 是最轻量的控制方式；Embedding 适合给模型接入私有知识和外部数据；Fine-tuning 成本更高，适合改变模型风格或默认行为。多数应用不应一开始就微调，而应先判断 Prompt 和 Embedding 是否足够。

**Q4：为什么大家对 Agent 这么兴奋？**

A：因为 Agent 让模型从单次回答走向连续行动。它有机会从“帮人更快完成任务”升级为“替人完成任务”，成熟后甚至像一个员工。它也让小团队第一次拥有接近大公司自动化能力的工具。

**Q5：为什么曲凯看好 Dify 这种中间层？**

A：因为他从应用层看见了大量重复基础设施工作：开发者并不想每次都自己处理模型接入、知识嵌入、可控性和落地问题。如果上游模型分散、下游应用海量，中间层就可能成为关键入口。

**Q6：这期对 AI 创业者最大的提醒是什么？**

A：不要把全部精力投入“解决模型技术局限”，而要利用已有模型能力，更好地定义用户需求、找到精确场景、做出可用产品。大模型不是同花顺，但也不是烂牌，关键是怎么打。
