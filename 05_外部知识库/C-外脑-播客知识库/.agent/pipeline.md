> 本文档定义从来源收件箱到播客知识库的完整执行流程。
> 每次执行前先读取 `rules.md` 确认目录边界，再按本文档的顺序推进。
>
> 最后更新：2026-07-17

---

## 总览

```
阶段一【搬运】  阶段二【拆解】           阶段三【补缺】              阶段四【合成】
     │               │                      │                        │
A-外脑收件箱   89单集笔记/             99原始资料/              01/02/03/04 原子节点
  ┌─┴─┐         ┌─┴─┐                    ┌─┴─┐                    ┌─┴─┐
```

## 阶段一：搬运

### 目标

将来源目录的转录原文和播客笔记物理移动到播客知识库对应目录。

### 来源

```
A-外脑收件箱/99-待归类旧资料/
├── 07-Archive 归档/播客转录/     ← 3584 个文件，转录原文
├── 06-Library 资料/播客笔记/     ← 190 个文件，已提炼笔记
└── 06-Library 资料/课程笔记/播客笔记/  ← 2 个文件，可能重复
```

### 目标

```
C-外脑-播客知识库/
├── 99原始资料/<节目名>/           ← 转录原文，按节目分目录
│   ├── 清洗文本/
│   ├── 原始转写/
│   └── 元数据/
│
└── 89单集笔记/<节目名>/           ← 单集笔记，按节目分目录
    └── 第X集 标题.md
```

### 执行步骤

#### Step 1：转录原文 → 99原始资料

1. 遍历 `07-Archive 归档/播客转录/` 下每个节目目录
2. 对于每个节目，将整个文件夹移动到 `99原始资料/<节目名>/`
3. 特别注意：清洗文本放在 `清洗文本/` 子目录，原始转写放在 `原始转写/` 子目录，元数据放在 `元数据/` 子目录（如果来源已有子目录结构，保留）
4. 完成后检查：没有遗漏任何节目

#### Step 2：播客笔记 → 89单集笔记

1. 遍历 `06-Library 资料/播客笔记/` 下每个节目目录
2. 对于每个节目，将整个文件夹移动到 `89单集笔记/<节目名>/`
3. 检查 `06-Library 资料/课程笔记/播客笔记/` 下 2 个文件是否与 Step 2 已移动的重复——如果重复，跳过；如果不重复，也移入 `89单集笔记/`

#### Step 3：补 Frontmatter

对于 89 单集笔记中缺少 frontmatter 的文件，批量添加标准 frontmatter 模板：

```yaml
---
podcast: "[[节目名]]"
episode: 第X集
title: "原标题"
guest: ""
date:
extraction_status: pending
extracted_at:
---
```

注意：如果笔记已有 frontmatter，保留原有内容，仅补充缺失字段。

#### Step 4：清理来源目录

1. 确认所有文件已成功移动后，删除来源目录下的空目录

### 完成标准

- [ ] 99原始资料/ 下所有节目都有了转录原文
- [ ] 89单集笔记/ 下所有节目都有了笔记
- [ ] 所有 89 笔记 frontmatter 包含 `extraction_status` 字段
- [ ] 来源目录已清理

## 阶段二：拆解（有笔记的节目）

### 目标

对已有单集笔记的节目，逐集拆解为 01/02/03/04 原子节点。

### 来源

```
89单集笔记/
├── 42章经/              ← 53 集笔记
├── 给女孩的商业第一课/   ← 114 集笔记
└── 平民创业手册/         ← 23 集笔记
```

### 目标

01/02/03/04 目录下开始有内容。

### 执行步骤

#### Step 1：确认拆解顺序

优先拆解内容密度最高、笔记质量最好的节目。推荐顺序：
1. 42章经（53 集，笔记质量高，AI/投资/商业话题集中）
2. 给女孩的商业第一课（114 集，量大，多人物）
3. 平民创业手册（23 集，实操性强）

#### Step 2：单集拆解流程

对每集笔记，执行以下子步骤：

1. **读取** 89 单集笔记的完整内容
2. **分类** 笔记中的每条信息，按 rules.md 的判断决策树归入 01/02/03/04
3. **写入** 对应文件：
   - 金句/观点 → 找到或创建 `01人物原萃/<嘉宾名>.md`，追加到对应段落
   - 方法/框架 → 找到或创建 `02方法流程/<方法名>.md`，追加来源
   - 概念 → 找到或创建 `03概念链接/<概念名>.md`，追加多源表述
   - 判断取舍 → 找到或创建 `04判断哲学/[判断] <决策节点>.md`，追加候选路径、选择依据、不选理由和反转条件
4. **链接** 在新写入的内容中加上 Wiki Link 回到来源笔记
5. **标记** 在 89 笔记的「拆解记录」段落追加本次拆解记录，更新 `extraction_status`

#### Step 3：跨集合并规则

当写入 02 方法或 03 概念时，检查目标文件是否已存在：
- 已存在 → 追加来源到「来源」段落，补充差异到正文
- 不存在 → 创建新文件，按 rules.md 模板初始化

对于 01 人物，同一嘉宾在多集出现时，追加到同一文件的不同段落（金句追加到金句段落，观点追加到对应主题段落）。

#### Step 4：处理嘉宾索引

拆解完一个节目后，检查出现了哪些嘉宾，为每个嘉宾创建 01 文件（如果还没有），并补充 podcast_sources。

### 完成标准

- [ ] 42章经全部 53 集拆解完成
- [ ] 给女孩的商业第一课全部 114 集拆解完成
- [ ] 平民创业手册全部 23 集拆解完成
- [ ] 所有已拆解笔记的 `extraction_status` 为 `complete`
- [ ] 每位嘉宾都有 01 人物文件

## 阶段三：补缺（无笔记的节目）

### 目标

对只有转录、没有提炼笔记的 13 个节目，生成单集笔记后再拆解。

### 来源

```
99原始资料/
├── 中国好生意/
├── 义乌听见/
├── 商业就是这样/
├── 好有共鸣/
├── 姜Dora在此/
├── 富女孩宝典/
├── 我是销冠/
├── 搞钱女孩/
├── 搞钱学姐/
├── 破局点/
├── 组织进化论/
├── 罗永浩的十字路口/
└── ...其他
```

### 执行步骤

#### Step 1：生成单集笔记

对每个节目的每集转录：
1. 读取 `99原始资料/<节目名>/清洗文本/第X集.md`（如果清洗文本不存在，用原始转写）
2. AI 提炼为标准笔记格式（摘要 + 金句 + 核心要点 + 关键问答）
3. 写入 `89单集笔记/<节目名>/第X集 标题.md`，frontmatter 补全

#### Step 2：拆解（同阶段二）

对新生成的 89 笔记，按阶段二的流程逐集拆解进 01/02/03/04。

#### Step 3：分批执行

13 个节目不需要一次性全部处理完。建议按优先级分批：
- **第一优先**：话题集中、与已有节目互补的（如破局点、搞钱女孩）
- **第二优先**：转录质量好、内容密度高的
- **第三优先**：剩余节目

每批处理完一个节目后，标记进度。

### 完成标准

- [ ] 所有 13 个节目的转录都已生成 89 单集笔记
- [ ] 所有新增笔记已拆解进 01/02/03/04
- [ ] `extraction_status` 均为 `complete`

## 阶段四：合成

### 目标

基于 01/02/03/04 积累的原子节点，做跨节目专题合成，产出有判断的深度研究。

### 前置条件

- [ ] 至少 3 个以上节目已完成拆解（阶段二 + 阶段三）
- [ ] 01/02/03/04 中已有一定数量的节点

### 执行步骤

#### Step 1：发现专题

扫描 01/02/03/04，寻找跨节目反复出现的主题。判断是否值得做专题：
- 至少涉及 2 个以上节目/人物/概念/判断节点
- 有足够素材支撑分析
- 能够形成清晰的论点

#### Step 2：写作

按 rules.md 中 05 深度研究的模板写作：
1. 一句话论点
2. 背景说明
3. 核心分析（按逻辑分段）
4. 共识与分歧
5. 判断/启示（标注 [AI推理]）
6. 信息来源（完整的 Wiki Link 追溯链）

#### Step 3：回链

在深度研究文件中引用的所有 01/02/03/04 文件，追加反向 Wiki Link 回到深度研究文件。

### 建议的首批专题

基于现有 3 个有笔记的节目：

- 「AI 投资的共识与分歧」（42章经 + 给女孩的商业第一课）
- 「年入千万的女性创业者的共同特征」（给女孩 + 平民创业手册）
- 「获客方法论：从 3 个播客中学到的打法」（跨三个节目）
- 「定价的底层逻辑：不同行业、不同阶段的定价策略」

### 完成标准

- [ ] 首批 4 个专题至少完成 2 个
- [ ] 所有深度研究文件引用了完整的 Wiki Link 追溯链
- [ ] 所有被引用的 01/02/03/04 文件有反向链接

## 通用规则

### 批量处理的节奏控制

- 每处理完一个节目就停下来让用户检查，不要一口气全跑完
- 阶段二和三建议以「节目」为批次单位，而不是以「集」为单位
- 如果用户对拆解质量不满意，先修正规则再继续

### 错误处理

- 转录质量太差导致无法提炼 → 标记该集 `quality: low`，创建极简版笔记（仅摘要），不强行拆解
- 笔记内容过于稀薄 → 同上的极简处理
- 文件名冲突 → 保留原有文件，追加 `_副本` 后缀，报告用户决策

在 `C-外脑-播客知识库/.agent/progress.md` 中维护进度表：
