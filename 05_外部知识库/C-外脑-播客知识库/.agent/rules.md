## 全局原则

1. **先收再理**：不确定归属的内容先进 89单集笔记，不强行归类
2. **原文神圣不可侵犯**：99原始资料一字不改；引用时标记 `[原话]` vs `[归纳]` vs `[AI推理]`
3. **复利优先**：能跨节目复用的内容才从 89 升级到 01/02/03/04
4. **不创建死链**：Wiki Link 只链接已存在的目标文件
5. **不污染99**：99只放转录原文，任何提炼内容不放99
6. **标注级别**：所有非原文内容必须标注 `[原话]` / `[归纳]` / `[AI推理]` / `[待确认]`

## 全局边界冲突速查表

当一段内容可能属于多个目录时，按此优先级裁决：

| 冲突场景 | 裁决 | 口诀 |
|---|---|---|
| 方法步骤 vs 概念定义 | 有操作步骤→02；纯定义→03 | 「能做」vs「能懂」 |
| 人物观点 vs 通用方法 | 与人解耦仍有效→02；绑定人→01 | 把人名去掉，还有价值吗？ |
| 概念定义 vs 人物观点 | 核心价值在概念澄清→03；在「这个人的看法」→01 | 谁是主角？概念还是人？ |
| 多源汇拢 vs 深度分析 | 只做定义罗列→03；有判断洞察→05 | So what？有结论吗？ |
| 单集总结 vs 跨集合成 | 单一来源→89；跨源有判断→05 | 跨了几条河？ |
| 转录原文 vs 提炼笔记 | 逐字记录→99；有摘要提炼→89 | 改过一个字吗？ |
| 具体取舍 vs 方法/概念 | 讲怎么做→02；讲是什么→03；讲为什么选 A 不选 B→04 | 为什么这样选？ |

## 标注规范

| 标记 | 含义 | 使用场景 |
|---|---|---|
| `[原话]` | 嘉宾原文逐字引用 | 能确认是原话的金句、引语 |
| `[归纳]` | AI 基于原文的提炼，非逐字引用 | 从大段对话中总结出的观点 |
| `[AI推理]` | AI 的判断和洞察 | 跨源分析、模式发现 |
| `[待确认]` | 归纳后不确定准确性 | 转录质量差或多义表述 |

每条观点/金句/方法末尾必须标注来源：`— [[节目名]] 第X集`

## 01人物原萃/ — Persona Skill

### 终极目的

**不是观点归档，是可调用的思维工具。** 遇到某类问题时，调用这个人的思维方式来帮你分析。

每个 01 文件 = 一个 persona skill——回答：
1. 这个人能帮我解决什么问题？（专长）
2. 遇到这个问题时，他会怎么分析？（思维工具）
3. 什么时候不该找他？（调用边界）

### 与 02方法流程 的关系

| | 01人物原萃 | 02方法流程 |
|---|---|---|
| 核心 | 这个人**怎么用**这套方法（有个人色彩） | 这套方法**本身**（与人解耦、可操作化） |
| 实例 | 张津剑判断 AI 浪潮的思考路径 | 结构-节奏判断框架的操作步骤 |
| 交互 | 01 引用 02：`[[02方法流程/xxx]]` | 02 链接 01：在来源中标注提出者 |

### 收录范围

- 嘉宾被**展开讨论**（有定义/有案例/有辨析） → 必须建
- 该人物有至少一个可被提取为「思维工具」的分析框架 → 必须建
- 仅是背景介绍/短暂出镜 → 不建，信息留在 89 单集笔记

### 创建标准

**核心检验**（创建前必答）：
1. 这个人的思考方式能不能形成一个可调用的「工具」（触发场景 + 思考路径 + 输出形式）？
2. 这个工具的类型是否和别人已有工具明显不同？
→ 两个都 Yes 才建。如果只是「他说了一些有道理的话」但没有形成可调用的思考路径 → 留在 89。

### 内部结构

```markdown

- **身份**：
- **背景**：
- **标签**：

## 擅长 & 不擅长
- **擅长**：XXX 类型的问题
- **不擅长**：XXX 类型的问题

## 核心心智模型
<!-- 3-5 个模型，每个含：一句话 + 来源 + 怎么用 + 局限性 -->

### 模型1：XXX
- **一句话**：
- **来源**：[[来源]] 第X集 [原话]/[归纳]
- **怎么用**：触发场景 + 思考步骤
- **局限性**：什么情况下不适用

## 决策启发式
<!-- 速查规则，每条配实例 -->

## 表达DNA（可选）

<!-- 矛盾之处、已知偏见、限性盲区 -->
```

### 质量检验

1. 每个心智模型是否有「局限性」段落？（没有 = 偶像化）
2. 「不擅长」和「盲区」是否真实标注？（没有 = 粉饰）
3. 原文引用是否标注了具体来源？

### 书写逻辑

**视角转变**：不要问「这个人在播客里说了什么」，要问「如果这个人是我团队的一员，我遇到什么问题可以找他」。存档思维 = 按话题平铺观点；蒸馏思维 = 从语料中提取可复用的认知操作系统。

**六层要点**：
- **画像**：3 行做完，不展开故事
- **擅长 & 不擅长**：决定调用时机。不擅长的部分和盲区呼应
- **核心心智模型**：3-5 个，每个含一句话 + 来源 + 怎么用 + 局限性。局限性强制写，不写等于偶像化
- **决策启发式**：每条 = 原则 + 原文实例，不是 AI 编的
- **内在张力 / 盲区**：找到矛盾——他说了 A 但做了非 A，他的框架在 X 有效但在 Y 自相矛盾
- **诚实边界**：信息源密度、利益立场、信息截止日期

**关键原则**：
1. 反偶像化：每模型强制写局限性
2. 标注来源：`[原话]`/`[归纳]`/`[AI推理]` + 来源
3. 诚实标注局限：不让调用者拿残缺工具当万能钥匙

**提炼流程**：素材 → 筛选（有可调用的思维框架吗？） → 提取 3-5 个核心模型 → 补局限性 → 提取启发式 → 反向审视矛盾/盲区 → 写诚实边界 → 质量检验

### 判断决策树

```
素材是关于一个人？
├─ 他有独特的分析框架（不只是观点）→ 提取为核心心智模型
├─ 他有可操作的行动规则 → 提取为决策启发式
├─ 他有明确的盲区和内在矛盾 → 写清内在张力
├─ 他说的话支撑某个心智模型 → 归入原文引用
├─ 他只是说了些有道理的话（没有形成可调用的路径）→ 留在 89
├─ 他说的是一个可与人解耦的方法 → 02
├─ 他说的是一个抽象概念的定义 → 03
└─ 多人物对比 → 04
```

## 02方法流程/

### 终极目的

回答：「怎么做？」「按什么步骤？」「用什么框架思考？」——拿到就能用。

**核心原则**：与人解耦后依然有效。换个人来说同样的话也成立。

**核心检验**（创建任何一个方法文件前必答）：
1. 有人拿着这个文件，能不能在不听原播客的情况下，直接照着做？
2. 文件里有没有一个完整的操作示例（端到端跑一遍）？
3. 如果我删掉文件里所有的「某人说/某人认为」，剩下的部分是否依然成立？
→ 三个都 Yes，才配放在 02。

### 收录范围（6 种子类型）

| 子类型 | 定义 | 实例 | 反例（不是这种） |
|---|---|---|---|
| SOP/操作步骤 | 有先后顺序的具体做法，可逐条执行 | 「内容选题的 5 步流程」 | 「选题的底层逻辑」（那是概念） |
| 框架/模型 | 有结构的心智工具，帮助分析和决策 | 「波特五力」「AARRR」「三层定价法」 | 「商业模式画布的定义与起源」（那是概念） |
| 公式/指标 | 可计算的判断标准或量化工具 | 「获客成本 CAC = 总营销支出÷新客数」 | 「获客成本的影响因素」（那是深度研究） |
| 模板/清单 | 可直接套用的工具，填空题式的 | 「投资人尽调 30 问」「活动 SOP 模板」 | 「尽调的注意事项」（那是深度研究） |
| 策略/打法 | 在特定场景下的行动方案，有场景边界 | 「小红书冷启动的 4 种打法」 | 「小红书的平台特点」（那是概念） |
| 原则/心法 | 不是具体步骤，但是可复用的指导原则 | 「定价先锚定再分化」「先做深再铺宽」 | 「定价是一门艺术」（那是金句，去 01） |

### 排除边界

| 不放 | 原因 | 去哪 |
|---|---|---|
| 纯概念定义（没有操作步骤） | 「PMF 是什么」≠「怎么找到 PMF」 | 03 |
| 人物的个人经验故事（未提炼为通用方法） | 离开这个人就不成立 | 01 |
| 多个方法的对比分析 | 跨方法合成有判断 | 04 |
| 主持人即兴的、非结构化的建议 | 不是经过提炼的方法 | 89 |
| **「描述了一个框架但没有操作化」** | 读完只知道「有这样一个方法」，不知道怎么用——这不是方法，是概念描述 | 03 |

### 关键边界

**方法 vs 概念**：
- 「PMF 的三种类型（显性/隐性/创造型 PMF）」→ 03（纯定义，没有操作步骤）
- 「如何判断你的产品是否达到了 PMF：5 个信号」→ 02（有操作步骤）
- 「PMF」→ 03（定义）；「如何找到 PMF」→ 02（方法）——两者用 Wiki Link 互链
- **最容易搞混的情况**：嘉宾展开论述了一个框架（如「生命力包含韧性、定力、自我净化、自我突破」），这看起来像方法，但如果文件只写了四个维度是什么而没有写「怎么评估/怎么培养」，那就是概念不是方法。必须补上操作化才能放在 02。

**SOP vs 原则/心法**：
- 可逐条执行、有先后顺序 → SOP/操作步骤
- 没有具体步骤但是指导性很强 → 原则/心法
- 两者都归入 02，但标注类型不同

### 文件质量标准

每个方法文件（包括 stub）必须满足：

1. **可操作性**：有「怎么用」段落，包含至少一种明确的用法（步骤/场景/观测信号）
2. **完整示例**：有一个端到端的示例（真实场景推演），不是假设的几句话
3. **场景边界**：明确写了「什么时候用」「什么时候不能用」「已知局限」
4. **来源可追溯**：方法中的操作步骤如果是从嘉宾论述中操作化提取的，标注 [AI推理]

**不合格的常见表现**：
- 整篇文件只是在解释「这个方法由什么组成」→ 应该去 03
- 「怎么用」部分只有泛泛的「可以用于投资判断」「可以用于自我评估」没有具体步骤 → 不合格
- 没有完整示例，只有一句话描述 → 不合格

### 从笔记中提取方法的流程

1. **识别**：笔记中嘉宾是否描述了一个可以脱离他人而成立的操作方式？
2. **命名**：用嘉宾原词或最通用的名称
3. **操作化**：把嘉宾的论述翻译成可执行的步骤——这一步是关键。嘉宾通常不会按「Step1/2/3」讲，需要 AI 从对话中提取结构
4. **补示例**：用嘉宾的原例或推演一个场景，端到端跑一遍
5. **写边界**：明确局限性。如果是 [AI推理]，必须标注

### 文件组织

- **粒度**：一个方法一个文件，命名 = 最通用的方法名
- **跨节目同类合并**：如果多个节目讲了同类方法，合并到一个文件，分段标注来源差异
- **命名规则**：优先使用嘉宾原名称；多个节目叫法不同时取最通用的
- **创建门槛**：首次出现即创建 stub → `_stubs/`，标记 `status: stub` + `source_count: 1`
- **升级流程**：
  1. 读 `_stubs/` 下所有 stub 完整内容（标题+正文），AI 做语义判断
  2. 匹配上 → 追加来源 → `source_count` +1 → >= 2 则移到父目录，status 改 `growing`，从索引删除
  3. 未匹配上 → 创建新 stub + 追加到索引
  4. aliases 仅为 Obsidian 辅助，不作为匹配依据

## 03概念链接/

### 终极目的

回答：「这个词什么意思？」「和另一个词什么关系？」「在不同语境下怎么用？」——像一本跨播客的迷你维基。

**核心原则**：客观定义优先，多源表述汇聚。概念本身是主角，谁说的只是注脚。

**核心检验**（创建任何一个概念文件前必答）：
1. 不看原播客的人，读了这篇能不能理解这个概念？
2. 这个概念有明确的「vs 对象」吗？（跟什么概念相对/相区别？）
3. 这个概念在播客中是**被讨论/定义/展开**的，还是只是顺口提到了名词？
→ 仅被顺口提到 → 不建文件。被展开讨论过 → 可以建。

### 收录范围（5 种子类型）

| 子类型 | 定义 | 实例 | 反例（不是这种） |
|---|---|---|---|
| 概念定义 | 核心概念的精确描述，说清楚是什么 | 「PMF 指产品与市场的匹配点，即...」 | 一个人一句话的定义 = 金句，去 01 |
| 概念辨析 | A vs B 的区别和联系 | 「PMF vs Product-Channel Fit」 | 「PMF 很重要」（那是观点，去 01） |
| 多源表述 | 同一概念在不同节目/不同嘉宾口中的不同说法 | 「42 章经叫 PMF，给女孩叫『找到对的客户』」 | 同一个人的两次表述（不是多源） |
| 概念关系 | A 是 B 的前提、A 和 B 互斥、A 包含 B 等 | 「PMF 是增长的前提条件」 | 「A 和 B 都很重要」（不是关系判断） |
| 概念演化 | 这个概念的含义在时间/语境中的变化 | 「PMF 从 2007 年 Benchmark 提出到今天的理解演变」 | 仅用一句话概括（需要展开） |

### 排除边界

| 不放 | 原因 | 去哪 |
|---|---|---|
| 带操作步骤的方法 | 「怎么做 PMF」和「PMF 是什么」不同 | 02 |
| 人物的主观观点（即使是关于概念的） | 「张津剑怎么看 PMF」→ 01 用 Wiki Link 指过来 | 01 |
| 跨节目深度分析 | 有判断和洞察（不只是汇聚定义） | 04 |
| **只在对话中顺口提到、没有被展开讨论的概念** | 嘉宾说了一句「PMF 很重要」但没有展开定义和讨论 → 不建 | 留在 89 |
| **孤立概念——和已有概念网络没有任何连接** | 出现了一次，和其他所有概念/方法都没有 Wiki Link | 先放 stub，若长期孤立考虑删除 |

### 关键边界

**03 概念 vs 05 深度研究**：
- 「PMF 在 42 章经、给女孩、平民创业手册中分别被定义为...」→ 03（汇聚定义，不做判断）
- 「从 10 个节目看 PMF 概念的演化：2007→2025，共识与分歧」→ 05（有判断、有洞察、有叙事）

**03 概念 vs 02 方法**：
- 看内容是「是什么」还是「怎么做」
- PMF 是什么 → 03；如何找到 PMF → 02
- 容易出现混淆的情况：嘉宾展开论述了一个概念（如「定力 = 有所为有所不为，控制心」），这应该进 03 展开定义和辨析；但如果进一步描述了「怎么评估一个人有没有定力（观测信号 + 打分表）」，操作化部分进 02

**03 概念 vs 01 人物观点**：
- 「张津剑认为垂直模型是过渡态」→ 01（观点，绑定人）
- 「垂直模型指针对特定行业训练的 AI 模型，与通用模型相对。张津剑认为是过渡态，理由是...」→ 03（概念定义 + 多源表述之一）
- 判断标准：如果把说这话的人名去掉，这句话还能作为一个概念的定义站住脚吗？能 → 03。不能 → 01。

### 文件质量标准

每个概念文件（包括 stub）必须满足：

1. **可理解性**：不看原播客的人能理解这个概念
2. **定义完整性**：不只是「XX 是指...」一句话，而是包含「为什么需要这个概念」「它解决什么问题」「它和什么概念相对」
3. **辨析性**：至少有一个明确的「vs 对象」（和什么概念区别）
4. **可链接性**：至少有一个 Wiki Link 到另一个概念或方法（概念不是孤岛）
5. **来源可追溯**：每条定义/表述标注来源节目+集数+嘉宾+[原话]/[归纳]

**不合格的常见表现**：
- 只是把一句嘉宾的话放在文件里，加了个「一句话定义」→ 这是金句归档，不是概念文件
- 定义太笼统，没有辨析对象（读了不知道和别的概念什么区别）→ 不合格
- 全是 [AI推理] 而没有标清楚哪些是来自播客的 [原话]/[归纳] → 不合格
- 没有任何 Wiki Link → 概念是孤岛，没有链接价值

### 从笔记中提取概念的流程

1. **识别**：笔记中是否有一个术语被嘉宾**展开讨论**（定义+案例+辨析），而不只是顺口提到？
2. **检查已有节点**：读 `03概念链接/_stubs/` 和 `03概念链接/` 所有文件内容，AI 做语义判断——是否已有类似概念？
3. **提取定义**：从嘉宾论述中提取核心定义，标注 [原话] 或 [归纳]
4. **找辨析对象**：这个概念在讨论中和什么概念做了对比？→ 写进「辨析」
5. **找关系**：这个概念和已有的哪个概念/方法有关？→ 写进「概念关系」+ Wiki Link
6. **判断能否建**：展开度 + 辨析性 + 可链接性 三条至少满足两条才建

### 文件组织

- **粒度**：一个概念一个文件，命名 = 最通用的概念名称
- **创建门槛**：首次出现即创建 stub → `_stubs/`，标记 `status: stub` + `source_count: 1`
- **升级流程**：同 02 的升级流程
- **与 04-Concepts 的关系**：03 是播客知识库内部的概念网络；如果某概念足够通用、跨知识库都适用 → 可升级到 `04-Concepts 概念/`，03 保留一份指针

## 04判断哲学/

### 终极目的

回答：「为什么这个节点选择 A，而不是 B？」——把具体决策背后的候选路径、约束、权重、舍弃理由和反转条件保存下来。

**核心原则**：04 不是方法步骤，不是概念解释，也不是跨节目大文章；它是单个决策节点的取舍链。

### 收录范围

| 放什么 | 不放什么 |
|---|---|
| 明确的二选一 / 多选一决策节点 | 只有一句结论、没有候选路径 |
| “先做 X 而不是 Y”的阶段性判断 | 纯执行步骤，去 02 |
| “不选 B”的理由、代价和风险 | 纯概念定义，去 03 |
| 判断会被什么条件反转 | 跨节目大专题，去 05 |

### 创建标准

创建任何 04 文件前必须回答：

1. 是否存在至少两个候选路径？
2. 是否能说清选择依据，而不是只写结论？
3. 是否能说清不选项为什么暂时不选？
4. 是否能写出反转条件？

四个问题至少前三个为 Yes 才建；否则留在 89 拆解记录。

## 05深度研究/

### 终极目的

回答：「So what？」——跨节目、跨维度做专题合成，产出有判断和洞察的分析。

**核心原则**：这是产出层，不是整理层。必须包含判断和洞察，不能只是信息汇拢。

### 收录范围（5 种子类型）

| 子类型 | 定义 | 实例 |
|---|---|---|
| 专题分析 | 跨节目提炼某个主题的全景 | 「AI 投资的共识与分歧：5 个播客 15 位嘉宾怎么看」 |
| 模式发现 | 跨人物/跨节目的共性规律 | 「年入千万的女性创业者的 4 个共同特征」 |
