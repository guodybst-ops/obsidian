# 01 概念写作规范（`[概念]` 前缀）

> **管辖**：`03概念链接/` 下所有 `[概念] xxx.md` 文件（含 stub 与主区成品）。
>
> **参照标杆**：`03概念链接/[概念] Agent.md`、`03概念链接/[概念] 定力.md`——现存两个主区成品已经是这套骨架的成熟形态。本规范把它们隐含的结构显性化。

---

## 一、什么是 `[概念]` 笔记

回答问题：**"X 是什么？为什么值得单独命名？它跟别的有什么关系？"**

使用姿势：陌生人看完前 3 节，能不能在 30 秒内说清楚 X 是什么、什么时候会用到这个词、跟他已知的 Y 有什么区别。

判据反问：
- 如果这个笔记的主体是"甲 vs 乙 该选谁" → 不是 `[概念]`，是 `[对比]`。
- 如果这个笔记的主体是"XXX 打败 YYY / XXX 已死" → 不是 `[概念]`，是 02 `[心法]`。
- 如果这个笔记就是一段感想没有明确术语 → 不属于 03。

---

## 二、标准骨架

```markdown
---
tags: [概念, <领域>, <细分>]
created: YYYY-MM-DD
layer: extract
status: stub / growing / stable
provenance: external / mixed
viewpoint_owner: external_author / mixed
prefix_type: 概念
aliases: [<别名 1>, <别名 2>]
source_count: N
sources:
  - show: "..."
    episode: "..."
    speaker: "..."
---

# <概念名>

## 一句话

<≤ 40 字，不含"XX 说 / XX 提出"。>

## 定义

<核心定义 + 拆解要点（编号列表或 3-4 段短文）。>

<如有多源补充，用 "### <NNN 节目> 补充：<视角>" 子节层层追加，不覆盖原义。>

## 多源表述

| 来源 | 说法 | 标注 |
|---|---|---|
| [[<节目>]] NNN <说话人> | "<原话或归纳>" | [原话] / [归纳] |
| ... | ... | ... |

## 辨析

- vs **<相近概念 A>**：<一句话说清区别>
- vs **<相近概念 B>**：<一句话说清区别>
（可选：加对比表格。表格适合三个以上维度对齐时用。）

## 概念关系

- 与 [[<相关概念>]] 相关——<一句话说清关系>
- 是 [[<父概念>]] 的子形态 / 特例 / 组成部分
- 可操作化为 [[02方法流程/_stubs/[SOP/框架/心法] xxx]]

## 附录：出处与演化（可选）

<这个概念在哪一集首次出现，后续集次如何演化、增强、修正。用时间轴叙述。>

## 附录：原文素材（可选，兜底）

<新骨架容纳不下、但原 stub 已经提炼过的原话、案例、类比——原样保留在这里。>
```

## 三、章节说明与要求

### `## 一句话`（必写）

- **≤ 40 字**。字数硬限制。
- **不含"XX 说 / XX 提出"**——归属信息在 frontmatter `sources` 里和 `## 多源表述` 表格里。
- 目标：一个陌生人只看这一行就能大致定位这是啥。

**正例**：
> 让大模型利用推理能力、上下文和工具，完成连续动作达成目标的技术形态。

**反例**：
> 张津剑在 42 章经 001 集提出的关于创业者定力的一种模型，指的是……（❌ 夹叙夹议 + 超字数）

### `## 定义`（必写）

- 核心定义放最前面（几行说清核心特征），再拆要点。
- 多源补充用 `### <NNN 节目> 补充：<视角>` 子节，**追加不覆盖**——参照 Agent.md 的做法。
- 如果这个概念在 4+ 集里都被强化过，多源补充可能占定义章节的一半篇幅，可以接受。

### `## 多源表述`（必写，即使只有 1 个来源）

表格三列：
- **来源**：`[[<节目>]] NNN <说话人>`，双向链接节目名。
- **说法**：原话打引号，归纳不打。
- **标注**：`[原话]` / `[归纳]` 二选一。

单源笔记也要写这一节，只有一行，方便未来累加。

### `## 辨析`（推荐，除非概念极其独立）

- vs 相近概念，一行一个。
- 对比维度超过 3 个时用小表格；≤ 3 个时用短句列表。
- 别写"vs" 关系时其实是对比笔记的伪装——如果 vs 章节比"定义"还长，考虑拆成 `[对比]` 笔记。

### `## 概念关系`（必写）

- 至少 1 条 wiki link。
- 可以链到：其他 03 概念、02 方法（SOP/框架/心法）、01 人物、04 判断哲学、05 深度研究。
- **禁止死链**：链之前先确认目标文件存在（Obsidian 中未链接的会显示为灰色，容易识别）。
- 用短句说明关系：`是 XXX 的操作化`、`XXX 的前置认知`、`XXX 的反面`。

### `## 附录：出处与演化`（可选）

- 概念在多集里演化时用。参照 [[定力]] 里的写法（001 → 022 → 043 的演化）。
- 单源概念可以省略这一节。

### `## 附录：原文素材`（兜底，可选）

- **红线保护**：返工时无处安放的原话/案例/类比，全部塞这里。
- 长度不限，但不要重复"多源表述"表格已有的内容。

## 四、frontmatter 细节

### 必填字段

- `tags`: 第一个必须是 `概念`，后续按领域标签。
- `prefix_type: 概念`（必写，与文件名前缀对齐）。
- `layer: extract`。
- `provenance` / `viewpoint_owner`: 参见 AGENTS.md 观点归属规则。
- `source_count`: 数字，等于 `sources` 数组长度。

### `aliases` 数组

- **重要**：Obsidian 用 `aliases` 做搜索命中，`[[Agent]]` 会同时匹配 `aliases: [AI代理, 智能体]`。
- 单概念多个说法（英文、中文别名、缩写）都塞进去。
- 例：`aliases: [AI代理, 智能体, 自主Agent]`。

### `sources` 数组

- 一个说话人一条记录，即使是同一个节目不同集次也拆两条。
- 例（参照 [[定力]]）：
  ```yaml
  sources:
    - show: "42章经"
      episode: "001"
      speaker: "张津剑"
    - show: "42章经"
      episode: "022"
      speaker: "张津剑"
  ```

### 升主区时追加

- `revised_at: YYYY-MM-DD`
- `revised_reason: "从 _stubs 升级到主区，对齐 03 概念写作规范"`

---

## 五、返工原则（沿用 02 通用红线）

1. **返工前必读原文**（最强红线）。原 stub 的所有原话、案例、类比、推演示例必须全部保留，只允许换位置。
2. 新骨架容纳不下的内容 → `## 附录：原文素材`。
3. 不删除任何 wiki link 目标；只允许改写链路径。
4. 修改后追加 `revised_at` + `revised_reason` frontmatter。

---

## 六、6 关自检（提交前必过）

1. **一句话 ≤ 40 字，无"XX 说"** ✅
2. **多源表述表格存在（哪怕只有 1 行）** ✅
3. **概念关系至少 1 条 wiki link，且目标真实存在** ✅
4. **辨析或 vs 章节不超过定义章节的 60%**（超了考虑拆成 [对比]）
5. **无夹叙夹议来源引用**（来源统一在表格/frontmatter，不在正文中间"张津剑在 022 集说……"）
6. **原 stub 素材全部保留**（返工时）
