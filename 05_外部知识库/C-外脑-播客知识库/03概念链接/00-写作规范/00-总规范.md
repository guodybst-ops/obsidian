# 03 概念链接 总规范（轻分档）

> **优先级**：这是 `03概念链接/` 下所有笔记（含 `_stubs/`）的**顶层规范**。两份子规范（概念 / 对比）在本规范之下细化各自骨架。
>
> **立规缘起**：2026-07-14。02 方法流程用三前缀（SOP/框架/心法）分档验证有效后，回头看 03 现有 89 个 stub 实际混着 4 种物种。相比 02，03 的骨架差异没那么"结构性"——单概念/对比/三角/别名都能靠一套定义型骨架收住，只有 "X vs Y" 对比型主体是对比表而非定义，需要独立骨架。所以 03 采用**轻分档**：`[概念]` 默认 + `[对比]` 专用，不做全前缀。

---

## 一、03 层的两种物种

| 前缀 | 物种 | 回答的问题 | 使用姿势 | 对应规范 |
|---|---|---|---|---|
| `[概念]` | 定义型笔记 | **"X 是什么？它跟别的有什么区别？"** | 查术语、辨析、找关系图 | `01-概念写作规范.md` |
| `[对比]` | 对比型笔记 | **"X 和 Y 到底怎么选/怎么区分？"** | 打开就看对比表，看边界与判据 | `02-对比写作规范.md` |

### 两者的本质区别

- **概念** 是一个**定义节点**：主体是"X 是什么"，vs 关系只是附属的辨析。
- **对比** 是一张**判据表**：主体是"X 和 Y 各是什么、什么时候用哪个"，两个都是主角，缺一不可。

## 二、分类判据（新建或分类 stub 时按此判断）

按顺序问 2 个问题，第一个"是"决定归属：

### 问题 1：这个笔记的主体是"两个东西的对比"吗？

- **是**（文件名含 `vs / X vs Y / 甲 vs 乙 / 甲对乙`，或主体是两个并列概念的边界与选择）→ **`[对比]`**
- 不是 → 进问题 2

### 问题 2：这个笔记的主体是"某个东西的定义 + 关系图"吗？

- **是**（定义一个术语、模型、三角/N元关系、别名收敛）→ **`[概念]`**
- 都不像 → **不属于 03**，检查是不是应该挪到：
  - `02方法流程/_stubs/[心法] xxx.md`（讲的是"XXX 已死"/"XXX 打败 XXX"这种**断言/命题**，几句话讲完 + 触发场景 + 反例）
  - `02方法流程/_stubs/[框架] xxx.md`（讲的是"用这几个维度评估"）
  - `01人物原萃/`（讲的是某人的一整套心智模型）
  - `04判断哲学/`（具体决策节点的取舍理由）
  - `05深度研究/`（跨集合成的深度主题）

### 补充判据：混合形态怎么办

- **概念名带 "vs" 但只有一方是主角**（例："Agent vs SaaS"，只是想讲清 Agent 是什么，SaaS 是背景对照物）→ `[概念]` Agent.md，vs SaaS 写在辨析章节。
- **三角/N 元关系**（例："Maker-User-Designer 三角"）→ `[概念]`（不是 [对比]，因为主体是**三方结构**而不是**二选一**）。
- **别名/术语**（例："Context 工程"、"AI 员工"）→ `[概念]`，主体就是定义。
- **断言型命题**（例："知识付费已死"、"生成打败推荐"、"AI 是外挂人是主角"）→ **迁移到 02 的 `[心法]`**，不留在 03。判据：几句话讲完 + 有触发场景 + 有反例 = 心法，不是概念。
- **拿不准**：先归入 `_stubs/` 用 `[?]` 前缀，等到有第二个来源出现再决定升级到哪个前缀。

## 三、目录组织

```
03概念链接/
├── 00-写作规范/                # 元规范目录（本目录）
│   ├── 00-总规范.md            # 本文件
│   ├── 01-概念写作规范.md      # [概念] 骨架
│   └── 02-对比写作规范.md      # [对比] 骨架
├── [概念] xxx.md               # 合格概念成品
├── [对比] xxx vs yyy.md        # 合格对比成品
└── _stubs/
    ├── [概念] xxx.md           # 待返工/未升主区
    ├── [对比] xxx vs yyy.md
    └── [?] xxx.md              # 尚未分类
```

**注意**：
- 前缀写在文件名头部，用方括号包裹，与主标题之间空一格。
- Obsidian 中 wiki link 引用时可以直接写 `[[概念名]]`（不含前缀）——通过 `aliases` 字段做别名映射。
- 主区（03 根目录）与 `_stubs/` 的区别不是"物种"，而是"成熟度"：**主区 = 稳定成品**（source_count ≥ 2 或已经打磨过），**_stubs = 单源初稿或未打磨**。见"六、成熟度与升主区"。

## 五、通用红线（两类都要遵守）

1. ❌ **禁止在正文里做人物/来源引用夹叙夹议** — 具体原话统一放在"多源表述"表格里 `[[节目]] NNN 说话人 | "原话/归纳" | [原话]/[归纳]`。
2. ❌ **禁止把"为什么值得学"作为开篇** — 想写背景，一律放到最后 `## 附录：出处与演化` 或 `## 附录：为什么值得关注`。
3. ❌ **`## 一句话` 章节 ≤ 40 字，且不含"某某说 / 某某提出"字样**。
4. ❌ **附录不得超过主体篇幅**。
5. ❌ **返工前必须完整读一遍原文；返工不得删除原素材**。这是**最强红线**（沿用 02 v1.1）。
   - 原 stub 已提炼的**原话、案例、类比、推演示例、来源、关联链接**必须**全部保留**，只允许换位置（挪到附录 / 折叠区 / 关联区）。
   - 如果新骨架容纳不下原素材，追加 `## 附录：原文素材` 章节兜底。
   - 违反这条 = 违反用户 2026-07-13 明确纠正："重新写的话，记得回顾一下原文的内容"。
6. ❌ **不允许出现死链**：`## 概念关系` 里的 wiki link 目标必须真实存在（可能是 03 主区、03 stub、02 stub、01 人物），不能凭想象生造。

## 六、成熟度与升主区

**主区 vs stubs 的判据**（不是物种判据，是成熟度判据）：

| 状态 | 位置 | 触发升级的信号 |
|---|---|---|
| `stub` | `_stubs/` | 单源初稿，只有 1 个 source |
| `growing` | `_stubs/` 或主区 | source_count ≥ 2，多个说话人/节目开始收敛到同一个概念 |
| `stable` | 主区 | 骨架章节齐全（一句话/定义/多源表述/辨析/关系），可被他人引用 |

**升级动作**（stub → 主区）：

1. `mv "_stubs/[概念] xxx.md" "[概念] xxx.md"`
2. frontmatter：`status: stub` → `growing` 或 `stable`
3. 追加 `revised_at` + `revised_reason: "从 _stubs 升级到主区，对齐 03 写作规范"`
4. 检查 `## 概念关系` wiki link 是否都是真实文件（避免死链）
5. 如果原 stub 章节不全，按 01-概念写作规范 或 02-对比写作规范 补齐

## 七、与 02 层的边界

同一个术语可能同时出现在 02 和 03，判定归属：

- **它是"XXX 是什么"** → 03（概念定义）
- **它是"用 XXX 做事的步骤"** → 02 `[SOP]`
- **它是"用 XXX 打分"** → 02 `[框架]`
- **它是"XXX 时要想起 YYY"** → 02 `[心法]`
- **它是"XXX 打败 YYY"这种断言** → 02 `[心法]`（**不在 03**）

例：
- `Agent` = 概念定义 → `03/[概念] Agent.md` ✅（已有）
- `AI 员工搭建六步法` = 步骤 → `02/[SOP] AI员工搭建六步法.md` ✅（已有）
- `生成打败推荐` = 断言 → `02/[心法] 生成打败推荐.md`（**待迁**）
- `Agent 环境-工具-反馈设计框架` = 打分/评估 → `02/[框架]` 或 `02/[SOP]`

**互链规则**：03 概念在 `## 概念关系` 里可以链到 02 的方法（"可操作化为 [[02方法流程/_stubs/xxx]]"），反过来 02 也可以链到 03 概念（"参见 [[03概念链接/xxx]] 术语定义"）。

## 八、维护与演化

- 两类**并存不合并**：不试图用统一骨架同时框住定义型和对比型。
- 每季度审计 stub 前缀分布：如果 `[对比]` 少于 5 个 stub，考虑是否值得独立一档；如果 `[概念]` 超过 60 个 stub 且长期不升主区，说明升级动作没跑起来。
- 89 stub 首批处理原则：
  - 只做**分类 + 改前缀**，不返工骨架（返工是 Phase 2 独立工作）
  - 断言型 11 个**迁移到 02 [心法]**
  - X vs Y 对比型改前缀为 `[对比]`
  - 其余 `[概念]`
- 升主区候选优先级：**source_count ≥ 2** 且**来源集中在某个高频说话人**（例：张津剑系、42章经系）的先做。
