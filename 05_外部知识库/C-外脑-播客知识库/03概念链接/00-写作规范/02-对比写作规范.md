# 02 对比写作规范（`[对比]` 前缀）

> **管辖**：`03概念链接/` 下所有 `[对比] xxx vs yyy.md` 文件（含 stub 与主区成品）。
>
> **为什么单独一档**：对比笔记的主体不是"一个概念的定义"，而是"两个东西的边界与选择"。用 `[概念]` 骨架硬套，会把辨析章节撑到 60% 以上，反而丢掉对比笔记最该有的"判据表 + 什么时候选哪个"。

---

## 一、什么是 `[对比]` 笔记

回答问题：**"X 和 Y 到底怎么选？什么场景用 X，什么场景用 Y？"**

使用姿势：陌生人打开就看对比表，能不能 30 秒内知道"我现在这个场景应该选 X 还是 Y"。

判据反问：
- 如果这个笔记的主体是"X 是什么"，Y 只是背景对照物 → 不是 `[对比]`，是 `[概念]` X.md，Y 写在辨析章节。
- 如果这个笔记的主体是"X 打败 Y" → 不是 `[对比]`，是 02 `[心法]`。
- 如果这个笔记的主体是"3 个以上东西的分层结构"（三角/N 元）→ 不是 `[对比]`，是 `[概念]`。

## 三、章节说明与要求

### `## 一句话`（必写）

- ≤ 40 字。
- 必须**同时**含 X 和 Y，说清核心分野。
- 反例：只讲 X 不讲 Y = 写偏了。

**正例**：
> Copilot 帮你更快做，你是决策者；Agent 替你做，模型是决策者。

**反例**：
> Agent 是一种让大模型自主完成任务的技术形态。（❌ 只讲了 X，没讲 Y）

### `## 各自定义（简版）`（必写）

- 每一方 3-5 行，说清核心特征。
- **如果 X 和 Y 已经有 03 主区独立笔记**：这一节退化为两行 wiki link + 一句话摘要，避免重复维护。
- **如果 X 和 Y 只在这个对比笔记里存在**：这一节要写全。

### `## 对比表`（必写，核心章节）

- 表格是这类笔记的**主体**——占篇幅最大的应该是这一节。
- 维度数建议 3-6 个；<3 个考虑用短句列表；>6 个说明维度切得太碎，合并。
- 每格内容尽量对齐（同一维度上 X 和 Y 的说法要在同一层次）。

**维度选取参考**（不同类型对比适用不同维度）：
- 技术类：核心机制 / 输入输出 / 适用场景 / 成本 / 可控性
- 商业类：客户 / 价值 / 成本结构 / 竞争壁垒 / 演化方向
- 心智类：预设 / 决策方式 / 情绪反应 / 长期后果

### `## 什么时候选 X / 选 Y`（必写）

- 这一节是"对比笔记之所以有用"的关键——如果读者看完不知道自己场景该选哪个，笔记就白写了。
- 用"信号列表"而不是"论述"：
  - ✅ `- 你在做的事有明确 SOP → 选 X`
  - ❌ `X 更适合那些流程稳定的场景，因为它……`
- **混合形态章节**（可选但推荐）：说明 X 和 Y 之间是不是一条光谱，中间有没有实际存在的混合形态。这一节能防止读者误以为"二元对立"。

### `## 多源表述`（必写）

- 表格结构同 `[概念]` 笔记。
- 特别注意：**同一说话人在不同集里可能给出不同的对比说法**，一集一行。

### `## 常见误区`（可选）

- 什么样的场景经常被搞错。
- 短句列表。

### `## 概念关系`（必写）

- 至少 1 条 wiki link。
- 常见关系：
  - X 和 Y 都是某个父概念的子类
  - 对比结果可操作化为 02 的某个 SOP/框架
  - 与另一个类似的 X' vs Y' 对比笔记对照

## 四、frontmatter 细节

### 特有字段：`dimensions_axis`

- 用于快速索引这个对比用了哪些维度，方便未来跨对比笔记检索。
- 例：
  ```yaml
  dimensions_axis: [核心机制, 决策方式, 客户价值, 演化方向]
  ```

### 特有字段：文件名建议

- 用 `[对比] X vs Y.md` 格式，X 和 Y 用空格分隔 `vs`。
- 例：`[对比] Agent vs SaaS.md`、`[对比] 主体性 vs 依赖性.md`。
- **不要**用 `[对比] X-Y.md` 或 `[对比] X与Y.md`（不一致会破坏搜索）。

## 五、返工原则（沿用 02 通用红线）

1. **返工前必读原文**（最强红线）。
2. 无处安放的原素材 → `## 附录：原文素材`。
3. 修改后追加 `revised_at` + `revised_reason: "对齐 03 对比写作规范"`。
4. 从 `[概念]` 改为 `[对比]` 或反向时，同步更新 `prefix_type` 字段。

## 六、6 关自检（提交前必过）

1. **一句话同时含 X 和 Y** ✅
2. **对比表存在且维度 3-6 个** ✅
3. **"什么时候选 X / 选 Y" 章节有信号列表** ✅
4. **对比表占篇幅 ≥ 定义章节的 50%**（否则可能应该写成 [概念]）
5. **无夹叙夹议来源引用** ✅
6. **原 stub 素材全部保留**（返工时）

## 七、常见误判纠正

**误判 1**：X 名字带 vs 就一定是 `[对比]`。
- 反例：`Agent vs SaaS` 其实是想讲清 Agent 概念，SaaS 只是对照物 → 写成 `[概念] Agent.md`，SaaS 在辨析章节。

**误判 2**：三角关系当成对比。
- 反例：`Maker-User-Designer 三角` 是三方结构，不是二选一 → `[概念]`。

**误判 3**：断言当成对比。
- 反例：`生成打败推荐` 不是"生成 vs 推荐 该选谁"，是"某个时代生成会赢" → 迁到 02 `[心法]`。
