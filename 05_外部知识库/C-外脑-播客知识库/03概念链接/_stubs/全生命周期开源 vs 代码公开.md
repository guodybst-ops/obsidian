# 全生命周期开源 vs 代码公开

## 一句话

把写完的代码放到 GitHub 上只是「代码公开」。真正的开源是全生命周期开放——从文档、设计讨论、版本演进、决策路径到代码，让外部参与者看到构建的全过程。

## 定义

- **代码公开**：将完成后的源代码放到公开仓库。类似餐厅公布菜谱，但用户不知道食材从哪来、后厨怎么运作。
- **全生命周期开源**：从项目第一天起，就把构建过程、文档、设计决策和演进路径全部开放。类似餐厅透明后厨——用户看到食材采购、加工、烹饪全过程。

## 为什么需要这个区分

东旭认为，很多人误解了开源，以为开源就是公开代码。但对数据库这样的基础设施软件来说，客户会把关键业务托付给它。如果软件是黑盒，用户很难放心。全生命周期开源让客户看到系统如何被构建、如何演进、如何处理问题——这才是建立信任的根本机制。

更重要的是，开源的护城河不是某份代码，而是：
- 持续多年投入形成的工程复杂度
- 核心团队对历史问题和设计权衡的理解
- 用户社区和企业客户的心智占位
- 项目方向的控制能力

后来者看到答案（代码），但无法复制做题过程。

## 辨析

- vs **代码公开**：答案 vs 做题思路。答案本身价值有限，因为软件在持续迭代。
- vs **开源商业化**：全生命周期开源是社区信任的基础，商业化依靠云服务等不冲突的模式。
