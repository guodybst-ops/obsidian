# Agent vs SaaS

## 一句话

SaaS 是给人使用的工具，用户需要操作它以提升效率；Agent 是交付结果的主体，用户提出目标后由它自主完成。两者的产品设计逻辑、用户心智和工作范式完全不同。

## 定义

- **SaaS**：Software as a Service，以工具形态存在。用户是操作者，需要学习界面、配置参数、掌握流程。价值 = 工具效率 × 人的使用能力。
- **Agent**：自主完成任务的主体。用户只需要提供目标和约束，Agent 自主规划、执行、获取反馈并交付结果。价值 = 结果质量。

## 为什么这个区分重要

很多 SaaS 公司把自己包装成 Agent，但本质仍然是工具。关键检验：如果去掉人的操作，产品还能交付结果吗？如果不能，它仍然是 SaaS。

雷磊的核心观点：给人设计软件和给 Agent 设计软件，应该从完全不同的出发点开始。给人设计关注流程引导和 UI，给 Agent 设计关注反馈信号和安全边界。

## 辨析

- vs **SaaS + AI**：只是把大模型入口加到已有 SaaS 上 ≠ Agent。Agent 需要从底层重构工作流和反馈机制。
- vs **通用 Agent vs 垂直 Agent**：雷磊认为两者长期共存。通用 Agent 像综合商超，垂直 Agent 像细分店铺，只要在特定领域能稳定交付结果，就能形成业务。
