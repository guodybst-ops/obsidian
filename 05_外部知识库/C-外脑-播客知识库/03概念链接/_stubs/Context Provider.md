# Context Provider

## 一句话

AI 时代人的核心价值不是更聪明的执行者，而是上下文供给者——提供 AI 无法从训练数据中获得的业务知识、历史原因、边界条件和真实需求。

## 定义

Context Provider 是任川提出的 AI 时代人才画像的第一个核心能力。很多 agent 不工作的根本原因不是模型不够强，而是上下文工程失败——AI 没有获得完成任务所需的背景信息。

需要的上下文包括：
- **行业知识**：餐饮、医疗、金融等垂直领域的真实流程和规则
- **历史系统知识**：为什么系统是这样设计的、过去踩过什么坑
- **用户真实需求**：用户嘴上说需要 A，实际需要的是 B（需要人去分辨）
- **边界条件**：哪些情况可以做、哪些绝对不能做

## 为什么需要这个概念

很多人把"AI 时代的工程师"理解为"会用 AI tools 写代码的人"。任川认为这是误解——真正重要的是能把问题定义清楚、把上下文整理好、让 AI 能有效工作的人。人加 AI 的产出必须大于 AI 本身，否则人的加入反而会降低效率。

## 辨析

- vs **领域专家**：领域专家拥有知识，但 Context Provider 进一步需要把知识转化为 AI 可理解的格式（结构化的 requirements、边界条件、约束）
- vs **Prompt Engineer**：Prompt Engineer 关注如何写 prompt 让 AI 更好回答。Context Provider 关注的是「让 AI 知道什么」而不只是「怎么说」。
- 关联概念：[[Agency]]——有 Agency 的人是好的 Context Provider，因为他们会主动去获取和整理上下文。
